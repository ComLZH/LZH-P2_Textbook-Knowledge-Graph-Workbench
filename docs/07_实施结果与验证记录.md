
## 2. 已实施模块

### 2.1 数据契约

新增 `src/textbook_builder/pipeline_contracts.py`，定义页面证据、连续性结果、局部节点、局部关系线索、规范节点、别名映射、关系候选、书/章清单和运行清单。

### 2.2 页面证据与 OCR

新增 `services/page_evidence.py`：

- PDF 原生文本足够时不调用 OCR。
- 扫描页使用共享 `PP-OCRv6_medium_det` 和 `PP-OCRv6_small_rec`。
- 模型源目录固定指向系统 `shared_resources/models/ocr/`。
- 中文路径不兼容时复制到 ASCII 临时缓存，不移动共享模型。
- 页面证据按图像 SHA-256、检测模型、识别模型和流水线版本缓存。
- OCR 异常转换为 `unavailable`/`needs_review` 状态，不生成伪文本。
- PyMuPDF 同时兼容 `pymupdf` 新入口和 `fitz` 旧入口。

### 2.3 页面顺序检查

新增 `services/page_continuity.py`：

- 检查文件页码连续、印刷页码、重复图像/文本、页尾与页首边界。
- 只把可疑相邻页送入可选模型复核。
- 结果只给 `keep_order` 或 `manual_review`，不自动重排。
- 工作台开关默认关闭，适合通常已经按书本顺序制作的 PDF。

### 2.4 首轮抽取

新增 `llm/staged_extractor.py`：

- 每批最多 4 页或约 12000 字符。
- 一次模型阅读同时输出 `nodes` 与 `local_relation_claims`，两个数组彼此独立。
- 正常 OCR 页面只发送文本和块级证据；只有页面标记为需要视觉复核时才附图。
- 每批临时 ID 在本地增加命名空间，避免不同批次重复使用 `n1` 等 ID 时相互覆盖。

### 2.5 节点归一化和关系整合

新增：

- `normalizers/node_canonicalizer.py`
- `services/relation_consolidation.py`
- `services/staged_extraction.py`

实现行为：

- 只自动合并名称、类型、章节均能保守判等的节点。
- 保留所有临时 ID、教材称谓和显式别名映射。
- 关系先映射到规范节点 ID，再验证类型、证据和推断范围。
- 自环、未知类型、歧义端点不会进入候选边。
- 模型推断且没有证据引用的关系进入专家复核状态。
- 最终关系阶段禁止新增节点，只允许使用规范 `node_id`。
- 最终阶段使用压缩后的逐页文本，不再次上传整页图片。

### 2.6 整本书保护

新增 `services/book_manifest.py`：

- 识别章节起止页、小节标题、目录/非正文页和印刷页码映射。
- 节点先全局保守归一化，再按章节执行关系补全。
- 单个章内关系请求最多 80 个节点。
- 跨分组关系不会被删除；当前不主动执行无证据的整本书跨章补边。

这使完整 PDF 具备分段处理基础，但不等于整册抽取准确率已经验收。

### 2.7 工作台和命令行

`WorkbenchAnalysisRequest` 新增 OCR、页序检查、分阶段抽取和最终关系整合选项。为兼容旧的无界面调用，`staged_pipeline_enabled` 的请求默认值为 `False`；桌面工作台的复选框默认启用分阶段抽取。

运行清单记录文本/视觉模型调用次数和输入字符估算，用于比较流程调整前后的输入规模；精确 Token 数仍需在线服务返回 usage 或使用对应 tokenizer 计算。

桌面默认值：

- 本地 OCR：开启。
- 分阶段抽取：开启。
- 页面顺序检查：关闭。

新增命令：

```powershell
python run_project.py staged-check --pages 11-13 --force-ocr --check-page-order
python run_project.py staged-check --pages 11-13 --remote
```

本地命令只建立页面证据与可选顺序检查；`--remote` 才读取 `.env` 并调用第三方模型。

第二轮明细检查结果：
