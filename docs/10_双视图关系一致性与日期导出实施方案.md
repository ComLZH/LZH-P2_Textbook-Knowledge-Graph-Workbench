## 1. 本轮目标

本轮修复不调整 OCR、提示词、节点抽取和关系抽取算法，集中解决建设态审查工作台的四类一致性问题：

1. 兼容视图与 G6 共用不同坐标语义，造成章节框、节卡片和文字重叠。
2. G6 隐藏端点属于结构节点的真实 `progressive`、`prerequisite` 等关系，导致两种视图表达不一致。
3. 应用、窗口和开发者信息缺少统一的 `LZH-P2` 项目标识。
4. 多轮导出写入同一目录，正式导出被质量门禁阻止后可能残留上一轮的正式图谱和分层映射。

## 2. 已确认产品规则

### 2.1 层级与嵌套

- `contains` 继续作为层级事实的权威来源。
- G6 中的父子包含关系默认用“大框包含小框”的 combo 嵌套表达，不默认绘制 19 条包含箭头。
- 兼容视图同样通过章节框和内容区表达层级。
- 图形嵌套只是一种表现方式；底稿、关系表、质量检查和正式导出仍完整保留 `contains` 边。
- 待审结构可以正确嵌套，但不会因此自动变成正式通过。

### 2.2 真实非层级关系

- `workbook.edges` 是两种视图共同的真实关系来源。
- `progressive`、`prerequisite` 及其他真实非层级关系不得因为端点是章、节或其他结构节点而隐藏。
- 真实关系优先于布局辅助关系；已存在真实关系时可以不生成同端点布局辅助边，但不能反向隐藏真实关系。
- 审查状态只控制关系线型、透明度和状态标识，不控制关系是否进入画布。
- 布局辅助边与真实关系必须带有不同标记，默认允许单独隐藏。

### 2.3 状态摘要

- “待审”只统计 `pending`，不得把 `needs_expert_review` / `needs_revision` 静默混入或遗漏后仍让用户误认为全部未完成项均已计数。
- 图谱标题区分别显示节点、关系、待审和待修数量。
- 本轮冻结底稿的验收计数为：25 个节点、31 条关系、24 个待审节点、20 条待审关系、11 条待修关系。

### 2.4 项目标识

- 公开配置的 `application` 对象增加独立 `project_code = "LZH-P2"`。
- 完整显示名称统一为 `LZH-P2 教材知识图谱本地工作台`。
- Windows 窗口标题、页面主标题、应用程序名称和开发者信息入口共同读取该配置。
- 开发者弹窗标题使用 `LZH-P2 · 开发者信息`，正文显示项目标识、完整产品名称、开发者刘钊昊和联系方式 `comlzh@outlook.com`。
- API Key 等秘密仍不得进入公开应用信息配置。

### 2.5 日期目录导出

- 用户选择的目录是导出根目录，每轮实际产物写入当天的 `YYYY-MM-DD/` 子目录。
- 同一天再次导出时，该日期目录表示当天最新一轮一致产物；写出前必须处理上一轮已知产物，避免质量门禁失败后继续保留旧 `formal_graph.xlsx` 或 `layer_mapping.json`。
- 日期目录至少包含 `reviewed_draft.xlsx` 和 `graph_quality_report.md`。
- 只有正式质量门禁通过时，日期目录才包含 `formal_graph.xlsx` 和 `layer_mapping.json`。
- 导出结果必须生成 `export_manifest.json`，记录导出日期、图谱 ID、来源 ID、实际文件、正式导出是否生成以及被阻断原因摘要。
- 工作台完成后打开和提示的是本轮日期目录，而不是仅显示导出根目录。

## 3. 坐标与布局契约

### 3.1 状态隔离

- G6 `manual_positions` 保持中心点坐标，只能由 G6 读取和保存。
- 兼容视图使用独立坐标状态；在没有独立保存需求前，优先每次由确定性布局重新计算。
- G6 与兼容视图继续使用不同像素坐标语义；2026-08-25 关系布局升级到版本 3 后，旧配置的安全字段继续保留，但旧 `manual_positions` 失效，避免覆盖新的左向右层级。
- 切换视图不得修改另一视图的位置配置。
- 两种视图共享章节内语义层级而不是共享像素坐标；方向分类、循环例外和最新版验收以 `13_G6关系驱动左向右分层布局实施方案.md` 为准。

### 3.2 兼容视图几何约束

- 章节容器由标题区和内容区组成，节卡片只能进入内容区。
- 所有直接子节点的矩形必须被父容器内容区完整包含。
- 同一容器中的节点矩形不得相交。
- 容器高度按实际使用的节点行动态计算，不保留无节点占用的大段空白。
- 关系边在节点卡片之后或通过安全路径绘制，标签与节点卡片保持最小间距。
- 场景边界按最终项目范围计算，并支持缩放、滚动和恢复默认布局。

## 4. G6 关系显示契约

G6 载荷至少分为：

- `hierarchy`：父子映射和结构角色，用于 combo 嵌套；
- `edges`：所有真实非 `contains` 关系；
- `layout_edges`：可选的表现层辅助边；
- `review_state`：节点和关系审查状态；
- `view_config`：只属于 G6 的位置、聚焦和辅助边显示设置。

默认显示规则：

| 类型 | 默认表现 |
| --- | --- |
| `contains` | combo 大框包含节卡片，不默认画箭头 |
| `progressive` | 青绿色有向边，标签“递进” |
| `prerequisite` | 蓝色有向边，标签“前置” |
| 其他真实语义边 | 按现有关系图例显示 |
| 布局辅助边 | 低对比度、可单独隐藏 |

## 5. 实施顺序

1. 冻结本文和相关导航、层级、视觉规范中的新规则。
2. 扩展应用公开信息配置和测试，统一 `LZH-P2` 显示名称。
3. 将 G6 坐标从兼容视图状态中隔离，修复兼容视图布局和重叠。
4. 修改 G6 payload，保证真实非层级关系完整进入 `edges`。
5. 更新 G6 关系图例、筛选、审查状态和待修摘要。
6. 实现日期目录导出、旧产物处理和导出清单。
7. 使用冻结的三页目录结果完成无 API 回放、自动化测试和 Windows 双视图视觉验收。
8. 将最终测试数字、截图结论和已知限制回填到当前状态与实施记录。

- 8 条递进和 4 条前置关系可见，关系类型与方向正确。
- G6 中拖拽或保存位置后切换到兼容视图，布局仍保持正确。

### 6.2 G6

- 6 个章 combo、19 个节卡片继续正确嵌套。
- 载荷包含 12 条真实非层级关系：8 条 `progressive`、4 条 `prerequisite`。
- 真实关系不再进入“结构端点抑制”集合。
- 待修关系仍可见，并能与已通过、待审状态区分。
- `contains` 不默认生成拥挤箭头，空间嵌套与关系表事实一致。

### 6.3 名称与导出

- 所有指定位置显示 `LZH-P2`，配置缺失或损坏时仍安全回退。
- 导出根目录下自动建立当天 `YYYY-MM-DD/` 子目录。
- 正式导出被阻止时，日期目录不保留旧正式图谱或旧分层映射。
- `export_manifest.json` 与实际文件、当前图谱 ID 和质量门禁结果一致。

## 9. 2026-09-10 后续兼容说明

- `contains` 不再作为所有建设态包含含义的单一集合：教材结构使用 `structure`，教材归属使用 `membership`，无法可靠分类的旧记录使用 `unresolved`。
- G6 与 Qt 不再分别从旧 workbook 猜测容器，而是共同消费 `ReviewViewProjection` 和布局版本 4 的递归几何。
- v2 质量门禁和正式发布不读取画布筛选、坐标或 combo；唯一/多归属均经显式 profile 确认。
- 本文件 2026-08-23 的 49 项回归和截图继续作为历史目录样例证据；当前回归与正文样例证据见文档 17。
