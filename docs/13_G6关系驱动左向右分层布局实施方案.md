## 1. 问题与根因

当前 G6 章节内部节点主要按固定列数的目录网格排列，而不是根据真实语义关系计算横向层级。节点换行后，语义正确的 `source → target` 可能在视觉上变成由右向左回指；同一来源的并列目标也不能稳定地上下对齐。

此外，现有 G6 对全部关系统一绘制终点箭头，没有区分方向性关系与对称关系。`equivalent`、`parallel`、`contrast` 因而容易被误读成单向学习顺序。

本轮只调整表现层布局和边的视觉语义，不交换关系端点，不反转模型输出，也不修改 P4 正式图谱契约。

## 2. 产品规则

### 2.1 关系分类

| 分类 | 关系 | 布局和连线规则 |
| --- | --- | --- |
| 方向性语义关系 | `prerequisite`、`progressive`、`derives_to`、`explains`、`applies_to`、`represented_by` | 起点层级小于终点层级；默认从节点右侧出发、从目标左侧进入，主阅读方向为左向右 |
| 对称关系 | `equivalent`、`parallel`、`contrast` | 不建立单向层级约束；优先放在同一层上下排列，使用中性线或双端标识 |
| 层级关系 | `contains` | 继续使用大框包含小框，不重复绘制箭头 |
| 布局辅助关系 | `layout_*` | 遵循左向右引导，但不进入正式图谱 |

### 2.2 循环关系

- 对方向性关系图计算强连通分量；同一强连通分量中的节点属于同一循环组。
- 循环组整体参与左向右分层，组内节点在同一层上下排列。
- 循环内部边保留真实端点与方向，以显式回边表现，不为追求全部向右而篡改语义。
- 布局结果输出循环节点和循环边诊断，供测试、详情面板和后续质量检查使用。

### 2.3 章节与整册边界

- 章节容器继续纵向排列，避免整册图谱无限横向扩张。
- 左向右分层主要在每个章节容器内部执行。
- 跨章节方向性关系以章节顺序作为稳定回退；不为单条跨章边改变整册章节顺序。
- 同一层多个节点上下排列，并通过确定性排序和邻接重心降低交叉。

### 2.4 手工位置

- 自动布局是默认基线，旧版手工坐标不得继续覆盖本轮新算法。
- 布局版本升级后，旧 `manual_positions` 自动失效；旧配置文件保留其他安全字段。
- “恢复布局”清空手工坐标并重新应用当前关系分层算法。
- 教师仍可自由拖拽；拖拽后的坐标属于显式手工覆盖，可能产生回指，恢复布局可返回关系驱动状态。

## 3. 共享布局数据契约

新增确定性的章节关系分层结果，至少包含：

- 每个节点的 `rank`、同层顺序和循环组编号；
- 每个方向性边是否满足左向右、是否属于循环内部；
- 每个对称关系是否进入同层约束；
- 每个章节的层数、最大同层节点数和布局诊断。

Python 层负责计算该结果。G6 payload 和兼容视图都消费同一结果，避免两个视图分别猜测关系方向。

## 4. 实施顺序

1. 冻结本文、文档导航和验收规则。
2. 在公共布局模块实现关系分类、强连通分量、压缩图分层、同层排序和诊断。
3. 修改 G6 payload：章节内节点按共享层级生成中心坐标，输出布局元数据，并将布局版本升级。
4. 修改 G6 边：方向性边固定右侧输出、左侧输入；对称边使用中性或双端表现；循环内部边标记为回边。
5. 修改兼容视图，使章节内部几何使用相同层级，并保持节点完整嵌套、无重叠。
6. 处理旧视图配置失效、保存和“恢复布局”行为。
7. 增加单元测试、现有目录样例回放、浏览器运行时检查和 Windows 工作台截图验收。
8. 将实现结果、测试数字和限制回填本文及当前实现记录。

## 5. 验收标准

### 5.1 算法

- 无环方向性关系满足 `rank(source) < rank(target)`。
- 同一层节点具有不同纵向槽位且不重叠。
- 对称关系不产生虚假的单向层级。
- 循环图可以稳定完成布局，循环节点与循环边被显式标记。
- 相同输入重复构建得到相同层级和顺序。

### 5.2 G6

- 无环方向性边满足 `source.x < target.x`。
- 方向性边固定从右侧锚点连到左侧锚点。
- 对称关系不显示为普通单向终点箭头。
- `contains` 继续通过 combo 嵌套表达。
- 恢复布局后不再读取旧版破坏方向性的坐标。

### 5.3 兼容视图

- 与 G6 使用相同的章节内节点层级。
- 容器完整包住子节点，节点不重叠，章节之间不覆盖。
- 方向性关系的宏观阅读方向与 G6 一致。

### 5.4 回归

- P2 完整自动化测试通过。
- 当前真实保存样例中无环方向性边全部向右。
- G6 页面在本地 Edge 中无脚本错误和 G6 警告。
- 不改变节点数、关系数、关系类型、关系端点和审查状态。

## 6. 非目标与限制

- 不重新调用第三方 API，不调整 OCR、抽取提示词或归一化结果。
- 不把视觉顺序写回正式知识关系。
- 不承诺循环内部每条边均向右；回边是保留真实循环语义所必需的例外。
- 教师显式自由拖拽后可以临时打破自动层级，恢复布局可重新应用默认规则。

## 7. 实施与验收结果

本方案 8 个实施步骤均已完成：公共关系布局、方向分类、对称同层、循环压缩、G6 锚点与路由、兼容视图共享层级、布局版本升级、自动化与真实页面验收均已落地。

实现结果：

- `utils/relation_layout.py` 提供确定性的章节关系布局和诊断。
- G6 payload 输出 `relation_layout`、节点 rank/order/component/cycle 和边 directionality/routing/anchor/cycle。
- G6 方向性边固定右出左入；`equivalent`/`contrast` 使用双端标识，`parallel` 使用无箭头中性线，循环使用独立回边路由。
- 兼容视图按相同 rank 分列、按 order 分行，并动态计算章节容器宽高。
- 布局版本升级到 3；版本 1/2 的手工坐标清空，其他安全视图字段保留。
- “恢复布局”实测保存版本 3 和空 `manual_positions`。

冻结 `导出测试/2026-08-24/reviewed_draft.xlsx` 回放为 15 节点、20 关系、2 个章节容器和 7 条真实语义边；7/7 无环方向性边左向右，反向边 0。Edge 运行时为 1 个 canvas、13 个普通节点、2 个 combo、7 条语义边，控制台 0 错误、0 警告。

完整自动化回归为 `62 passed`。视觉证据位于：

- `storage/ui_validation_20260825_relation_layout/workbench_g6_1480x900.png`

已知边界保持不变：循环内部边允许回指；教师显式自由拖拽可以暂时打破自动层级，点击恢复布局即可返回默认状态。

## 8. 2026-09-10 布局版本 4

- 输入从旧 workbook 章节分组升级为 `ReviewViewProjection`；结构、归属和语义的表示职责分离。
- 纯函数几何先递归计算子作用域完整尺寸，再定位父作用域，卡片固定为 250×86 逻辑像素；G6 与 Qt 使用相同节点/作用域坐标。
- 方向性 SCC、对称同层、跨作用域、顺序冲突和未决语义分别输出约束状态；语义循环不会被误报成结构循环。
- G6 运行时读取真实节点与 combo 包围盒，报告文档 revision、投影指纹、规格版本、坐标系、容差、越界和同父重叠。
- 拖拽开始保存整图位置，结束后检查几何；非法位置恢复到拖拽前状态，不改变 membership。点击“恢复布局”清除版本 4 手工坐标。
- 冻结正文样例的真实 Chromium 结果为 9 节点、2 combo、0 几何违规；1480×900 与 1180×720 截图见文档 17。

因此，本文件末尾旧表述“教师显式自由拖拽可以暂时打破自动层级”只保留为版本 3 历史事实；版本 4 允许在当前父框内容区内无重叠调整，但不允许越界或拖动改变业务归属。
