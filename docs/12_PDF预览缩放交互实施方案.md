# 12. PDF 预览缩放交互实施方案

更新时间：2026-08-24  
状态：已完成；以当前代码、58 项自动化测试和三种尺寸双布局视觉快照为准

## 1. 问题与复现结论

当前桌面工作台导入 PDF 后使用 `QPdfView` 的多页、适合宽度模式。普通鼠标滚轮可以上下浏览页面，但没有实现 `Ctrl + 鼠标滚轮` 缩放。

在 PySide6 6.10.2 的离屏交互测试中：

- `Ctrl + 滚轮` 前后缩放模式均为 `FitToWidth`；
- 缩放因子没有变化；
- 垂直滚动位置发生变化，说明该组合键仍被当作普通滚动处理。

因此该问题属于当前交互能力缺失，不是特定 PDF 文件或扫描页面造成的偶发现象。

## 2. 目标

在不替换 PDF 渲染器、不改变教材读取和分析链路的前提下，为 PDF 原文预览增加可发现、可复位、可测试的缩放能力：

- 导入 PDF 后仍默认适合宽度；
- `Ctrl + 滚轮向上/向下` 分别放大/缩小；
- 普通滚轮继续只负责纵向浏览；
- 缩放期间不得同时滚动页面；
- 翻页和页码跳转保留当前缩放比例；
- 图片预览、来源记录和工作台其他滚动区域不受影响。

## 3. 交互契约

### 3.1 缩放模式

1. 新 PDF 加载成功后，缩放模式初始化为 `FitToWidth`。
2. 用户第一次执行放大或缩小时，视图切换到 `Custom` 模式。
3. “适合宽度”操作重新切回 `FitToWidth`，窗口宽度变化后继续由 Qt 自动适配。
4. 页码切换、查看分析起始页和查看分析结束页不得擅自重置缩放模式。

### 3.2 鼠标和键盘

- `Ctrl + 滚轮向上`：以当前比例为基准放大。
- `Ctrl + 滚轮向下`：以当前比例为基准缩小。
- 普通滚轮：保持 QPdfView 原生纵向滚动。
- `Ctrl + +`：放大。
- `Ctrl + -`：缩小。
- `Ctrl + 0`：恢复适合宽度。

组合键仅在 PDF 预览具备有效文档时生效；鼠标缩放仅拦截 PDF 视口内的 `Ctrl + 滚轮`，不得影响左侧数值输入框、配置滚动区和图谱视图。

### 3.3 比例与反馈

- 自定义缩放范围：25%–400%。
- 每一个标准滚轮刻度按约 10% 的倍率平滑变化；高精度触控板增量按实际滚轮增量计算。
- PDF 导航栏显示“缩小、当前比例、放大、适合宽度”四项紧凑控件。
- 适合宽度状态显示“适合宽度”；自定义模式显示取整后的百分比。
- 达到上下限时对应按钮禁用，并在工具提示中说明快捷键。

### 3.4 视点稳定

鼠标缩放应尽量保持指针下方内容的位置稳定。实现时记录缩放前后的滚动范围和指针相对位置，缩放后补偿水平、垂直滚动条，避免阅读位置明显跳动。

## 4. 实现设计

1. 建立专用 `ZoomablePdfView`，集中维护最小、最大缩放值和倍率计算。
2. 在其视口安装事件过滤器，只接管带 `Ctrl` 修饰键的滚轮事件。
3. 对外提供放大、缩小、恢复适合宽度方法以及缩放状态信号。
4. 工作台只负责创建按钮、绑定快捷键、显示缩放状态和在文档切换时复位。
5. 所有缩放操作调用同一套边界和状态同步逻辑，避免鼠标、按钮、快捷键产生差异。

## 5. 实施顺序

1. 记录本方案并更新文档导航。
2. 实现可缩放 PDF 视图和缩放状态同步。
3. 在现有 PDF 页码导航行增加缩放控件。
4. 增加快捷键和工具提示。
5. 补充交互规格测试。
6. 使用 `textbook/目录页构建测试.pdf` 做真实文档事件模拟。
7. 执行完整 P2 自动化测试并更新实施记录。

## 6. 验收条件

- PDF 初次导入为适合宽度状态。
- `Ctrl + 滚轮` 能双向改变缩放比例，且不改变滚动位置为普通滚轮的步进结果。
- 普通滚轮不改变缩放模式或比例。
- 按钮和三个快捷键与鼠标操作结果一致。
- 自定义缩放始终限制在 25%–400%。
- 恢复适合宽度后状态标签和按钮状态正确。
- 翻页、跳页及分析范围跳页后仍保持用户选定比例。
- 非 PDF 来源不会错误启用缩放操作。
- 现有桌面工作台和 P2 全量自动化测试无回归。

## 7. 非目标

- 不改变 PDF 页码与教材印刷页码的映射规则。
- 不加入 PDF 编辑、批注、文字选择增强或页面旋转功能。
- 不调整图片预览的缩放行为。
- 不替换 `QPdfDocument`、`QPdfView` 或教材分析数据流。

## 8. 最终实施结果

- 新增 `src/textbook_builder/pdf_preview.py`，由 `ZoomablePdfView` 统一处理缩放倍率、上下限、指针锚定、适合宽度复位及 PDF 视口事件过滤。
- `desktop_app.py` 的 PDF 导航区新增缩小、比例状态、放大和适合宽度控件；无 PDF 时禁用，到达边界时分别禁用对应方向。
- `Ctrl + 滚轮` 被独立接管，普通滚轮继续交给 `QPdfView`；`Ctrl++`、`Ctrl+=`、`Ctrl+-` 和 `Ctrl+0` 仅在 PDF 面板范围内生效。
- `tests/test_pdf_preview_zoom_spec.py` 新增 4 项测试，覆盖无文档初态、鼠标事件隔离、快捷键、缩放边界、复位和跳页保持。
- `scripts/capture_workbench_ui.py` 在导入 PDF 时额外保存一次放大状态，便于持续检查比例反馈和导航区排版。

验证结果：

```text
python -m compileall -q src scripts tests
python -m pytest -q
57 passed
```

使用 `textbook/目录页构建测试.pdf` 在 1480×900 和 1180×720 下分别检查适合宽度及放大状态。四张快照中没有出现缩放行、页码导航和分析范围控件的覆盖；放大后 PDF 内容和滚动范围按预期变化。快照保存在 `storage/ui_validation_20260824_pdf_zoom/`。

本轮未调用第三方 API，也未修改 OCR、模型抽取、审查和导出契约。

## 9. 2026-08-24 响应式控制栏追加方案

### 9.1 问题与测量

真实 Windows 使用截图显示，页码导航和缩放控制分别占用两行，压缩了 PDF 页面可视高度。当前控制区高度约为 97 个 Qt 逻辑像素；在空间充足时合并为一行，预计可缩减到约 51 像素，释放约 46 像素的页面高度。

两组现有控件合计约需 744 像素。实测 PDF 控制区可用宽度如下：

| 窗口尺寸 | 显示全部 | 专注教材 |
| --- | ---: | ---: |
| 1180×720 | 372 px | 791 px |
| 1480×900 | 504 px | 1091 px |
| 1850×1164 | 647 px | 1393 px |

因此不能强制始终同排：专注教材时空间充足，但教材与图谱同时显示时会在常用尺寸下产生挤压。

### 9.2 已确认规则

1. 页码控制形成独立左侧组，缩放控制形成独立右侧组。
2. 容器根据两组控件实时 `sizeHint`、组间安全间距和自身可用宽度判断布局，不按固定屏幕分辨率判断。
3. 空间充足时两组位于同一行：页码组左对齐，缩放组右对齐，中间使用弹性空白。
4. 空间不足时自动换为两行：页码组位于第一行，缩放组位于第二行并继续右对齐。
5. 页面导航、缩放按钮和比例徽标统一到相同视觉高度，避免同排后基线错位。
6. 拖动顶部分割器、切换“教材/图谱/全部”和改变窗口尺寸后自动重新判断。
7. 响应式重排只改变控件位置，不改变缩放、翻页、页码、分析范围和快捷键行为。

### 9.3 追加验收条件

- 1180×720、1480×900、1850×1164 的专注教材布局均使用单行控制栏。
- 上述尺寸的显示全部布局在空间不足时稳定回退为两行，不扩大窗口最小宽度。
- 从专注教材切回显示全部，或拖窄教材面板后，控制栏能够从单行恢复为两行。
- 宽布局中页码组贴左、缩放组贴右，两组之间不存在覆盖。
- 窄布局中第二行缩放组保持右对齐，控件不被截断。
- 单行状态相较原两行状态释放 PDF 预览纵向空间。
- 既有 57 项测试以及新增响应式规格测试全部通过。

## 10. 响应式控制栏最终实施结果

- `pdf_preview.py` 新增 `ResponsivePdfControlBar`，通过页码组、缩放组和实时可用宽度动态切换单行/双行。
- 实际分组后的单行所需宽度为 685 px；不使用固定分辨率或固定布局模式作为判断条件。
- 单行时页码组左对齐、缩放组右对齐，控制栏高度为 48 px；双行时缩放组仍右对齐，高度为 94 px。
- 页面导航、缩放按钮和比例徽标统一为 40 px 控制高度；最窄 1180×720 显示全部布局中的页码控件均在组内边界内。
- 从显示全部切换到专注教材，再切回显示全部，布局能够完成双行→单行→双行的可逆变化。
- `tests/test_pdf_preview_zoom_spec.py` 增加三尺寸集成规格，该阶段正式测试入口为 58 项通过；2026-08-25 关系布局调整后的最新基线为 62 项。
- `capture_workbench_ui.py` 增加专注教材的适合宽度与放大状态快照，视觉证据位于 `storage/ui_validation_20260824_pdf_responsive/`。

验收结果：1180×720、1480×900、1850×1164 的专注教材布局均为同一行左右对齐，显示全部布局均按宽度安全换行；未发现控件覆盖、越界、布局抖动或缩放状态回归。单行布局相较原布局释放 46 px PDF 纵向空间。

本轮未调用第三方 API，也未修改 PDF 读取、OCR、模型抽取、审查和导出契约。
