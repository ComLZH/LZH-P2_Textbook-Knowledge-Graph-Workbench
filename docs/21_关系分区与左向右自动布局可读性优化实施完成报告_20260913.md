## 1. 结论

本轮已把用户反馈中的主要视觉问题落实为可运行实现：

- 《篆刻》的五个步骤从教材证据恢复为 `1 磨平印面 → 2 设计印稿 → 3 印稿上石 → 4 操刀刻印 → 5 钤印于纸`，父节点位于左侧，步骤在右侧同列自上而下排列。
- 步骤间四条真实递进关系仍保留为业务边；它们只退出普通横向 rank 计算，不会被降格为可隐藏的布局辅助线。
- 关系模式按活动语义/未决关系的连通分量生成单层浅色分区框；孤立节点统一进入“当前未连接知识点”区域，不逐点套框。
- 默认布局保持左向右主阅读流，组件在二维空间打包。用户不需要先拖动节点才能识别主要关系；自由拖拽继续属于 E20 后续增强。
- 源/目标卡片均进入避障保护，端口外法线、终端直段、箭头多边形、端口间距、长共线、分区边界和标签碰撞进入共享硬门禁。
- G6 与 Qt 使用同一共享场景中的卡片、路径、箭头和标签位置。G6 提供适配、邻域、分区显隐、重新排版和恢复默认视图；三种动作不再混用。
- 布局版本升级为 6，旧 v4/v5 手工坐标不再套入新场景；关系模式继续锁定节点拖动，避免卡片和路径形成半更新。
- 多组件 ELK 任务在一次 Node 子进程中批量执行并逐组件写出检查点；后段超时、退出或非法组件不会抹掉已完成且已校验的组件结果。

本轮没有修改两个用户导出的 XLSX，没有调用外部模型，没有改变审核状态、业务关系、教材归属、正式发布投影或 P4 协议。

## 2. 用户可见行为

### 2.1 关系探索

- 分区框只表示当前关系基础图中的阅读单元，不表示教材章节、知识包含或智能主题分类。
- 一个全连通网络只形成一个框；系统不会为了视觉上“多几个方块”而删除弱边或伪造主题。
- 框标题使用稳定的中性“某知识点相关”名称；标题、颜色和显示序号都不是业务身份。
- 分区可显隐，但显隐不改变成员坐标、关系或业务指纹。
- 一跳/二跳返回时恢复进入邻域前的相机和选择；`Esc` 可退出当前聚焦。

### 2.2 步骤阅读

- 顺序只从已有证据文本提取，优先使用节点、关系、occurrence 与 evidence anchor 的真实绑定。
- 支持阿拉伯数字、带“步骤/第 N 步”的数字、中文数字和圈号；不会根据 `target_ids` 数组位置猜序号。
- 编号作为上下文阅读约束进入投影，不写回知识节点全局属性。
- 卡片标题显示序号，完整名称和证据仍可从详情查看。

### 2.3 路径与标签

- 箭头尖端与卡片边框保持可见间隙，最后一段沿目标端口负法线接入。
- 同侧高连接度会分配稳定端口，容量不足时允许换到相邻侧。
- 标签没有安全位置时整组件隐藏并在详情保留完整内容；缩放显隐同时控制文字和背景，不留下空白小框。
- `accepted + unresolved` 继续同时显示审核通过与“含义待确认”，未知类型不会回退为 `explains`。

## 9. 放行级别、已知限制与下一步反馈

本轮达到规划的 **G20-B 核心阅读试用版**：五步顺序、左向右布局、单层关系分区、完整边界打包、端点/箭头、标签、两模式、双端基础渲染、状态兼容、离线和规模路径均可供用户实际使用。

没有声明 G20-C，原因是 V20-01 的历史缓存冻结缺口，以及 29 个包含未执行子场景的总项。以下限制在试用时应保持可见：

1. 分区是连通关系单元，不是主题聚类；一个大连通网络仍只会有一个框。
2. 美术默认关系图仍有 12 个可辨认点交叉；硬性穿卡、长共线、箭头遮挡和失败路径均为 0。教材定位模式交叉更多，仍主要用于归属核对。
3. 单个高密组件会进入诊断视图；目前没有从该诊断图直接选组件并在后端局部求解的完整入口。
4. Qt 是基础兼容渲染器；分区显隐、复杂键盘导航和高密关系详情仍以 G6 为主。
5. 自由拖拽、多层知识嵌套、单连通图主题发现仍是 E20，不应当作本轮漏实现。
6. Node RSS、安装包签名/杀毒软件/卸载矩阵和完整真实鼠标键盘 E2E 仍需专门发布验证。

建议用户本轮实际使用重点：

- 确认《篆刻》五步是否符合教材阅读习惯，以及右侧纵向递进线是否清楚。
- 在数学图中从“13.2.1 三角形的边”追踪四条关系，确认箭头端点不再与边框混淆。
- 尝试一跳、二跳、显示全部、显隐分区、重新排版和恢复默认视图，反馈相机返回与详情是否自然。
- 提供仍难追踪的具体节点、截图和当时使用的阅读模式；下一轮可针对真实拓扑优化软性交叉，而不盲目放宽硬门禁。
