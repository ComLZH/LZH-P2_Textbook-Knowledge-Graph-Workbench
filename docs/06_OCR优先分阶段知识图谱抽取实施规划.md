# 06. OCR 优先、单次页面感知与分阶段知识图谱抽取实施规划

更新时间：2026-08-22  
状态：方案已审查通过；核心实现、本地小样本和受控在线冒烟已完成，生产质量验收未完成

## 1. 目标与边界

P2 的核心目标是从教材内容中抽取知识点节点及知识点之间的关系，并保证结果有教材证据、可审核、可修订、可质量检查、可导入 P4。

本次调整不把 P2 扩展为 RAG、自动出题、掌握度、推荐或运行时图数据库。P2 内部可以增加 OCR、页面结构、中间候选和评估对象，但正式导出继续保持 `formal_graph.xlsx`、`graph_quality_report.md` 和 `layer_mapping.json`，P4 不承担建设态过程。

## 2. 已确认原则

1. 原生 PDF 文本优先；扫描 PDF 或图片在无有效文本时使用本地 OCR。
2. P2 直接读取 `shared_resources/models/ocr/`，不依赖 P1/P3 私有实现。
3. 页面 OCR、公式识别和版面证据按图片哈希缓存，正常路径不重复处理同一页面。
4. OCR 内容提取与页面顺序检查互相独立。
5. 页面顺序检查默认关闭；开启后先做本地检查，只把异常页对交给模型复核，系统不自动重排。
6. 第一次页面/章节分析可以同时输出节点候选和局部关系线索，但必须分开保存。
7. 局部关系线索不是正式边；所有页面完成后先归一化节点，再将线索映射到统一节点 ID。
8. 关系抽取阶段只能引用节点白名单，不能静默创建新节点。
9. 页内、相邻页、同节、跨节和跨章关系分层处理。
10. 单章节在上下文允许时可进行一次文本化全章整合；整本教材采用逐章抽取、全书节点归一化和跨章整合。
11. 没有可靠证据时不为图谱连通强制补边。
12. 模型输出始终是候选，必须经过确定性规则、模型复核和教师审核。
13. 归一化后的 `contains` 是层级事实来源，父级字段是统一生成的兼容投影。
14. 待审目录结构应正确嵌套显示，再由教师按章或全局批量确认。
15. 目录编排顺序与知识递进语义分开处理。

## 3. 目标数据流

```text
PDF/图片
  -> 原生文本读取或一次性本地 OCR/公式/版面处理
  -> PageEvidenceBundle 缓存
  -> 可选 PageContinuity 检查
  -> 首轮节点候选 + LocalRelationClaim
  -> CanonicalNode 归一化与别名映射
  -> 关系线索重映射
  -> 页内/跨页/章内关系整合
  -> 必要时跨章关系整合
  -> 规则检查 + 模型复核 + 教师审核
  -> P2 正式图谱
```

图片主要感知一次。后续关系整合优先使用缓存 OCR 文本、结构化证据、节点目录和局部关系线索；只有公式、图表、几何图或低置信度区域需要局部裁图复核。

## 4. 中间对象

### 4.1 页面证据

`PageEvidenceBundleDTO` 保存页码、图片哈希、OCR 模型、文本块、bbox、阅读顺序、公式、标题、视觉区域、缓存状态和原图路径。

### 4.2 页面连续性

`PageContinuityResultDTO` 保存相邻页编号、连续性分数、检查信号、是否需要模型复核、模型结论和用户确认状态。

### 4.3 局部关系线索

`LocalRelationClaimDTO` 保存临时端点、候选关系类型、证据锚点、推断范围、证据类型、理由和置信度。它不能直接进入正式导出。

### 4.4 归一化节点

`CanonicalNodeDTO` 和 `NodeAliasMappingDTO` 保存稳定节点 ID、规范名称、别名、来源临时 ID、证据及合并置信度。

### 4.5 关系候选

`RelationCandidateDTO` 只能引用规范节点 ID，保存关系类型、证据类型、推断范围、证据引用、理由、置信度和审核状态。

## 5. OCR 与缓存

P2 默认候选组合：

```text
PP-OCRv6_medium_det_infer
  -> 文本行检测
PP-OCRv6_small_rec_infer
  -> 文本行识别
```

`PP-FormulaNet_plus-S_infer` 作为公式证据候选，不直接决定知识关系。

缓存键至少包含页面图片 SHA-256、OCR 组合、OCR 配置版本和数据契约版本。缓存失效必须是显式且可追踪的；同一页面重复运行时优先回读缓存。

PaddleOCR 依赖保持可选：没有安装 OCR 运行环境时，带原生文本的 PDF 仍可运行；扫描页面返回明确的 `needs_review` 或 `unavailable`，不能静默伪造 OCR 结果。

## 6. 页面顺序检查

第一版在工作台提供 `检查 PDF 页面内容连续性` 开关，默认关闭。

本地信号包括：

- PDF 页序和印刷页码连续性；
- 标题、章节、列表和公式编号递进；
- 上一页末句与下一页首句承接；
- 页眉页脚及章节名称突变；
- 图片哈希和 OCR 文本重复；
- 文件名顺序冲突；
- 章节边界识别。

开启后只对低于阈值的页对生成复核任务。大模型只接收相邻页首尾片段、标题、页码、本地信号和必要裁图。模型不能自动修改页序；最终由用户确认。

## 7. 首轮抽取协议

首轮输出拆成：

```json
{
  "chapters": [],
  "node_candidates": [],
  "local_relation_claims": []
}
```

节点候选保存临时 ID、名称、类型、定义、页码、证据块和置信度。局部关系线索保存 `source_mention`、`target_mention`、候选类型、证据、理由和范围。

兼容期允许解析旧 `chapters[].knowledge_points[].candidate_relations`，但新分阶段路径会先把它们转换为局部关系线索，再在节点归一化后重建候选边。

## 8. 节点归一化

归一化顺序：

1. 明确节点 ID 和名称的完全匹配；
2. 规范化名称和别名匹配；
3. 教材章节、类型和证据辅助消歧；
4. 低置信度合并进入人工审核，不自动破坏性合并。

每个临时节点必须可追溯到规范节点或明确标记为未决。关系重映射只能使用已经建立的别名映射。

## 9. 关系分层整合

- 页内关系：来自首轮局部线索。
- 相邻页关系：使用两页 OCR 首尾、标题、节点目录和局部线索。
- 同节关系：汇总小节节点和证据。
- 跨节关系：使用全章节点目录和按需检索证据。
- 跨章关系：在全书节点归一化后，基于章节结构和相关证据单独生成。

关系阶段发现遗漏节点时只能输出待补节点建议，不能直接写入节点白名单。

## 10. 全章与全书输出

单章节在上下文允许时，节点归一化后使用一次文本模型进行全章关系整合。模型可输出完整候选节点快照与关系，但不得修改稳定节点 ID。

整本教材先生成 `BookManifestDTO`，记录目录、章/节页码范围、印刷页码映射、非正文页面和处理状态；之后逐章处理，再执行全书节点归一化、跨章候选筛选和跨章关系抽取。完整全书图谱由程序组装，不要求一次模型读取整本书。

## 11. 证据与审核

关系证据类型：

- `explicit`：教材直接陈述；
- `structural`：目录、标题或层级支持；
- `derived`：多个教材片段支持的有限推导；
- `model_inferred`：模型推测，缺少充分直接证据。

推断范围：

- `same_page`；
- `adjacent_pages`；
- `same_section`；
- `cross_section`；
- `cross_chapter`。

`model_inferred` 且没有直接证据的关系默认进入 `needs_expert_review`。页面先后顺序可支持结构和教学顺序判断，不能单独证明先修、推导、等价等强语义关系。

## 12. 质量门禁

确定性检查覆盖：端点、白名单、自环、关系类型、重复边、审核状态、证据、循环、孤立节点和层级异常。

模型复核覆盖：逻辑、方向、类型、必要条件、证据充分性和冗余性。教师保留接受、拒绝、编辑、反转、合并、拆分和专家复核能力。

孤立节点只诊断，不因名称相似、标签相同、向量接近或连通需求自动补边。

## 13. 成本控制

- 原生文本优先于 OCR；
- OCR 文本优先于整页多模态；
- 异常页面才升级模型；
- 公式和图形只提交必要裁图；
- 关系模型只接收节点白名单和必要证据；
- 跨章阶段先筛选候选对；
- OCR 和模型结果按版本缓存；
- 单页修改不触发整本书重跑。

## 14. 实施阶段

1. 冻结当前 P2/P4 基线，建立小型教材验收样例。
2. 增加页面证据、连续性、局部关系、规范节点、关系候选和运行清单契约。
3. 建立 P2 共享 OCR 适配器、页面渲染和缓存。
4. 增加默认关闭的页面顺序检查和异常复核接口。
5. 将首轮抽取协议调整为节点候选与局部关系线索分离。
6. 实现节点归一化、别名映射和关系重映射。
7. 实现页内、跨页和全章关系整合。
8. 为整本教材预留 BookManifest 和跨章处理接口。
9. 增加规则检查、真实模型小样本验证和人工金标准指标。
10. 保持 P4 接口稳定，完成全部回归测试与文档同步。

## 15. 验收条件

1. 正常路径同一页面 OCR 只执行一次并可命中缓存。
2. 同一完整图片原则上只进行一次主要多模态理解。
3. 顺序检查关闭时不产生额外顺序模型调用。
4. 顺序检查开启时只对异常页对调用模型。
5. 系统不自动重排用户 PDF。
6. 局部关系线索不直接进入正式导出。
7. 正式关系全部引用规范节点 ID。
8. 关系阶段不能静默创建节点。
9. 每条关系有教材证据或专家复核状态。
10. 不为连通强制补边。
11. 单章节能输出完整候选图谱。
12. 整本书采用逐章和跨章分层处理。
13. P2 正式产物继续兼容 P4。
14. 新增能力具有离线测试和真实教材小样本记录。
15. 模型调用、Token 相关元数据和处理版本可追踪。

## 17. 2026-08-22 目录层级补充方案

目录页专项测试证明首轮模型能够生成主要章、节节点及 `contains`，但分阶段底稿没有把关系投影成 `parent_node_id`。旧布局只读取父级字段并隐藏 `contains`，导致候选图层级丢失。

后续实施保持“节点与关系独立抽取”原则，在关系归一化后增加统一层级解析：候选图使用包括 `pending` 在内的无歧义 `contains` 正确嵌套；教师批量确认时原子接受结构节点和对应关系；正式导出检查父级依赖、多父级和循环。具体规则和冻结验收数据见 `08_目录结构层级投影与批量审查实施方案.md`。
