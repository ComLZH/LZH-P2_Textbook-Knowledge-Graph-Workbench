# 03. 数据契约与 P4 接口

更新时间：2026-09-13

## 1. P2 内部主要对象

- `SourceRecordDTO`：教材来源和页码/文件元数据。
- `EvidenceAnchorDTO`：文本、页码、图片、bbox 和目标节点/关系证据。
- `DraftKnowledgeItemDTO`：候选节点、候选关系、模型理由与审核状态。
- `P2ReviewDocumentDTO`：建设态 schema 2 聚合根对象；统一承载节点、结构作用域、出现、关系、证据、审核历史、发布 profile、视图状态和导入基线元数据。
- `FormalGraphMetadataDTO`：图谱 ID、学科、年级、学期和版本。
- `FormalNodeDTO`：正式知识节点。
- `FormalEdgeDTO`：正式关系。
- `FormalGraphWorkbookDTO`：正式图谱工作簿。

代码事实来源：`src/textbook_builder/contracts.py`。

视图契约补充：`ReviewViewStateDTO` 当前使用投影版本 2、布局版本 6，并以 `renderer + view_mode` 作为状态身份；`relations` 与 `textbook` 的隐藏项、焦点和位置不得互相覆盖。v4/v5 手工坐标不会套入 v6 场景，未来版本状态由旧客户端只读保留、不降级重写。视图状态、筛选和相机仍不进入业务指纹或 P4 正式投影。

## 2. 分阶段抽取中间对象

代码事实来源：`src/textbook_builder/pipeline_contracts.py`。这些对象只服务于 P2 建设态流程，不改变 P4 正式导入格式。

- `OcrTextBlockDTO`：块级文本、bbox、多边形、置信度和阅读顺序。
- `PageEvidenceBundleDTO`：页面 ID、图像哈希、原图路径、OCR 状态/模型、文本块、公式、标题、视觉区域和缓存状态。
- `PageContinuityResultDTO`：相邻页规则分数、信号、模型复核状态和人工确认状态。
- `LocalNodeCandidateDTO`：首轮独立节点候选和临时 ID。
- `LocalRelationClaimDTO`：首轮局部关系线索；不能直接作为正式边。
- `CanonicalNodeDTO`、`NodeAliasMappingDTO`：规范节点与临时节点/别名映射；`CanonicalNodeDTO.occurrences` 保留全部来源出现位置。
- `RelationCandidateDTO`：重映射后的候选边及证据类型、推断范围。
- `BookManifestDTO`、`ChapterManifestDTO`：整本书/章节处理清单。
- `ExtractionRunManifestDTO`：来源哈希、流水线版本、缓存命中、模型调用计数和输入字符估算。精确 Token 数仍取决于第三方模型 tokenizer/响应 usage。

## 6. 关系证据与推断范围

证据类型：`explicit`、`structural`、`derived`、`model_inferred`。

推断范围：`same_page`、`adjacent_pages`、`same_section`、`cross_section`、`cross_chapter`。

模型推断关系没有证据引用时会被标为 `needs_expert_review`；自环、未知关系类型和无法唯一解析端点的线索不会进入候选边。

## 7. P4 正式接口

P2 输出：

1. `formal_graph.xlsx`：`graph`、`nodes`、`edges` 三张表。
2. `graph_quality_report.md`：质量检查结果。
3. `layer_mapping.json`：章节层、知识点层、层级边、学习路径边和语义边。

旧桌面导出在这些业务契约外增加日期目录包装。v2 发布改为独立运行目录和 `publish_manifest.json`：先预检和暂存，验证文件哈希后提交 `runs/<run_id>/`，再原子更新 `current.json`。两种包装都不改变 P4 对 `formal_graph.xlsx` 与 `layer_mapping.json` 的内容协议；新版阻断时不会创建正式输出，也不会删除上一有效运行。

P4 消费位置：

- `p2_engine.adapters.importers.TextbookGraphImportPipeline`
- `p2_engine.adapters.readers.layer_mapping_reader`
- `p2_engine.core.graph_core.layer_mapping_index`

当前 3 项兼容测试验证：P2 正式表可以进入 P4 SQLite 图谱仓储并保留节点与关系。

新增中间对象会在 P2 内转换回现有 `DraftKnowledgeItemDTO` 和 `EvidenceAnchorDTO`，所以 `formal_graph.xlsx`、质量报告、分层映射及 P4 importer 均保持原协议。2026-08-15 P4 独立单元测试 33 项通过。

## 8. 所有权边界

- P2 负责候选、建设态审核和导出。
- P4 负责运行时正式图谱版本、题目挂载、状态和应用态视图。
- P2 不读取 P3 作答证据，也不生成 `MasteryState`。

## 9. 目录结构层级契约

- 候选层以 `contains` 为结构事实来源。
- `candidate_parent_node_id` 和 `FormalNodeDTO.parent_node_id` 是兼容旧工作簿、G6 combo 与 P4 接口的单父级投影。
- 一个子节点只有一个无歧义父级时可以生成投影；多个父级、缺失端点或循环必须形成质量问题，不能静默覆盖。
- `container` 不等于 `chapter`。候选视图和分层映射从层级深度派生 `chapter`、`section`、`subsection` 结构角色，P4 现有节点类型枚举保持不变。
- 候选层可以用待审 `contains` 正确嵌套；正式层只使用已通过节点和已通过关系。
- 结构批量确认必须同时接受结构节点与其 `contains`，非结构关系保持原审核状态。
- 目录阅读顺序保存为布局/顺序属性，不自动转换成 `progressive`。

## 10. 建设态 schema 2

代码事实来源：`src/textbook_builder/review_document.py`、`review_document_io.py`。

### 10.1 聚合对象

- `ReviewDocumentMetadataDTO`：`schema_version=2`、稳定文档/来源身份、来源哈希、分析运行 ID 和单调 revision。
- `ReviewNodeDTO`：知识对象或结构节点本体；`lifecycle_state` 独立于审核状态。
- `StructuralScopeDTO`：教材章/节/子节结构角色与阅读顺序；不把普通知识概念提升为容器。
- `KnowledgeOccurrenceDTO`：某知识对象在教材中的一次出现，可独立引用页、块、临时 ID 和证据。
- `ReviewRelationDTO`：稳定 relation ID、关系家族、端点、类型、出现/证据引用、审核状态、生命周期和迁移来源。
- `ReviewDecisionDTO`：追加式命令历史；撤销产生新 revision 和新记录。
- `ExportProfileDTO`：目标协议、发布范围和 `primary_membership_by_node`。
- `ReviewViewStateDTO`：非业务的 renderer 视图状态，不进入正式事实或业务指纹。

### 10.2 关系家族

| 家族 | 含义 | 显示/发布 |
| --- | --- | --- |
| `structure` | 教材结构包含结构 | 递归框；已接受后可投影为 P4 层级 |
| `membership` | 教材作用域包含知识对象 | 框内卡片/引用；发布时显式选择主归属 |
| `semantic` | 知识对象或允许端点间的知识关系 | 关系线；按 P4 能力表检查 |
| `unresolved` | 无法可靠分类的旧事实 | 问题线/诊断；未裁决时阻止正式发布 |

### 10.3 v2 审查包

工作表为 `review_meta`、`draft`、`scopes`、`occurrences`、`relations`、`evidence`、`migration_audit`、`review_history`、`export_profiles`、`view_state`、`import_baseline`。`draft` 是教师友好视图，扩展表才是完整事实；保存回读以业务指纹校验，不允许仅靠 `draft` 恢复多归属和历史。

`import_baseline` 保存对象/字段值、base revision/export ID 及字段哈希。Excel 回写按稳定 ID 进行三方比较；排序不改变身份，显式空值与缺失单元格分开，删除整行不会隐式删除业务对象。

### 10.4 正式投影约束

- 正式投影只消费活动、已接受且在发布范围内的显式关系。
- `candidate_parent_node_id` 和 `candidate_prerequisites` 只用于 v1 迁移/兼容显示，不能覆盖显式关系审核状态。
- P4 v1 仍是单父级目标；多归属知识必须在 profile 中选择主归属，次归属保留在审查文档和发布遗漏说明中。
- 预检绑定文档 revision、业务指纹、profile 指纹和目标能力版本；过期计划拒绝使用。

### 10.5 布局版本 6 的派生契约

- `ReadingSequence`：由已有证据、occurrence、节点和关系引用派生的上下文阅读顺序；不写入 `CanonicalNodeDTO`，不把显示序号升级为跨教材的知识属性。
- `VisualRelationGroup`：由关系基础图连通分量派生的单层阅读分区；分区 ID 由文档、成员集合和分组版本确定，标题、颜色与显示序号不构成身份。
- `VisualGroupGeometry`：共享场景中的分区矩形、标题区和内容区；只服务渲染与几何门禁，不是教材 scope、知识实体或 membership。
- `routing_only`：只用于布局约束职责，表示有序步骤间的真实递进边不参加普通 rank 计算；该边仍按原 `relation_id`、类型、状态和证据进入显示、审核及合规的正式投影。
- `SceneLayoutResult` 版本 6 与几何测量规格 3 同时携带实际路径、端口法线、箭头多边形和标签矩形；渲染器不得另算端点或替换为未经门禁的直线。
