## 1. Python 环境

建议使用独立 Python 3.11/3.12 环境：

```powershell
python -m pip install -r requirements.txt
```

Windows 扫描页 OCR 是可选的大依赖，按需安装：

```powershell
python -m pip install -r requirements-windows-ocr.txt
```

当前已验证组合为 `paddlepaddle==3.2.0`、`paddleocr==3.7.0`、`paddlex[ocr]==3.7.2`。

P2 与 P4 位于同一工作区。`run_project.py` 和集成测试会显式加入 P4 目录，以加载历史包名 `p2_engine`。

## 2. 模型配置

项目根目录保留本机 `.env`。如果需要重新创建，可复制示例文件：

```powershell
Copy-Item .env.example .env
```

配置字段：

```text
TEXTBOOK_BUILDER_LLM_API_KEY=
TEXTBOOK_BUILDER_LLM_MODEL=qwen3.6-plus
TEXTBOOK_BUILDER_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
TEXTBOOK_BUILDER_LLM_ENABLE_THINKING=false
TEXTBOOK_BUILDER_PROGRESS_RECORDING_MODE=full
```

模型名和 Base URL 是本地默认值，可以按兼容服务调整，不属于跨项目正式契约。

`TEXTBOOK_BUILDER_PROGRESS_RECORDING_MODE` 可设为 `full`、`summary` 或 `off`。工作台也可在“模型与识别 → 过程记录”中热切换；开发期默认 `full`，功能稳定后改为 `off` 即可停止写入。

## 4. 安全规则

- 真实 `.env` 不进入版本管理。
- API Key 不写入 README、截图、测试产物或日志。
- 已经进入共享目录或提交历史的 Key 必须在服务端轮换，仅删除文件不足以使旧 Key 失效。
- 界面显示 Key 时应使用密码输入模式，错误信息不得回显完整值。
- 在线测试会把所选页面的 OCR/原生文本、块级证据和归一化节点发送到配置的第三方 Base URL；执行前应确认教材数据允许出站。
- `progress_recordings/` 中的 OCR 文本和模型响应只用于本地开发排障，默认被忽略规则排除，不应上传到共享仓库。
- 记录器会脱敏 API Key、Authorization、access/refresh token、secret、password、Bearer 值和 `data:*;base64` 图片；记录写入失败不得中断业务链路。
- G6 内嵌 JSON 对 `</script>`、U+2028 和 U+2029 做安全转义；用户内容不得作为可执行脚本或未转义 HTML 拼接。
- 读取旧视图位置时拒绝 NaN、Infinity、非数字和绝对值超过 10,000,000 的坐标；非法值不得进入画布变换或覆盖有效状态文件。
- ELK 批处理结果逐组件校验请求 ID、节点集合、有限数值、正尺寸和协议版本；非法/缺失结果只影响对应组件，不能被当成成功几何。

## 5. 输出目录

- `storage/`：运行缓存、演示和工作台中间产物。
- `导出测试/`：历史人工复现目录；根目录现有文件可能来自不同轮次，必须结合图谱 ID、时间和清单判断，不能直接混合作为一轮结果。
- `textbook/`：本地教材源文件。
- `过程性可视化记录/`：历史视觉记录。
- `progress_recordings/`：开发阶段单次分析全过程记录，按 `YYYY-MM-DD/HHMMSS_<analysis_run_id>/` 隔离。

桌面端选择输出目录后，实际结果写入当天 `YYYY-MM-DD/` 子目录，并生成 `export_manifest.json`。同一天再次导出会先清理该日期目录中的已知旧产物；若质量门禁失败，旧 `formal_graph.xlsx` 和 `layer_mapping.json` 不会残留。命令行服务为兼容现有脚本，默认仍直接写入指定目录。

新增生产数据时，应把“临时运行结果”和“人工确认基线”分开，不能仅凭文件存在判断功能完成。

## 6. 可选依赖

- PDF 渲染使用 PyMuPDF。
- PDF 切分优先使用 `pypdf`，不可用时允许回退或记录为 unavailable。
- NetworkX 用于当前质量检查实现。
- 真实大模型调用使用 OpenAI-compatible SDK。
- 本地扫描页 OCR 使用共享目录中的 `PP-OCRv6_medium_det_infer` 与 `PP-OCRv6_small_rec_infer`，P2 不维护私有模型副本。

## 7. OCR 配置

正常情况下无需新增 `.env` 字段，P2 自动从系统工程根目录的 `shared_resources/models/ocr/` 读取模型。需要覆盖时可使用：

```text
TEXTBOOK_BUILDER_OCR_DET_MODEL=PP-OCRv6_medium_det
TEXTBOOK_BUILDER_OCR_REC_MODEL=PP-OCRv6_small_rec
TEXTBOOK_BUILDER_OCR_DET_MODEL_DIR=
TEXTBOOK_BUILDER_OCR_REC_MODEL_DIR=
TEXTBOOK_BUILDER_OCR_MODEL_CACHE_DIR=
TEXTBOOK_BUILDER_OCR_DEVICE=cpu
TEXTBOOK_BUILDER_OCR_LANG=ch
```

若共享目录包含中文，Paddle 在部分 Windows 环境无法稳定加载，适配器会把模型复制到系统临时目录下的 `p2_textbook_ocr_models/`。这只是运行缓存，原共享模型不会被移动或修改。

桌面工作台默认启用 OCR、默认启用分阶段抽取、默认关闭页序检查。命令行本地证据验证示例：

```powershell
python run_project.py staged-check --pages 11-13 --force-ocr --check-page-order
```
