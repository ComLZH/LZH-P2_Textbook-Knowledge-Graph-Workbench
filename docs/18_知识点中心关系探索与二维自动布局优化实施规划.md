## 0. 交接摘要、状态及阅读方法

### 0.1 本轮要解决什么

用户实际使用美术教材篆刻内容后发现：节点在一列中过度堆积，连线重合、穿过无关卡片，密集关系标签妨碍理解。用户已经确认，默认阅读方式应是**从一个知识点出发追踪其关联，再查看关系和教材证据**，而不是默认按教材页、章、节逐项核对。

本规划将下一轮目标定义为：在不改变业务事实的前提下，使节点、关系、标签和交互共同服务于可追踪的二维关系阅读。不能只调整间距、颜色或曲率，也不能以隐藏大部分事实代替自动布局。

### 0.2 事实、决定、假设与完成状态

本文使用以下口径：

- **事实 F**：已读取当前代码、用户底稿或生成页面，或完成只读计算。
- **决定 D**：本规划明确的实施边界与默认行为；其中用户直接确认的事项单独注明。
- **候选/初始参数**：需要在 S1 样例实验中核实，不代表算法已选定或参数已验收。
- **验收 V18**：实施必须提供的证据；R3 的实际状态以第 22 节和文档 19 为准。

R1 完成规划初稿与历史边界说明；R2 根据专家意见、源码/输入记录和用户确认修订规划。用户随后授权进入实施，R3 回填代码、运行时、候选评估、冻结样例、浏览器与规模证据。用户导出底稿未被修改，也未请求外部模型重新抽取；本轮最终自动化基线为 `90 passed`。

### 0.3 接手者优先阅读路径

1. 阅读本节、第 1 节决定表、第 2 节实证基线，理解任务与禁止事项。
2. 阅读第 4–6 节，理解两个阅读模式、业务身份与共享场景契约。
3. 阅读第 7–10 节，理解布局、引擎选型门禁、边路由和标签约束。
4. 阅读第 11–15 节，完成交互、视图状态、双渲染器、性能和相关数据问题设计。
5. 按第 16–18 节实施与验收；使用第 19 节问题表、第 20 节交付清单完成交接。

**实施已经按 S0→S6 推进。最终采用 ELK 主后端＋Python 受门禁回退，交付详情见第 22 节和文档 19；本段其余章节保留原规划语义，便于追溯设计取舍。**

| D06 | 同一阅读模式共享场景结果 | G6 与 Qt 不再各自决定边路径、箭头和标签位置；同一配置对应同一业务投影与逻辑几何 |

| D11 | 视图状态独立于业务与正式导出 | 布局、锁定、相机、筛选、聚焦不得修改业务 revision、审核状态或 P4 发布选择 |
| D12 | 可读性验收独立于节点几何验收 | 卡片不越界不等于边可读；增加穿卡、重合、标签及追踪任务检查 |

| D15 | 允许评估随包交付辅助运行时 | 用户确认无明确禁止新增可执行文件的规定；教师无需手工安装或配 PATH，交付成本须实测 |
| D16 | 双端语义/几何一致，交互能力分级 | G6 承担丰富探索体验；Qt 保证基础审查，不要求复制全部手势、动画与抽屉形态 |
| D17 | 隐藏、归属管理、归档分别命名 | 关系模式不暗选“本小节”；归档限定当前审查文档、可预览/撤销，不等同物理删除 |

以下是规划层的具体化，不是用户逐项指定的 UI 样式：视图协议版本、初始缩放阈值、具体引擎执行方式、布局质量阈值。接手者按门禁验证后可以调整参数，但更改 D01–D18 或引入收费/联网依赖须重新说明影响并取得方向确认。

### 1.1 明确不做的事项

- 不重新定义整个知识关系本体，不自动把 `contains` 分解为新的业务类型。
- 不自动纠正待审关系方向、删除循环、补齐孤立节点关系或接受模型建议。
- 不以模型生成的坐标作为布局事实，不为排版重新调用 OCR/LLM。
- 不扩展 P4 正式协议、不启动服务器版、多租户或云端布局服务。
- 不将完整教材正文、证据图片、密钥、个人路径发送给第三方布局服务。
- 不承诺无限规模全量卡片和全量标签在一个屏幕上清楚呈现。

文档 17 的节点/容器验证仍是对应样例的有效历史证据。本轮不能将它改写成“此前没有问题”，也不能倒推为“任意知识网络均已可读”。下一轮分别报告业务完整性、节点几何、边路由、标签可读性和交互，不使用一个 `violations=[]` 汇总代替所有维度。

## 3. 优化目标、约束优先级与失败行为

### 3.1 硬性不变量

1. 节点/关系的业务身份、端点、原始类型、审核状态、证据和出现记录不因布局而改变。
2. 活动范围内每条业务关系必须有且只有一个覆盖账本归宿：实际线、真实嵌套、上下文表示、显式过滤或可展开汇总。
3. 卡片内部互不覆盖；教材模式中的子项位于真实父框内容区，避开标题区。
4. 实际绘制的边路径不穿过非端点知识卡片或不可穿越标题区；没有合法路径时报告失败，不伪造直线作为成功结果。
5. 箭头指向真实目标；对称关系不凭布局产生先后；内部 cycle-breaking 不改变输出业务方向。
6. 被显示的完整标签不得遮住节点标题/操作区；被抑制的标签有可发现的详情入口。
7. 不因视图过滤或临时聚焦改变 Excel/P4 业务导出集合。

### 3.2 优化目标不是全部硬约束

在上述不变量满足后，按以下顺序比较候选：不可区分的线段重合、关系交叉、路径长度/绕行、整体紧凑度与宽高匹配、增量位置稳定性。聚焦操作以稳定性优先，不重排；显式全图重排以整体可读性优先。

候选成本应记录向量而非只有一个加权总分，例如：

`(hard_violations, ambiguous_overlap, crossings, detour, aspect_penalty, displacement)`。

先拒绝硬违规，再在同级合法候选之间优化。不能通过增加穿卡来减少交叉，也不能把所有边绕到外侧制造“零交叉”但极长的路径。不可避免的交叉需要清楚呈现，并支持单边追踪。

### 3.3 失败时如何处理

- 拓扑无效：保留业务表格与问题清单，禁止布局器自行删除对象修图。
- 布局/路由失败：保留同一数据版本的最近合法场景，显示降级原因；没有合法场景时提供节点/关系列表和明确的局部查看入口。
- 旧场景与当前业务版本不同：明显标注“旧快照”，禁用其业务编辑；不能只更换标题后伪装当前结果。
- 局部过密：提示范围、被汇总/未展开数量，允许进入邻域、筛选或列表，不能静默丢边。
- 不把视觉问题混入发布业务门禁：可读性不合格会阻断“视觉验收通过”和视图导出成功标识，但不自动拒绝已接受知识事实。

## 4. 产品形态：阅读模式与渲染器分离

### 4.1 两个维度

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| 阅读模式 view_mode | `relations`（默认）、`textbook` | 用户此刻如何理解知识 |
| 渲染器 renderer | `g6`、`qt` | 同一场景由什么技术绘制 |
| 阅读范围 view_scope | `overview`、`neighborhood`、显式筛选范围 | 当前展开哪些对象 |

不要把“G6/兼容视图”两个标签改造成两个互不一致的业务图。相同模式、范围、尺寸规格与状态，两个渲染器读取同一份场景；不同模式可有不同位置，但业务关系可对账。

“一致”指业务身份、逻辑几何和基础审查能力，不要求所有 UI 手势与动画完全复制。共同模式/范围可通过工作台控件驱动；具体能力分级以第 13.2 节为准，不能用轻量定位豁免 Qt 的端点、证据或关系覆盖。

### 4.2 默认关系探索模式

- 总览以业务知识节点为中心，一个活动知识对象默认一张卡片，归属作为徽标/上下文清单，不让每个教材引用都复制为一张大卡。
- 建议 view ID 为 `node:{node_id}@relations`；这是新投影实例 ID，不是新业务 node ID。
- 多归属节点显示归属数量，点击展开所有出现、章节、页码和对应 membership ID；不暗选主归属。
- 教材结构默认通过面包屑、筛选和详情表达，不强迫整张关系图服从多层大框。
- 若语义边端点本身是结构对象，应显式生成 `scope-endpoint:{scope_id}@relations` 的结构卡片，保留端点身份；不能丢边或假装它是普通概念。
- 局部聚类区域仅称“关系分组/布局分区”，没有教材章节含义。默认不用模型命名新知识分类；启发式组名必须带视觉分组提示。
- 首屏不自动选择所谓“最重要知识点”，33 节点样例默认完整展开总览，由用户点击进入关系追踪。

这会修订文档 16“所有显示模式均按归属复制实例”的表现规则，但不修订多归属业务模型。教材模式继续保留每处引用；两种模式的切换必须以 node ID 而不是旧 view ID 对接。

### 4.3 教材定位模式

- 保留现有 structure/membership 驱动的章、节、子节嵌套。
- 一个业务对象按有效 membership 生成多处引用卡片；现有 `node:{node_id}@{membership_id}` 可继续使用。
- 无归属对象位于虚拟待确认区域；内部同样做二维紧凑布局，不能退回单列堆叠。
- 语义关系每条只选择一对端点实例，优先当前明确的教材上下文，再选择共同作用域、路径更短的实例，最后用稳定 ID 打破平局。
- 端点选择不能随悬停和相机移动改变；展开/折叠或显式切换上下文时才重算，并记录选择理由。
- 在节点详情中可以跳转其他出现位置，主归属裁决仍使用既有发布选择流程。

### 4.4 默认信息与计数

顶部区分业务节点数、可见卡片数、业务关系数、实际关系线数、汇总/筛选数量，避免多引用造成“节点突然增多”的误解。审核状态独立统计 pending、accepted、rejected、needs_revision、needs_expert_review；“待审”组合口径必须有说明。

关系模式中只显示上下文的 membership/structure 仍计入业务关系，不冒充可见线。颜色变淡不等于过滤；标签被隐藏不等于关系被隐藏。

## 5. 共享投影、身份与表示覆盖

### 5.1 投影职责

`ReviewProjectionBuilder` 继续只读 `P2ReviewDocumentDTO`。拟增加显式模式/范围参数和节点上下文，不在投影器中执行引擎、访问浏览器、更新业务或写文件。

拟新增 `ViewSelectionContext`：

| 字段 | 说明 |
| --- | --- |
| document_id / document_revision | 校验所选对象是否仍存在于当前业务版本 |
| view_mode / view_id | 当前展示实例 |
| node_id / relation_id | 明确的业务目标；按对象种类选用 |
| membership_id / occurrence_id | 仅在用户已明确选择本处归属/出现时填入 |
| scope_id | 教材定位上下文，不能默认变成主归属 |
| aggregate_id | 选中汇总时使用；须先展开再逐对象审核 |

关系模式的“管理教材归属”先列出明确的归属对象；没有 membership_id 时不能执行“移除本处归属”，也不能拿第一条或主归属代替。单张知识卡不意味着存在唯一“当前小节”。隐藏卡片、管理归属、当前文档内归档、拒绝关系分别使用明确命令与影响范围，详见第 11.5 节。

### 5.2 两层表示账本

保留“业务→投影”事实账本，再增加“投影→当前显示”可见性账本；二者不可互相覆盖。

拟定事实表示枚举：

- `line`：一条可识别的投影关系线。
- `nested`：教材模式中实际可核对的嵌套。
- `context`：关系模式中由明确的教材归属/结构上下文入口表达。
- `filtered`：显式拒绝状态筛选、隐藏或范围过滤，有唯一主原因及附加原因。
- `aggregated`：汇总对象携带完整 represented_relation_ids，可展开回每条关系。

显示账本另记 `label_suppressed`、`dimmed`、`outside_viewport`、`collapsed_endpoint` 等。移出屏幕不能改变事实账本；聚焦变淡仍为 line。

每个活动 relation ID 恰有一条事实账本记录。`aggregated` 中成员集合不能与独立 line 重复；同一条边不允许在分组内部和分组之间双重计数。空 relation_id 的纯视图事件单独存放，不进入业务覆盖分母。

### 5.3 关系类型显示注册表

新增共享纯数据注册表，按 `relation_family + raw/normalized relation_type` 决定显示；不能只依赖 `normalize_relation_type` 的别名回退。

| 类别 | 显示与箭头 | 空间约束 |
| --- | --- | --- |
| structure / membership | 教材框或上下文入口；详情显示真实类别 | 教材模式限定父子归属；关系模式不强制大框 |
| prerequisite / progressive | 前置/递进，保留方向 | 局部顺序优先；状态影响强弱，不自动接受 |
| derives_to | 推导，保留方向 | 弱于明确工序/前置的方向偏好，不强迫全图链化 |
| explains / applies_to / represented_by | 解释/应用/表征，保留业务方向 | 主要表达邻接，不作为全局教学层级 |
| parallel / equivalent / contrast | 并列/等价/对比；无教学先后，箭头样式由注册表明示 | 邻近/成对偏好，不硬性压入同一 x 坐标 |
| unresolved / contains | “包含·含义待确认”；详情保留原始类型和理由 | 弱邻近，禁止生成章节父子；原始指向可用候选箭头并明确其未决身份 |
| 未知或空类型 | “未知关系〔原始值〕/关系类型待确认” | 默认不推导方向和层级；保留原始源/目标记录 |

unknown 不再回退为 explains。关系含义待确认与 review_status=pending 是两个独立维度，均可查询；不能将“含义待确认”当作第六种审核状态。

### 5.4 指纹拆分与稳定顺序

拟新增：

- `topology_fingerprint`：排序后的节点/实例、业务端点、关系类别、模式相关成员；排除相机和单纯颜色变化。
- `constraint_fingerprint`：顺序/邻近约束、审核状态导致的约束差异、锁定、折叠与范围。
- `metrics_fingerprint`：卡片尺寸档位、文字/徽标预留、端口和线宽规格。
- `style_fingerprint`：颜色、透明度及不影响边界的外观。
- `layout_fingerprint`：上述布局相关输入、引擎/算法版本、参数、固定随机种子、布局宽高档位。

集合序列化先按稳定 ID 排序，禁止依赖输入数组顺序。不能将现有 `structure_fingerprint` 直接当作纯拓扑指纹。接口过渡期保留旧字段用于旧调用，新增字段有独立版本，不就地改变旧哈希含义。

## 6. 场景几何契约与代码职责

### 6.1 唯一场景输出

将当前只含节点/框矩形的 `SceneGeometry` 扩展为版本化 `SceneLayoutResult`（拟定名称），由布局服务产生，两个渲染器消费。渲染器不得再用“左右关系”覆盖已计算边路径。

```text
P2ReviewDocumentDTO（只读业务快照）
  → ReviewProjectionBuilder（模式、身份、事实覆盖）
  → LayoutRequestBuilder（规格、约束、障碍、视图状态）
  → LayoutEngineRunner（可取消；统一 Python/可选 JS 后端边界）
  → Route / Label / ReadabilityValidator（有界检查与修正）
  → SceneLayoutResult（同一版本的节点、框、边、标签）
       ├─ G6 adapter
       ├─ Qt adapter
       └─ 离线静态审查快照
```

### 6.2 拟定输入输出字段

| 对象 | 必需字段与语义 |
| --- | --- |
| LayoutRequest | request_id、document_id/revision、projection_schema_version、view_mode、view_scope、view_revision、各指纹、engine/config、metrics、previous_layout、pins |
| NodeBox | view_id、业务 ID、parent_view_id（可空）、rect、title_rect、badge_rect、ports、context_ids |
| ScopeBox | 真实 scope_id/虚拟标记、外框、内容区、标题障碍、parent、border portals |
| VisualGroupBox | 仅视图 group_id、成员、布局包围盒；不得写入 document.scopes |
| EdgeRoute | edge_view_id、relation_id、source/target_view_id、source/target_port_id、坐标点/段、箭头位置与切向、layout_scope、route_status |
| EdgeLabel | relation_id、文本、可见级别、rect、路径位置、抑制原因；标签不作为业务节点 |
| SceneLayoutResult | request 身份回显、引擎/版本、逻辑坐标系、node/scope/group/route/label 表、canvas_rect、覆盖账本、issues、timings、是否降级 |
| ReadabilityReport | 版本及指纹、hard violations、路径/标签指标、可见/汇总统计、阈值版本、测量方式和未测项 |

所有业务端点为稳定字符串 ID，不能以标签文字连接。坐标为有限浮点逻辑单位；拒绝 NaN/Infinity、缺端点、负尺寸、重复 ID、过量路径段。父子局部坐标进入输出前统一转换为场景坐标，不能重复叠加 parent 偏移。

### 6.3 路径中间表示

首选表达为 `M/L/Q/C` 段序列或带等价信息的点列；适配器不得丢弃弯折点重新拟合任意曲线。圆角处理如改变路径，应在共享层输出最终段并校验。箭头按最终末段切向绘制，不按源点到目标点的直线弦方向绘制。

节点框、路径及标签必须来自同一 request，不允许新节点坐标配旧路由。布局结果发布给 UI 是一次原子场景替换。

## 7. 二维布局策略

### 7.1 先分析拓扑，不先按节点类型分列

1. 对当前允许显示的活动关系建立邻接图；未决边参与弱邻接，但不生成确定教学顺序。
2. 按模式建立知识实例和实际结构约束。
3. 计算无向连通块、度数、强连通分量、方向主链候选和跨框关系分布。
4. 分别安排连通块，再将含其路由/标签的整体包围盒打包。
5. 孤立节点放在紧凑区域，保持可选择及证据入口，不在主要路径中穿插撑长列。

不能把“概念/性质/方法”等类型固定为列。知识类型用样式/筛选表达，节点空间位置优先反映关联。

这里的邻接图只使用当前需要画线的 semantic/unresolved 关系；structure/membership 在教材模式中作为真实容器约束、在关系模式中作为上下文，不偷偷转为吸引边。否则同一教材的所有知识又会被一个目录父节点强行聚成一团，抵消模式分离。

### 7.2 局部布局策略及约束强度

| 局部结构 | 优先策略 | 约束边界 |
| --- | --- | --- |
| 明显前置/工序链及分支 | 局部分层＋层内交叉优化 | 主链尽量顺读；其他边不都强制加 rank |
| 集合/中心连接多个邻居 | 扇出、双侧或多行邻接布局 | 中心就近，端口分散；不能当教材父容器 |
| 对称双节点/小单元 | 紧凑成对或小网格 | 邻近不表示教学先后 |
| 混合稀疏网络 | 紧凑图布局＋避障路由 | 可以使用确定种子的一般图候选；不是持续抖动的物理仿真 |
| 有方向环 | SCC 局部组织、回边显式可追踪 | 不删除/翻转业务边；区分真实方向环与布局约束冲突 |
| 跨章多归属 | 关系模式扁平知识图；教材模式复合布局 | 模式之间只换实例表达，不改归属 |

初始约束等级：已接受 prerequisite/progressive 的局部顺序为高优先；待审同类型次之；需专家复核的方向建议更弱；explains/applies_to/represented_by 和未决关系主要产生邻近偏好。所有权重为算法输入，不表示业务置信度或审核结论。

业务箭头是硬约束；“目标一定在右边”不是全局硬约束。仅当局部无环且不与真实教材/锁定条件冲突时，要求主链单调。冲突时记录布局例外，不把对称边硬压同层导致的冲突误报成知识循环。审核状态变化导致约束改变时采用局部重算或标记待重排，不在用户点击审核后突然全图换位。

### 7.3 同层排序与长列控制

候选分层布局至少包含按邻接的重心/中位数层扫描或引擎等价交叉最小化，再进行坐标分配。ID 排序只用于确定性平局，不作为主要阅读顺序。

没有已知前序边的 24 个节点不能被解释成一个真实教学层级。跨连通块分别排列；同块内弱关联节点可在主链周围分区，必要时打散视觉列。只在不违背局部主链时使用分行/多列排列，不能按“每 6 个换列”机械切断主链。

同理，不把“每列最多 4～5 个”作为先行修复。孤立节点、小型独立连通块可优先二维打包；有边的同一连通块必须联合验证节点顺序、通道、端口和标签。合法长链允许保持顺读或采用经验证的转向，不以凑方形为目的打散。

美术基线必须显著改善 24/6/1/1/1 的分布。初始验收目标：相同卡片规格下，不再存在 24 节点共线长列；非真实长链样例的单一视觉列占比目标不超过 40%。这是 S1 需要确认的工程目标，不可用于强行改变拓扑。

### 7.4 全局二维打包

- 以连通块或已求解子框作为不可相互重叠的矩形单元，单元范围包含外侧路由、箭头和可见标签。
- 枚举少量目标宽度，使用可确定复现的 shelf/skyline 等矩形打包，比较合法候选；不得只依节点数量估面积。
- 目标宽高比来自实际图谱内容区，扣除工具栏、详情面板、DPI；不是整个桌面窗口的宽高比。
- 使用宽度档位和防抖；窗口每变化 1 像素不自动全图重排。初始以打开/显式重排/用户确认模式切换时确定档位。
- 显示顺序用可解释规则：主要连通块先、其余按证据阅读顺序与稳定 ID；并列顺序不声称重要性排序。
- 不在较小窗口强行缩小所有文字到不可读来满足一屏展示。

### 7.5 教材模式的递归与跨框协调

递归自底向上测量、自顶向下定位原则保留，但同级子框进行二维打包。跨框边数量影响同级框相邻偏好；仅独立排好每章再画跨章线不足以通过验收。

每条跨框边记录最低共同祖先、出入边界端口与合法走廊。父框内部不能把整块父矩形当障碍，否则其子项间无路可走；应分别处理标题区、无关子框和边界可穿越窗口。框尺寸最终应包含合法路由所需通道。

## 8. 引擎选型、运行时与有限求解

### 8.1 候选及 E1 门禁

| 候选 | 角色 | 不能直接假定的能力 |
| --- | --- | --- |
| 当前 recursive v4 | 冻结对照、问题重现、故障诊断 | 不能作为已满足可读性的兜底 |
| A：Python＋现有 NetworkX＋共享几何模块 | 正式候选；覆盖连通块、层内排序/局部布局、二维打包、端口、避障和标签 | 不因没有新增 JS 运行时就假定成本低、速度快；自研路由的正确性、取消与维护成本均须验证 |
| B：ELK/elkjs＋共享预处理/打包/校验 | 与 A 同等正式候选；验证分层、端口、复合图与边标签 | 不假定全部约束可直接表达，也不假定固定节点独立路由开箱即用；必要补充步骤计入总成本 |
| Dagre | 普通方向图的轻量对照，辅助识别复杂引擎的真实收益 | 不作为第三套完整产品建设；节点/路径点输出不能直接证明跨框、避障和标签合格 |

ELK 官方描述支持分层交叉优化、不同路由形式、端口和复合层级；Dagre 明确将布局与绘制分离并输出边路径点。上述是候选能力依据，不是本项目适配结果。参见第 21 节官方资料。

S1b 必须使用同一投影/尺寸/样例比较，至少包含：33 节点美术、真实多层教材、多归属跨框、星状高连接度、方向环、长中文标题。记录完整配置、版本、硬违规、交叉/重合、面积、稳定性、耗时、依赖和许可证。A/B 复用同一输入构造、指标及输出契约；不得给其中一方预先整理数据、隐藏难边或放宽判据。

E1 是有界技术原型门禁，不要求先做两套完整 UI、状态系统和发行产品。启动实验前记录时间盒、代表场景和终止条件；先打通最小 Scene 路径与测量脚本，再逐项证伪关键能力。超过时间盒仍未证明的能力标“未证实”，不能以候选品牌代替证据。生产级实现与故障矩阵在 S3–S6 完成；若选定候选在生产验收中暴露根本缺口，重新打开 ADR。

E1 放行条件：

1. 原始业务关系零丢失、零方向变更；未决和对称关系规则成立。
2. 最小 G6/Qt 适配样例可消费同一场景路径；无 WebEngine 的首次打开/重新计算及无 GUI CLI 有可执行的离线计算路径，不依赖已有缓存。
3. 在最小原型中证明第 17.2 节的对象完整、无误标、无重叠/穿卡/不可辨长段重合等静态硬指标，且比旧基线明显紧凑；完整交互任务及生产状态恢复留给 S4–S6，不能反过来成为 E1 的循环依赖。
4. 跨框、节点锁定、增量更新、取消/超时的高风险能力有最小实验和明确失败边界；不得只留下未经验证的设想。
5. 完成目标 Windows 普通用户、无网络、无开发者 PATH 的最小打包/运行实验，记录运行时发现方式与实际体积；最终安装、安全扫描和卸载回归留给 S5/S6。
6. 提交 ADR，比较完整链路而非单个算法：质量、性能、交付体积、许可、安全、取消、维护与测试负担；说明选择及不选另一候选的证据。

若 A/B 均通过相同硬门禁，优先总交付/维护成本更低的方案；不是单凭“纯 Python”字样决胜。若 B 在复杂路由或跨框上有显著、可复现的收益，可接受有证据支持的运行时成本。若 A 未过硬门禁，不能为回避依赖而降低可读性要求；反过来也不能只因 B 功能更多就提前选定。

若没有候选满足 E1，不得把“已接入引擎”写成优化完成。先交付语义误标修复和可读性诊断，再明确阻塞项；商业授权、云服务或架构大改需要用户决策。

### 8.2 后端执行与可选运行时交付边界

候选 A：Python 服务构造只读请求 → 后台计算任务执行布局/路由 → 返回统一 Scene → 共享校验。计算模块保持可无 GUI 单测；CPU 密集任务须验证线程/GIL 对 UI 的影响，必要时使用受控 Python 子进程，不把“未新增 JS 运行时”写成“绝不使用任何进程”。

候选 B 的独立运行时原型：Python 服务构造最小 JSON → 受控的本地 JS 运行时执行锁定版本 elkjs → 返回纯 JSON → 共享结果校验。若通过，G6/Qt/CLI 共用该执行协议，浏览器不是服务计算的必需依赖。

elkjs 也可在浏览器 JS 环境执行，不能把 Node 当作它唯一的运行方式，参见 [elkjs 官方 Node/Browser 使用说明](https://github.com/kieler/elkjs#usage)。利用已有 QWebEngine 的方案可作有界实验，但须同时证明无 WebEngine 的兼容视图首次打开原始 Excel、业务变化后重新计算、headless CLI 的计算来源；“浏览器先算好、Qt 读缓存”不能覆盖这些场景。若另配后端，两个后端的维护/一致性成本一并计入 ADR，不把浏览器原型直接当最终架构。

当前桌面实现使用 PySide6/Qt，G6 入口依赖可选的 WebEngine 原生组件及其运行支持；候选 A 的准确优势是“不新增独立 JS 运行时”，而不是产品实现为字面意义上的“100% 纯 Python、无外部可执行文件”。现有 Python 依赖声明不等于已完成任何新增运行时的打包验收。

若使用 Node：随产品提供或由受支持的安装流程自动配置受控运行时，教师无需手工安装、修改 PATH。必须由项目配置/发布包定位并核对版本；不能把开发工具自带 Node 当产品依赖。运行库、worker、入口脚本、许可证、来源和哈希纳入依赖清单，禁止运行时在线下载包。

交付验证记录实际发行版本、新增/压缩/安装后体积、升级替换、普通用户启动、中文/空格/只读安装路径、可写数据目录、离线运行及损坏/缺失组件提示。按交付渠道核验签名/安全扫描与权限要求，记录结果及限制；不预设约 50MB，也不推断必然被杀毒拦截。用户已允许评估新增辅助可执行文件，具体版本与随包方式由 E1 ADR 落实；若实际代价改变既有交付方式，按第 16.3 节升级说明。

外部进程用参数数组调用、固定允许的入口、受限消息大小与超时，日志和 JSON 通道分开；Windows 后台助手不弹出多余窗口。拒绝由用户节点文本决定命令/模块路径。引擎只接收 ID、尺寸、连接、标签布局所需最少文本或尺寸，不接收正文证据和 API 配置。

用进程/worker 隔离长任务；取消不只是忽略 Python Future，而应结束或废弃对应计算并阻止迟到结果覆盖。工作台关闭后释放本任务创建的进程，不终止其他应用同名进程。

### 8.3 混合布局与独立路由的验证要求

“ELK 支持正交路由”不等于“传入任意固定节点后，只重新路由所有弱关系”一定可行；同样，“实现 A*”不等于完成多边路由。S1b 对适用候选必须验证：

- 不参与主链 rank 的边怎样仍影响邻近，且如何取得其最终路由。
- 锁定节点、子框打包后，能否保留节点并独立重算边；不能在适配器中忽略引擎移动。
- 若采用自研/补充路由器，对比有界正交栅格 A* 与稀疏正交可见图搜索：膨胀障碍、合法端口、转折点、转折/交叉/共线拥挤代价、有限重路由与最终验证。可在明显不适用时给出反例后排除某种表示，不要求建设两套路由产品。
- 栅格节点量由画布面积、分辨率、障碍和走廊决定，不能只按业务节点数估计。记录搜索节点数、路径段数、峰值内存、扩展上限与超时；缩小栅格间距前评估增长，粗栅格找不到窄通道也不等于真实几何无解。
- 补充算法不自动获得“任意图总能成功”的承诺，失败必须进入第 3.3 节。

### 8.4 有限迭代与重复性

选定后端的每次生产请求最多比较 3 个整体布局候选（初始目标，可在 E1 以证据调整并版本化；不是要求每次都运行 A/B/Dagre）。候选之间可调整通道宽度/目标宽度/标签密度，但不改变业务图。只接受硬违规更少或同级目标改善的候选，达到预算后返回最佳合法结果或明确失败。

禁止形成 Python→JS 渲染→尺寸回传→Python 重排的无限循环。真实文字尺寸发现溢出时，先使用规格内的换行/省略或有限档位；需要换档应作为新 request，有次数上限和明确诊断。

固定输入排序、随机种子、引擎版本和参数；同输入重复结果允许规定的浮点容差，不允许随机漂移。结果缓存按 layout_fingerprint，而不是仅按 graph_id。

## 9. 端口、避障与关系路由

### 9.1 端口分配

- 节点四边支持多个端口，按邻居相对方向和边排序分配，不能所有边连接同一个边中心。
- 端口 ID 绑定 edge view ID 与端点角色；同端点多类型关系独立分道。
- 顺序尽量与另一端空间顺序一致，降低节点附近交叉；主链入口/出口可优先保留。
- 端口间距不足时允许调整卡片档位或分配其他侧，不能将端口摆到标题/徽标内部。
- 对称边、自环、双向两条不同事实均有独立路径；相同业务关系的重复记录仍由业务层处理，布局不擅自合并。

### 9.2 障碍与通道

卡片、标题、不可穿越的子框、固定注释以及预留操作区是障碍。以边宽、箭头和安全距离膨胀障碍后求解。允许接触本边源/目标的指定端口，但不允许经过本边端点卡片的其他内部区域。

同一通道多条边要有可辨间隔。共起点的极短汇合段可记录为端点区例外；长段完全重合不能作为合格结果。自动 edge bundling 首期关闭，除非用户显式进入带成员清单的汇总模式。

仅把卡片设为静态障碍的逐边 A*，可能让多条边反复选择同一条最短走廊，因此不能作为完整路由方案。路由器还需端口排序、已占通道/共享长度代价、可辨分道、交叉及标签预留；通过固定处理顺序和有上限的重路由消减拥塞，最终检查全部边，而非只检查最后一条。若没有合法通道，应扩大可用空间、换有限候选或报告失败，不能以“已避开卡片”掩盖无法区分的共线。

可调初始规格：卡片至边净距 12、平行边净距 8–12、端口间距 12、标签安全距 4、圆角半径 6，单位为逻辑坐标。实际最小值必须结合描边和字体实测，E1 后集中在 metrics profile，不散落两端代码。

### 9.3 路由与标签联动

先分配边通道及候选标签槽，再验证标签；必要时只调整相关路由或在预算内换候选布局。不是所有标签都强制放在几何中点。优先长直段、避开交叉点、箭头、端口和其他标签；过短边的完整标签放入悬停/固定详情。

实际绘制的圆角/贝塞尔段必须再次检测障碍，不能只验证未倒角折线。箭头三角形与点击命中区域也计入可操作性检查。

### 9.4 跨框、环和分组边界

教材模式按最低共同作用域分段路由，经显式 portal 出入边界；跨组语义仍然保留原 relation ID。循环回边可使用单独外侧通道，不与普通推导关系共用“循环”标识。不可仅因边向左画就判断为知识循环。

自环有独立回路和标签槽。汇总端点上的边必须能展开到真实节点，不将汇总框作为业务源/目标写回。

### 9.5 拖拽中的路径

拖拽过程可显示暂态预览，但需要标识其未验证状态，不持久化。结束后只对受影响节点、邻边、通道与标签重算，检查合法后原子提交；失败恢复拖拽前的场景和 pin 状态，不能只恢复节点而留下错误边。

## 10. 卡片、标签、图例与视觉密度

### 10.1 卡片规格

首轮对比继续使用当前 250×86 的卡片，避免仅缩小节点获得虚假的布局改善。可以另测紧凑/长标题档位，但报告必须说明尺寸差异。

标题区与状态徽标分开预留。建议标题最多两行，类型与简短状态放入底部元信息行；完整正文、原名、审核理由和证据进入详情。不得用固定“12 个字符”替代实际可用宽度，长中文、英文、数字、组合字符和缺字字体均需测试。

固定尺寸/有限档位由共享 metrics 管理，适配器在约定矩形中换行、省略，不能擅自扩卡。悬停或键盘聚焦可以看到完整标题。字体缩小有最低可读字号，不通过无限缩小掩盖溢出。

### 10.2 三档信息密度

| 档位 | 默认表达 | 不得发生 |
| --- | --- | --- |
| 总览 | 名称、类型/状态简记、全部展开范围内的边；普通边标签按空间择优显示 | 隐藏所有边后宣称清晰；无法区分未决关系 |
| 邻域追踪 | 当前节点及直接邻居突出，相关关系类型/方向清楚；其余淡化 | 悬停就重排，或无提示移除远处事实 |
| 单边审查 | 两端、完整类型、审核状态、证据和原始关系文本 | 只靠颜色找端点；自动接受当前关系 |

缩放可以影响标签密度，但不能改变业务或自动改变布局范围。初始阈值在 zoom=0.55/0.9 附近评估，使用滞回区防止标签反复闪烁；具体阈值依 DPI/字体验证，不能当普适常数。

自动缩放密度与滞回是 G6 首期丰富交互要求。Qt 可以采用明确的固定密度档位和共享详情入口，不必复制同一动态控制器；同一密度配置下的标签几何、抑制原因及事实覆盖仍须一致，见第 13.2 节。

### 10.3 标签优先级

固定选中边最高，其次当前焦点邻边与类型未决/需修订/需专家复核提示，再是主链类型和其他边。普通 pending 不逐边重复长状态文本；通过样式/图例和详情保留状态。审核密度模式可以显式要求更多状态，但仍需避让。

标签的可见/抑制原因写入显示账本。选择一条被抑制标签的边后，至少在固定详情完整展示，不强行把长牌插入拥挤路径。颜色不是唯一信息通道：未决有问号/文字、选中有轮廓/端点标记、状态有文字。

### 10.4 图例与辅助功能

图例由当前实际使用的关系/状态注册表生成，删除“所有包含关系由章节大框表达”这类在关系模式或未决关系上不成立的绝对描述。明确区分业务线、未决线、纯布局调试线；生产默认不显示调试辅助线，0 条时不提供误导按钮。

图谱区域应可键盘定位，关系清单提供等价的逐条访问；焦点样式与鼠标悬停区分。详情区在小窗口可抽屉展开，不能因屏幕较小完全失去证据操作入口。动画尊重减少动态效果设置，不依赖持续运动理解方向。

## 11. 知识点中心交互与状态转换

### 11.1 核心操作契约

下表定义业务效果和稳定性。G6 实现完整探索交互；Qt 的基础任务可由原生画布配合共同的工作台控件/列表完成，悬停、动画、分组拖动按第 13.2 节分级，不要求相同 UI 形态。

| 用户动作 | 必须发生 | 不得发生 |
| --- | --- | --- |
| 打开文档 | 展示模式、范围、待确认数量；无旧状态时进入关系总览 | 任意选一个节点作为权威中心；悄悄恢复其他文档坐标 |
| 悬停节点 | 临时突出节点及邻边，离开恢复 | 保存布局、改业务、重排全图 |
| 单击节点 | 固定选中，突出一跳邻居；详情展示入边/出边/对称/未决关系及教材上下文 | 因选择就删除无关节点或切换作用域 |
| 单击关系 | 明确标记源/目标，突出完整路径；关系清单定位对应 relation ID | 只高亮一个模糊线段；误定位同端点另一类型边 |
| “只看关联” | 显式进入 neighborhood，默认一跳，可扩展二跳 | 自动无限追踪整图；把边界外关系当不存在 |
| “展开更多” | 显示将增加的节点/边数量；稳定插入或局部重排 | 高连接度节点一次展开造成主线程长时间冻结 |
| 搜索知识点 | 按名称/别名或 ID 定位业务对象，显示其出现位置 | 仅在屏幕可见卡片中搜索；修改候选身份 |
| “定位教材” | 基于用户选择的 occurrence/evidence 跳转页码或切教材模式 | 猜一个归属当主归属；为缺证据节点伪造页码 |
| “返回总览” | 恢复之前相机、展开/选择状态 | 强制 fit 全图造成阅读位置丢失 |
| “适配范围” | 只改变相机，适配当前选定范围 | 修改节点或业务 |
| “重新布局” | 对明确范围提交新请求，保留锁定；可撤销到同版本前一场景 | 在未告知时清除用户锁定 |
| “清除锁定并重排” | 明确说明影响当前模式的锁定位置 | 清空其他模式/文档位置或全部历史 |
| 审核节点/关系 | 通过既有 Session 命令和 expected_revision | 布局器直接改状态；顺带审核邻居 |
| 筛选 | 显示当前条件和隐藏计数；一键清除 | 同步改变正式导出 profile |
| “隐藏此卡片” | 仅改变当前视图并记录隐藏原因，可恢复 | 归档实体、拒绝关系、删归属 |
| “管理教材归属” | 展示候选归属/出现，明确目标后使用业务命令 | 暗取第一条归属或称为没有依据的“本小节” |
| “归档知识点” | 预览当前审查文档内的影响，确认后逻辑归档 | 物理删除、跨项目删除或与隐藏混为一谈 |

### 11.2 邻域定义与边界

默认一跳发现按无向邻接找相关节点，方向仍按真实箭头显示；用户可切换“前驱/后继/全部”，对称与未决单独标记。未决边可被纳入发现，但不称为已证实的前置链。

邻域包含选定可见节点之间满足当前条件的关系，不仅是以中心为起点的边；边界外存在的关系显示数量和展开入口。二跳仍保留原业务关系，不生成“间接关系”新边。

搜索到被过滤/折叠对象时，应说明原因并提供显式临时展开，不静默撤销用户筛选。纯悬停不改变这些条件。

### 11.3 布局稳定与视图历史

1. 相机、悬停、普通选择及标签强调不触发布局。
2. 仅样式发生变化时复用坐标与路径；若状态改变使可见集合/顺序约束改变，生成新请求，采用原坐标热启动和局部修正。
3. 增删一条边优先保持节点位置，只重路由相关通道；不能保证时说明布局更新范围。
4. 节点新增只影响当前连通块及必要的相邻打包区域；未受影响块保持相对位置。
5. 模式切换有独立状态。用 node_id/relation_id 恢复选择；旧 view_id 不直接套到新模式。
6. 视图历史与业务撤销分开。布局撤销不得撤销审核，业务撤销后重新检查视图身份，不恢复失效对象。

### 11.4 锁定与拖动边界

关系模式允许锁定节点或整个视觉分组；组移动需整体平移成员、端口、路径和标签。教材模式拖动不能跨出合法父内容区；改变教材归属是独立业务命令，不能靠拖拽位置暗示已完成。

G6 承担高级拖动体验；Qt 首期不强制支持组/框拖动，但必须正确消费已有锁定和合法结果，可通过共同控件执行保留锁定重排/清锁。未实现的拖动须禁用并解释替代路径；若启用任何一种拖动，就必须完整遵守第 9.5 节提交/回退规则。

锁定分为用户明确设置的 pin 和算法热启动坐标。自动保存全部节点位置不等于用户锁定全部节点。两类输入必须分开，否则任何增量布局都会被错误地约束住。

### 11.5 节点操作权责、确认与恢复

不使用一个含混的“删除”按钮，再让教师临时猜测删除的是卡片、归属还是知识实体。三个入口预先分开：

| 入口 | 对象与影响 | 确认、撤销与默认边界 |
| --- | --- | --- |
| 隐藏此卡片 | 当前模式的明确 view_id；邻边依覆盖账本转为有原因的隐藏，不改业务 DTO | 视图撤销/显示隐藏对象可恢复；关系模式隐藏唯一卡不等于归档节点，教材模式默认只隐藏本处引用 |
| 管理教材归属 | 显式选中的 membership_id；显示章节路径、出现及状态；无归属时展示待确认状态/既有创建入口 | 关系模式详情可直接进入，不强迫先切教材模式；移除归属先展示业务影响，通过既有 Session/审核机制处理，保留历史，不物理删记录 |
| 归档知识点 | 当前审查文档内的 node_id；关联引用/出现、归属及关系按既有逻辑归档契约处理 | 展示对象名称/ID、受影响引用/出现与关系数量及明细入口；明确二次确认、expected_revision、取消无副作用，支持业务撤销，不删除证据或历史 |

关系模式没有隐含的“当前小节”。即使仅一条归属，也应显示该条具体上下文并由用户明确选择操作，不能把它偷偷写成主归属。多归属移除应预览是否触及已选发布归属或使节点暂无归属，并复用发布预检；不可自动选择替代主归属。

“归档”不是“彻底删除”的别名，也不表示跨其他审查文档/项目清除同名节点。本轮不设计物理删除。当前 UI 若沿用“删除”文案调用逻辑归档，后续实施应按上述名称统一入口、提示、测试及帮助说明；不能仅改提示却改变归档范围。拒绝关系仍是独立审核动作，不与上述三个入口合并。

## 12. 版本、视图状态、迁移与并发

### 12.1 版本域

| 版本 | 当前事实 | 下一轮约定 |
| --- | --- | --- |
| 文档修订 | 文档 16 R3、本文 R2 | 只管理文字，不表示程序 schema |
| 业务 Excel schema | 2 | 本规划默认保持 2；不为坐标变化升级业务协议 |
| projection_schema_version | 1 | 引入模式和 context/aggregate 账本时拟升为 2 |
| layout_version | 4 | 新二维/路由算法拟升为 5；不接受任意 `>=4` 的坐标 |
| geometry specification | 1 | 带端口、路径、标签的场景拟升为 2 |
| view_state_schema_version | 当前无统一完整协议 | 新独立视图状态拟定 2，与 layout_version 分开 |
| engine/config/metrics version | 部分散落 | 精确锁定并进入布局缓存键 |

版本号为本规划预留值，实施前核对分支是否已被占用。新字段只在契约落实时启用，不能先改数字而沿用旧语义。遇到未来不支持的版本，保留原状态并提示，不降级重写其内容。

### 12.2 视图状态唯一仓储

拟定 `ViewStateStore` 作为唯一持久化入口；Desktop 文件为桌面模式权威，浏览器 localStorage 只在独立静态页本地模式中负责保存，不让二者竞争“最新值”。

新状态至少包含：document_id、source identity/fingerprint、view_mode、view_state_schema_version、layout_version、metrics/config 指纹、view_revision、focused_node_id、focused_relation_id、明确教材上下文、filters、collapsed/expanded_groups、explicit_hidden_ids、pins、warm_start_positions、camera、updated_at。

存储键包含 document_id＋view_mode＋尺寸/布局兼容域；renderer 只隔离相机和像素相关偏好。可跨渲染器共享的逻辑 pins 使用同一语义，不再保存两套互不对应的业务位置。

`view_revision` 管理需持久化的用户视图变更；悬停等暂态使用独立 interaction revision，不使所有在途布局失效。布局请求另有 request_id，与回调身份一起校验。

### 12.3 坐标规范

- 新持久化 pins 统一为父内容区相对左上角坐标；关系模式根节点为场景局部坐标。
- G6 中心点仅为绘制适配，Qt 左上角仅为绘制适配；保存前转换成规范坐标。
- 容器移动采用整体位移，不同时给父容器和每个子节点叠加两次。
- 存储显式坐标系标识、父 view ID、尺寸规格，无法解释时拒绝套用。

### 12.4 从旧状态迁移

1. 先读取旧文件，不覆盖；记录原版本、来源和哈希。
2. 只有文档身份、旧实例及旧尺寸均匹配时，才能转换 G6 中心点或 Qt 左上角。
3. 旧文件中全部节点坐标默认只是 warm start，不自动转为 pins。
4. 关系模式知识去重后，多个旧 membership 实例不能随意选一个作为新 pin；使用可解释的初始位置估计或重新布局，不生成主归属选择。
5. 新引擎应对旧 v4 长列重新布局。旧坐标可作为“恢复旧视图”只读参照，不作为新默认布局的硬约束。
6. 旧状态没有可信文档指纹、未来版本或结构不匹配时，忽略其位置但保留原文件及迁移说明。
7. 保存新状态使用原子替换和独立新版本命名/命名空间；回退旧程序不破坏用户旧位置。

### 12.5 Excel 与视图快照边界

当前 v2 工作簿有 `view_state` 表，但本次底稿为空。不能宣称新模式的 camera/filters/routes 只要存在于内存，就已经随 Excel 保存。

首期完整新视图状态采用独立版本化 JSON；业务 v2 包保持既有字段兼容。既有 view_state 可作为旧状态导入来源，不作为新字段的第二权威来源。不要向 schema 2 任意增列后让旧 Reader 静默丢失新字段。

“保存业务审查包”仍保存业务；“导出审查视图快照”可携带独立 view_state/scene JSON 和静态页。界面须明确两者用途。若后续要求单个 Excel 无损携带所有新状态，另立 schema 兼容设计和旧读写门禁，不偷偷扩大本规划业务协议。

### 12.6 回调与持久化 ACK

每个布局请求绑定 document_id、document_revision、request_id、layout_fingerprint。只应用仍对应当前请求的数据；旧页面迟到、切书、切模式、重新分析后均不能覆盖新场景。

Desktop 保存视图状态需返回成功/失败 ACK，检查文档身份与预期 view_revision；浏览器不能仅因 localStorage 写入就显示“桌面位置已保存”。当前 legacy graph_id 与 v2 document_id 的来源必须统一解析/显式映射，不能比较错 ID 后静默丢弃。

写文件失败时保留内存状态和旧文件，提示“尚未保存”并可重试；重复 ACK 不增加视图 revision，不写业务历史。关闭文档时取消在途请求并阻断旧回调。

## 13. G6、Qt、离线导出与既有入口

### 13.1 G6 适配

- 使用当前本地 vendor 验证新自定义边形状/路径，不套用线上 G6 5.x 配置到现有 4.x 代码。
- 接收完整 `EdgeRoute`，注册对应路径绘制和命中逻辑；移除新版路径上的方向猜测、固定 curveOffset 和中点标签回退。
- combo 实际边界可能受内容自动计算影响，必须实测；逻辑框与运行时框不一致时报告，不由 G6 悄悄改变共享场景而 Qt 不知情。
- 选中样式不能把不同关系全部永久改成同一个颜色；退出选择恢复注册表样式。
- 更新窗口尺寸只更新相机/内容区，不无限触发重布局。
- 图标题优先显示教材/当前范围友好名称，原始 doc ID 放详情，避免长 ID 挤占工具栏。

### 13.2 Qt 适配与双端能力分级

- 从同一段序列创建 `QPainterPath`，箭头按末段切向绘制。
- 边项保存 relation_id 并可选中；点击命中区域宽于细线但不遮蔽节点交互，重叠命中时提供候选关系列表。
- 标题、标签、徽标使用同一预留矩形和注册表，完整显示 needs_expert_review，不在 Qt 后缀中遗漏。
- 与 G6 共用模式、范围、过滤与选择上下文。暂时不能支持的交互须显示能力提示，不能默默显示不同关系集合。
- 核心完成门禁要求两个渲染器都具备模式切换、节点/边选中、关联追踪、详情/证据入口及同一逻辑路径；允许 Qt 通过宿主工作台完成任务，不要求复制 G6 全套高级交互。

| 能力 | G6 首期 | Qt 首期最低要求 |
| --- | --- | --- |
| 身份、类型/状态、端点、证据与覆盖账本 | 必需 | 必需；不能退化为只看图或只突出一张卡 |
| 同配置的框、卡片、路径、箭头和标签 | 必需，按共享结果绘制 | 必需；不同像素效果可测量解释，不允许另算业务路径 |
| 模式/范围/筛选、一跳/二跳与边界数量 | 完整探索入口 | 可使用共同工具栏/列表/详情；得到相同配置和业务集合 |
| 节点/边选择、端点强调、关系/证据查看 | 画布与列表联动 | 点击或键盘/列表选择可完成相同审查，命中歧义可消解 |
| 悬停一跳、动态密度滞回、抽屉/过渡效果 | 首期丰富交互；遵守不重排原则 | 非必需；可固定密度、点击追踪及侧栏；完整类型/状态不能因此失去入口 |
| 节点/视觉组/教材框拖动与暂态预览 | 按第 9.5、11.4 节实现并验收 | 高级拖动非必需；未实现时禁用，使用共同重排/清锁入口；启用即执行相同合法性门禁 |
| 已有 pins、合法重排结果、视图/业务撤销分离 | 必需 | 必需；不因不能组拖动就忽略共享锁定或套用错误坐标 |
| 无 WebEngine 首次打开与重新计算 | 不适用该渲染器 | 必需，走已选后端，不依赖曾生成的网页场景缓存 |

能力表是开发与验收的共同边界。高级可选项标注“未提供，已禁用及有替代入口”；基础项缺失必须记失败/未完成，不能借“兼容模式”跳过。验收分别记录共同能力、G6 专属能力与 Qt 可选能力；相同场景对比固定共同密度/范围，不把 G6 的实时悬停状态当作静态几何差异。

### 13.3 离线审查视图导出

本规划拟增加/统一显式“导出当前审查视图”工作流，不把它混入正式 P4 发布。建议包结构：

```text
review_visualization_<run-id>/
  graph_review.html
  scene_layout.json
  view_state.json
  readability_report.json
  visualization_manifest.json
  vendor/g6/...
  vendor/layout/...       # 仅当该包支持浏览器内重新布局
```

manifest 记录业务/投影/布局指纹、版本、文件哈希、筛选/汇总范围和是否降级。默认静态页消费已算好的合法场景，不需要 Python/Node 常驻，也不运行外部模型。

首期静态快照支持平移缩放、选择、邻边强调、详情及当前数据内的筛选；结构性重排/拖动若缺少完整本地路由能力应禁用并说明“返回工作台重排”，不能继续用直线凑数。若提供浏览器离线重排，须另通过同一算法版本、worker、file:// 加载和离线验收，不作为首屏显示的前置条件。

如果导出只包含筛选后子集，应在页头明确写出范围及未包含数量；没有随包提供的数据不能显示为“点击即可完整展开”。相对资源要可解析，中文路径/空格、无网络、无 Qt 桥接均测试。不要让教材原始绝对路径、密钥或任意原始 HTML 注入导出页面。

### 13.4 正式导出与其他入口

`PublishPlanningService` 仍只读业务文档和显式 profile。画布去重、聚类、过滤、折叠、锁定、缩放不得改变 parent/contains、已接受语义关系或主归属选择。新增视图导出文件不替代已有 `review_document_v2.xlsx`。

清点 Desktop 新旧分支、CLI staged-check、HTML exporter 和 Web 原型。可运行入口复用共享场景；当前环境无法启动的 Web 依赖不能为本规划伪报运行验收。不要顺带启动文档 15 的服务器产品阶段。

## 14. 规模、性能、调度与可解释降级

### 14.1 规模不能只有节点数

验收记录 n、m、度数分布、连通块、层深、跨框边、长标题比例、未决比例、可见实例数。多归属视图中业务节点与卡片数分别统计。33 节点/28 边属于基础交互样例，必须可全量查看。

初始自动策略（待 S1/S5 实测锁定）：

| 范围 | 默认策略 |
| --- | --- |
| 不超过 100 张可见卡片且 300 条线 | 尝试完整关系总览；先布局和路由，不提前隐藏边 |
| 超过上述阈值或出现超高连接度 | 提供明确的分组总览/邻域入口，显示总量与当前量；用户可请求完整布局 |
| 局部邻域 | 初始预算 60 卡片/150 边，超过时先显示中心和可解释的展开入口/关系列表，不伪装完整邻域 |
| 1000 节点压力样例 | 必须能打开、检索、分区和追踪局部关系；全量详细标签不是默认承诺 |

所有阈值是配置，不是“用户数据超过这个值就错误”。高连接度中心的关联在列表中仍完整可查；分批显示按明确的状态/稳定顺序并显示剩余数量，不暗称展示部分为全部关系。

### 14.2 性能目标与测量口径

以下是待验证目标：100 节点/约 200 边普通稀疏图首个合法场景冷启动 3 秒内，已布局场景的一跳选择/高亮 p95 不超过 200 毫秒；重计算不得让 UI 主线程持续阻塞。复杂复合图另行记录，不用普通稀疏图时间代替。

记录 CPU、内存、操作系统、Python/Qt/G6/引擎/运行时版本、窗口、DPI、冷/热条件；至少 5 次冷启动和 20 次热交互，报告 p50/p95/max、峰值内存、布局/路由/标签/校验/渲染分段耗时。数据构建、首次进程启动与缓存命中分别计时。

不采用未经本工程实测的“100 节点通常 20ms 内”承诺。只测连通分量或节点坐标不代表完整避障、标签、最终几何校验和渲染成本；A* 的搜索规模也不等于业务节点数。A/B 在同一硬件、输入与质量门禁下分别记录分段数据，Qt 固定密度与 G6 动态效果注明测试配置，不能用一端关闭功能后的时间冒充另一端结果。

初始单请求预算：普通图 5 秒，显式复杂全图 15 秒，均可取消；超时应返回降级提示而不是 UI 卡死。目标与预算不是已测事实；E1 可基于证据修订，但不能在未测机器上宣称性能达标。

### 14.3 调度与缓存

- 求解任务在 worker/受控进程执行，UI 线程只处理快照和绘制。
- 同一文档/模式采用 latest-request-wins，去抖合并结构性变更；业务命令不能被合并丢失。
- 选择/悬停不排队做全图布局，使用邻接索引在已绘制场景上操作。
- 缓存布局结果和连通块结果；缓存 key 必须包含模式、端点实例、尺寸、约束、引擎和配置。
- 内存与磁盘缓存有明确上限、淘汰和用户清理入口；不得递归清理整个 storage 或用户导出目录。

### 14.4 汇总原则

汇总节点和汇总边均是显示对象，携带成员 ID 列表及状态/类型计数，不写入业务 DTO。未经明确展开不能一键接受汇总中的全部关系。汇总边按真实起止分组和类型区分，不把相反方向关系压成一个方向。

折叠教材框时，边可以连接该框的显示代理，但必须保留实际端点和对应 relation ID。内部边被隐藏的数量与跨框边分开统计。标签省略、关系过滤、对象汇总是三种不同机制，界面和报告分开列示。

## 15. 相关语义质量、元数据与安全问题

### 15.1 未决 contains 的业务裁决不在布局器内

为 15 条未决关系提供清楚的列表、两端、原始类型、来源、证据和审核状态。允许用户进入现有关系编辑/审核流程。若目前本体无法表达“集合成员/步骤组成”，应记录本体扩展需求，而不是显示层创造新类型并自动正式发布。

“解释”“应用”及 `印石 prerequisite 砂纸` 等候选关系是否合理，需要教材证据和人工判断。布局可以保留候选方向并标识状态，不通过节点位置暗示已得到学科验证。

### 15.2 教材归属缺失

无 scopes/memberships 是底稿事实。应区分仅选择正文、目录未抽取、目录整合失败、chapter hint 为 unknown 等情况。先排好无归属图，再提供归属确认入口。

查证链路：选择记录与页码范围 → 章节清单/抽取响应 → canonical occurrence → `ReviewDocumentMigrator` → projection issues。只以现有记录诊断，不为此自动再次调用模型。无可用证据时明确“未知”，不创建一个看起来合理的教材章节点。

### 15.3 美术内容仍标注 math/g8/term1

R2 已补充以下证据，区分事实与历史行为推断：

1. `desktop_app.py` 使用 `QLineEdit("math")` 初始化学科，年级/册次默认为 g8/term1；并非必须由用户选择的学科下拉框。
2. `_document_options` 对空输入回退 math/g8/term1，固定 `education_stage="junior_middle_school"`、`grade_band="g7_g9"`，且 `subject_tags=[当前学科或 math, "geometry"]`，没有按本次教材内容区分。仅在 UI 改学科，仍可能留下 geometry 标签与不适用的学段假设。
3. 第 2.1 节匹配记录的 source_id 为 `LOCAL_TEXTBOOK_p13_p18_chapter_scope`，输入已经是 subject=math、grade=g8、term=term1、subject_tags=[math, geometry]，并带上述初中学段；与底稿身份相匹配。
4. 因此错误学科已经进入分析输入，不是单纯导出显示漂移；但这些记录不足以判断用户当时是否改过字段、切书是否沿用，不能归咎于某次用户操作。记录的源文件名还标有“七年级上册”，与 g8 不一致，应作为年级核对线索；仅凭文件名不能确认实际版本或自动改值。本规划统一称“美术篆刻样例”，不沿用审阅意见中未经核实的“八年级”称谓。

WP-G 分两条独立记录：既有样例的只读来源诊断，以及新输入的最小防护。未来实施至少覆盖：

- 换书后明确显示本次来源、学科、年级、册次及学段/标签，标出默认/沿用/用户确认值；提交前提供可见确认，不静默继承上一份教材的学科。
- 排查空值回退；必需字段为空或不一致时要求明确补充/确认，协议允许未知的字段保留未知并诊断，不能静默补为数学。
- 移除与所选学科无关的固定 geometry 标签，以及不随明确年级/声明变化的固定初中学段假设；使用已确认字段和受控映射，无法确定则提示。不是新增一套凭文件名/OCR 猜学科的分类器。
- 对照“界面字段 → `_document_options`/分析提交 → source_record → 规范化节点 → Excel 导出”逐段断言一致；测试美术、数学、切书、空字段及非初中年级。不能只加一个确认弹窗而保留底层固定标签。
- 不存在历史记录时标记不可追溯；有记录时附路径/哈希和具体字段。旧样例继续只读作为失败基线，不在回归夹具中先替换元数据后冒充问题已解决。

已生成 node ID 含旧学科信息，不能批量字符串替换 ID 修复，会破坏关系、出现、历史、Excel 基线和视图引用。若需要重建业务身份或合并数据，单独设计迁移并征得用户确认。该业务迁移不阻塞可视化样例复现和布局优化。

### 15.4 输入与展示安全

节点名称、关系文本、证据及底稿内容均是不可信数据。HTML 模板需安全序列化脚本 JSON，防止 `</script>` 等文本提前结束脚本；详情使用安全文本节点或严格转义，不拼入任意 HTML。布局器不执行文本中的命令/链接。

导出外部使用的诊断报告默认不包含完整教材正文、临时用户路径或密钥。记录布局耗时只需 ID/计数/配置。引擎包、脚本路径和版本来自受控配置，不来自底稿字段。

## 17. 验收指标、样例与测试矩阵

### 17.1 指标的操作性定义

| 指标 | 定义与排除项 |
| --- | --- |
| node_overlap | 非合法包含关系的卡片内部面积相交；同一业务节点不同实例仍分别检查 |
| scope_violation | 教材模式子项越出内容区、覆盖标题、同级框内部相交；不将合法嵌套当重叠 |
| edge_node_intrusion | 最终绘制路径/箭头进入非端点卡片内部；按 edge ID–node view ID 去重计数 |
| edge_crossing | 不同边在非共同端点区发生横向相交；弯折点相切/共端点分别记录，不能都当普通交叉 |
| ambiguous_overlap | 不同边在端点区外有超过阈值的共线/近重合路径，无法单独追踪；记录配对和长度 |
| label_overlap | 可见标签与其他可见标签、卡片标题/操作区、无关边发生遮挡；分别统计 |
| detour_ratio | 路径长度 / 端口间最短直线距离；零距离自环单独统计，不除零 |
| edge_length | 中位数、p95、最大值；按卡片宽度归一以便比较 |
| aspect_penalty | 图面宽高比与实际内容区宽高比的偏离；不能用外框缩放假装改善 |
| displacement | 固定参考点后未受影响节点/连通块的相对位移；排除纯相机平移 |
| coverage | 每条活动业务关系恰有一个可追溯表示，过滤/汇总均有原因/成员 |

路径检测采用线段/矩形精确相交或有误差上界的曲线细分；细分误差初始不超过 0.5 逻辑单位。运行时轮廓容差沿用量级 1–2 逻辑单位，但不能用该容差吞掉明显的穿卡或标签遮字。近重合距离/最短长度由 metrics version 明确，例如距离小于线宽加安全间隔、持续长度超过 20；S1 以实际像素可辨性锁定。

不能只用边包围盒相交判断穿卡：曲线包围盒与卡片相交不一定实际穿卡；同样不能只检查端点。报告应附触发对象 ID 和实际路径段，便于重现。

### 17.4 人工追踪任务

两个常用窗口和两个渲染器均执行以下基础任务。Qt 可通过共同工作台控件、列表、固定详情完成，不要求与 G6 使用相同悬停/抽屉手势；基础任务本身不得省略。记录操作步骤、是否误认端点、是否需手工挪节点；有计时则说明测试者与重复次数，不把单次主观印象称用户研究：

| Q10 | 数据元信息错误与 node ID 耦合 | 输入错误已有记录；防护默认/沿用/空值/固定标签与学段，历史身份不自动迁移 | 需要批量改身份、重抽取或合并数据时 |
| Q11 | 新视图状态无法完整装入现有 Excel | 版本化 sidecar/静态快照明确标注 | 用户要求单 Excel 全状态无损携带时 |
| Q12 | 优化在美术有效但数学/多层教材退化 | 跨学科/拓扑同基线测试，模式隔离，防止针对样例硬编码 | 需要缩减已承诺支持范围时 |

无需用户现在补充算法品牌、参数或精确配色。用户使用方向已足够明确，以上问题先通过代码/样例验证回答；只有产生表中实质性取舍才需要追加决策。
