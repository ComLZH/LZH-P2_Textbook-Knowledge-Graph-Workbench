# 15. P2 Web 服务器版产品边界与分阶段开发规划

更新时间：2026-09-13  
状态：阶段性共识已确认；用于后续方案设计和工程实施审查

桌面核心后续演进：2026-09-13 已形成投影版本 2、布局版本 6 的关系分区、证据顺序、批量 ELK 和共享端点/箭头几何。Web 实施若复用该核心，应消费同一投影与场景契约，不能在前端另算关系端点或把分区框解释为教材/知识包含；实际落点与未覆盖矩阵见[文档 21](21_关系分区与左向右自动布局可读性优化实施完成报告_20260913.md)。

## 1. 本轮共识的核心修正

“面向公众开放的教材知识图谱构建平台”不能充分表达 P2 的差异化价值。该说法仍可能被理解为把教材转换成类似普通思维导图的章节树，没有突出规范知识节点和类型化关系。

P2 Web 的最终目标正式收敛为：

> 建设一个面向公众开放的教材知识关系图谱建设平台：以教材内容结构和原文证据为底图，以规范知识节点和可审查的类型化有向关系为核心，支持教师参与确认，并向 P4 提供可计算、可追溯、可版本化的知识结构，服务后续知识诊断、学习路径和个性化学习。

更短的公开表述可以使用：

> 面向教材的、以知识关系为核心的可审查知识图谱建设平台。

P2 Web 不是“在线 PDF 脑图生成器”。服务器化不会改变 `14_P2项目定位综述与公开介绍稿.md` 中已经确认的产品定位。

## 2. 产品价值中心

P2 Web 的核心交付不是一张图，而是一组能够被审查和计算的数据：

- 经过归一化的知识节点；
- 具有明确方向和语义的类型化关系；
- 关系端点、置信度、来源和审查状态；
- 可以返回教材页码、图片和文本块的证据锚点；
- 教师修改、通过、拒绝和版本变化记录；
- 可继续导入 P4 的正式节点、边和分层映射。

关系包括但不限于：

- `contains`：包含；
- `prerequisite`：前置；
- `progressive`：递进；
- `derives_to`：推导；
- `explains`：解释；
- `applies_to`：应用；
- `represented_by`：表征；
- `equivalent`：等价；
- `parallel`：并列；
- `contrast`：对比。

教材顺序只能作为分析上下文，不能自动升级为前置或递进关系。模型生成的是候选，教师审查和质量门禁决定其能否进入正式图谱。

## 3. 双层数据结构

服务器版本继续保留两层相互连接的数据。

### 3.1 教材内容结构层

```text
教材
  └─ 章节
      └─ 小节
          ├─ 标题
          ├─ 页面
          ├─ 原文与 OCR 文本块
          ├─ 例题、活动和应用材料
          └─ 来源位置
```

作用：保持材料完整性、教材顺序和原文可追溯性。

### 3.2 规范知识关系层

```text
规范知识节点
  ├─ 前置 / 递进 / 推导 → 其他知识节点
  ├─ 解释 / 表征 → 概念或表示方式
  ├─ 应用于 → 方法、题型或实践场景
  └─ 等价 / 并列 / 对比 ─ 相关知识节点
```

作用：形成可供 P4 使用的知识依赖和语义网络。

### 3.3 证据桥梁

每个候选节点和关系尽量关联教材页面、文本块、模型理由和审查状态。Web 端必须支持从节点或关系返回教材原文，也应支持从教材内容查看已经关联的知识对象。

## 4. 部署与开放边界

### 4.1 最终形态

- 最终面向公众开放使用。
- 支持用户注册、登录和独立项目空间。
- 支持多个用户上传不同教材材料。
- 支持平台模型计费和用户自带 API Key。
- 支持管理员控制资源、费用、并发、容量和数据保留。

### 4.2 第一阶段

- 部署在局域网内。
- 仍然从第一天启用账号、项目和数据隔离。
- 初期可以关闭公开注册，由管理员创建账号或发放邀请码。
- 初期使用低并发队列适配配置较低的服务器。
- 局域网版本通过真实多人试用后，再进入公网安全建设。

### 4.3 桌面端与服务器端

现有 P2 Desktop 继续保留。P2 Web 不复制一套抽取算法，而是与桌面端共用 P2 Core：

```text
                         P2 Core
     OCR、抽取、归一化、关系、审查、质量检查、导出
                            │
             ┌──────────────┴──────────────┐
             │                             │
      P2 Desktop                     P2 Web
      PySide6 本地端          Web API＋任务系统＋网页端
```

## 5. 用户、项目与数据隔离

基础所有权结构：

```text
用户
  └─ 项目
      ├─ 教材来源
      ├─ 分析运行
      ├─ 候选节点与关系
      ├─ 证据与质量报告
      ├─ 审查记录
      └─ 导出版本
```

所有业务记录至少关联：

- `user_id`；
- `project_id`；
- `analysis_run_id`；
- 创建时间和修改时间；
- 数据版本；
- 保留策略和删除状态。

第一阶段就建立多租户隔离，不能先使用全局目录，后期再补用户字段。任何查询、下载、审查和导出都必须校验资源所有权。

后续组织协作阶段再扩展组织、成员、角色、共享项目和冲突合并。

## 6. 第三方模型与费用责任

### 6.1 平台统一模型

- 使用服务器管理员配置的模型、地址和 API Key。
- 费用由平台承担。
- 受用户配额、每日页数、模型调用量和平台预算限制。
- 每个任务记录计费来源、模型、调用次数、输入输出量和费用估算。
- 达到预算或配额时不再创建平台付费任务。

### 6.2 用户自带密钥

第一版优先支持单次使用：密钥在创建任务时提交，只在任务执行期间存在，结束后销毁。

后续可以增加加密保存：

- 密钥加密存储；
- 浏览器提交后不再返回明文；
- 日志、错误信息和过程记录全部脱敏；
- 用户可以验证、替换和删除连接；
- 管理员不能从普通后台页面查看明文。

重要规则：

> 用户选择自带密钥后，调用失败不得静默切换到平台密钥。平台计费和用户计费之间的切换必须由用户明确确认。

管理员应能暂停全部平台付费任务，同时允许符合条件的用户自带密钥任务继续运行。

## 7. 存储、保留与容量控制

支持用户选择保留时间，也支持管理员按时间和容量控制服务器占用。但正式数据不采用无提示覆盖。

### 7.1 数据类别

| 数据类别 | 重要程度 | 默认策略 |
| --- | ---: | --- |
| 原始教材文件 | 高 | 到期后软删除，保留短期恢复窗口 |
| 审查底稿、正式图谱和版本记录 | 最高 | 不被普通缓存清理覆盖 |
| 页面渲染图和 OCR 缓存 | 中 | 可重新生成，优先清理 |
| 模型原始响应和过程记录 | 中或低 | 按运行模式和保留时间轮转 |
| 临时导出压缩包 | 较低 | 到期自动清理，可重新生成 |

### 7.2 配额层级

```text
系统绝对上限
  ↓
用户额度或套餐上限
  ↓
项目自定义保留时间与容量
```

用户可以选择比管理员上限更短的保留时间和更小的项目容量，但不能突破管理员设置的绝对上限。重要项目可以标记为禁止自动清理。

### 7.3 自动清理

建议设置可配置的存储高水位和低水位。达到高水位后按以下顺序清理，降到低水位后停止：

1. 过期临时文件；
2. 无引用页面渲染图；
3. 可重新生成的 OCR 缓存；
4. 过期过程记录和旧导出包；
5. 用户允许自动删除且已过期的历史版本；
6. 仍然超限时停止新上传并通知管理员。

只有纯缓存和循环日志允许轮转覆盖。正式底稿、证据和图谱版本不得因为磁盘满而被另一个任务直接覆盖。所有自动清理都要记录原因、对象、释放空间和执行时间。

## 8. 上传、任务与并发控制

所有限制都应进入管理后台配置，而不是写死在业务代码中。

### 8.1 用户级

- 单用户最大运行任务数，初始默认 1；
- 单用户最大排队任务数；
- 每日任务数和每日处理页数；
- 平台模型额度；
- 用户存储额度。

### 8.2 任务级

- 单文件最大体积；
- PDF 最大页数；
- 单次最大分析页数；
- 单任务超时；
- 最大 OCR 页数；
- 最大模型调用次数；
- 单章最大节点和关系规模。

### 8.3 系统级

- 全局最大运行任务数；
- OCR 并发数；
- 模型并发数；
- PDF 渲染并发数；
- 导出并发数；
- 全局队列长度；
- 是否接受新任务；
- 系统维护模式。

低配置服务器的初始值可以是：每用户运行 1 个任务、全局运行 1 个任务、OCR 并发 1、模型并发 1。以后提升服务器配置时，只修改后台参数。

### 8.4 公平队列

公众环境不能让单个用户连续提交大量任务占满队列。采用按用户公平轮转，在同一用户内部保持任务顺序。管理员可以暂停、取消、重试、调整优先级或冻结异常用户任务。

## 9. 任务状态与故障恢复

建议采用以下状态机：

```text
uploaded
  → queued
  → preparing_pages
  → extracting_text
  → extracting_candidates
  → normalizing_nodes
  → consolidating_relations
  → checking_quality
  → awaiting_review
  → exporting
  → completed
```

异常状态包括：

```text
retrying
failed
canceled
paused
```

浏览器请求只创建任务，后台 Worker 执行长耗时工作。任务在主要阶段保存检查点，关闭浏览器或重启服务器后仍能查询和恢复。OCR、模型和导出使用独立资源并发限制。

  └─ 管理后台接口
          │
      任务调度器

  ├─ 全局及分资源并发

## 11. Web 端必须突出关系的产品设计

服务器化不能只把 PDF 上传和脑图展示搬到网页。Web 工作台至少需要：

- 教材结构视图和知识关系视图并存；
- 节点与关系分别审查；
- 关系类型、方向、状态、置信度和证据可见；
- 从关系跳转到两个端点和教材证据；
- 从教材内容查看关联的知识节点与关系；
- 统计缺少证据的关系和未关联知识的内容块；
- 章节嵌套保持教材层级；
- 无环方向性关系左向右，对称关系同层，循环关系显式回边；
- 导出的是结构化节点和边，而不是只有图片或脑图文件。

平台后续评价指标也不能只统计“生成了多少节点”，还应观察：

- 有效关系覆盖率；
- 不同关系类型的教师通过率；
- 关系证据完整率；
- 关系端点有效率；
- 模型重复运行的关系稳定性；
- 从候选到正式图谱的修改比例；
- P4 导入和图计算可用性。

## 12. 管理后台范围

后台至少提供：

| 配置或视图 | 作用 |
| --- | --- |
| 是否开放注册 | 局域网与公网切换 |
| 用户、角色和项目 | 隔离与权限管理 |
| 单文件体积和 PDF 页数 | 控制上传规模 |
| 单任务分析页数 | 控制 OCR 与模型成本 |
| 用户运行和排队任务数 | 防止占用队列 |
| 全局及分资源并发 | 适配服务器配置 |
| 用户和项目存储额度 | 控制容量 |
| 数据保留天数 | 生命周期管理 |
| 存储高/低水位 | 自动清理 |
| 平台模型预算 | 费用保护 |
| 是否允许自带密钥 | 模型策略开关 |
| 任务队列和 Worker 状态 | 运行维护 |
| 模型用量、失败率和耗时 | 成本与稳定性 |
| 清理、删除和审查日志 | 审计追踪 |
| 维护模式 | 暂停新任务 |

## 13. 分阶段开发规划

### 阶段 0：服务器版产品与契约冻结

- 确认本文产品边界。
- 冻结用户、项目、任务、节点、关系、证据、版本和导出契约。
- 明确平台密钥、自带密钥和费用责任。
- 明确保留、容量、回收和自动清理规则。
- 输出数据库、API、任务状态和管理参数设计。

验收：所有后续模块使用同一份关系中心产品定义，不把 Web 版本描述成普通脑图服务。

### 阶段 1：共享 P2 Core

- 保留 P2 Desktop。
- 将剩余 Qt 依赖从业务逻辑中剥离。
- 统一无界面的分析、关系、审查、质量和导出接口。
- 用文件标识和存储接口替代业务层绝对路径。
- 为长任务增加检查点和幂等标识。

验收：不启动桌面窗口即可完成输入、候选关系、审查、质量检查和导出；桌面端结果和测试不回归。

### 阶段 2：多租户数据库

- 建立用户、项目、教材、运行、节点、关系、证据、审查事件、质量和导出表。
- 所有读写强制验证所有权。
- 以数据库作为服务器版事实来源，Excel 保留为交换格式。
- 增加版本号和并发修改检测。

验收：用户之间严格隔离；服务器重启后状态可恢复；关系及证据可追溯。

### 阶段 3：文件存储与生命周期

- 分类保存教材、页面、OCR、过程记录和导出物。
- 实现用户、项目和系统容量统计。
- 实现保留时间、软删除、重要项目锁定和自动清理。
- 增加文件哈希去重与无引用文件检查。

验收：容量超限不会覆盖正式关系图谱；缓存可安全重建；清理过程有审计。

### 阶段 4：异步任务和公平队列

- 实现任务状态机和后台 Worker。
- 实现每用户、全局和分资源并发限制。
- 实现公平轮转、取消、暂停、超时、重试和恢复。
- 向网页提供当前阶段和排队信息。

验收：全局并发为 1 时稳定串行；修改参数后可扩展并发；浏览器关闭和服务器重启不丢任务。

### 阶段 5：认证、密钥和费用保护

- 建立注册、登录、密码恢复和会话安全。
- 实现平台统一模型配置与额度。
- 实现用户自带密钥单次使用，后续扩展加密保存。
- 记录每个任务的费用责任和模型用量。
- 阻止密钥泄露和未经确认的计费模式切换。

验收：平台密钥不可由浏览器读取；任务计费来源明确；额度耗尽后停止平台费用。

### 阶段 6：Web API

- 实现项目、教材、任务、节点、关系、证据、质量、图谱和导出接口。
- 实现分页、筛选、批量审查、错误码和幂等请求。
- 实现管理后台接口。

验收：完整关系图谱建设流程可以只通过 API 完成；重复请求不重复创建任务或计费。

### 阶段 7：关系中心 Web 工作台

- 注册登录、项目和教材管理。
- PDF/图片上传、预览、翻页、缩放和证据定位。
- 分析参数、计费来源、排队和进度。
- 教材结构与知识关系双视图。
- G6 类型化关系、关系详情和教师审查。
- 节点、关系、证据和质量表格。
- 自动保存、历史恢复和导出。

验收里程碑：用户上传 PDF 后关闭网页，服务器仍能排队完成分析；用户重新登录后能继续审查类型化关系、查看证据并导出结构化节点与边。

### 阶段 8：管理后台

- 管理用户、项目、注册方式和角色。
- 动态配置页数、大小、配额、保留时间和并发。
- 查看队列、Worker、磁盘、模型用量、失败率和清理记录。
- 支持维护模式和暂停平台付费任务。

验收：主要运行参数无需修改代码或手工编辑配置文件。

### 阶段 9：局域网多人试运行

- 管理员账号或邀请码进入。
- 使用真实但获得授权的教材样例。
- 验证关系审查、任务排队、数据隔离、恢复、容量和服务器压力。
- 收集教师对节点粒度、关系类型和证据联动的反馈。

验收：少量用户连续使用后无数据串线、任务丢失和不可恢复的正式数据删除。

### 阶段 10：公网安全与公开测试

- HTTPS、邮箱验证或邀请码、验证码和频率限制。
- 恶意文件、超大页面和解析资源攻击防护。
- 平台额度、异常费用和滥用监控。
- 隐私政策、用户协议、版权提示和彻底删除机制。
- 备份、监控、告警、压力测试、发布和回滚。

验收：通过安全、隔离、恢复、容量、成本和并发测试后，以有限额度进入公网测试。

### 阶段 11：配额计费与组织协作

- 用户套餐和平台模型额度。
- 组织、成员、角色和共享项目。
- 多教师审查、意见、版本对比和冲突合并。
- P2 正式图谱向 P4 在线发布、版本选择和回滚。

该阶段不阻塞局域网 MVP 和早期公网测试。

## 15. 已确认实施原则

1. 产品名称和目标必须突出“知识关系”，不能退化为教材脑图生成器。
2. 第一阶段虽在局域网部署，但从一开始建立账号、项目和数据隔离。
3. 保留桌面端，Web 端与其共享 P2 Core。
4. 平台统一承担模型费用，同时支持用户自带 API Key。
5. 自带密钥失败时不静默切换到平台密钥。
6. 初期每用户最多运行 1 个任务，全局并发和各资源并发由管理员动态配置。
7. 队列采用用户公平轮转，低配置服务器可以完全串行处理。
8. 用户可以在管理员上限内选择数据保留时间和项目容量。
9. 缓存和循环日志可以轮转；正式底稿、证据和图谱版本不直接覆盖。
10. Web 端必须同时呈现教材结构、规范节点、类型化关系和证据，不以一张脑图作为最终交付。
11. 关系质量、证据完整性和 P4 可用性是平台核心指标。
12. 局域网多人试运行通过后，再进入公网安全、费用保护和组织协作阶段。

## 16. 当前非目标

- 本规划不意味着已经开始实现服务器版。
- 第一阶段不实现复杂商业计费和多人冲突合并。
- 不因服务器化改变 P2→P4 正式图谱契约。
- 不把教材顺序自动转换为已通过知识依赖。
- 不让大模型候选绕过教师审查和质量门禁。
- 不在浏览器或普通日志中暴露平台或用户密钥。

本文是后续数据库、API、任务系统、Web 工作台和部署方案的上位依据。进入工程实施前，应先依据阶段 0 继续细化数据表、任务状态、接口、存储策略和管理后台字段。
