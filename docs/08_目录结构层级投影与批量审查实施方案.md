# 08. 目录结构层级投影与批量审查实施方案

更新时间：2026-08-22  
状态：方案已由用户审查通过，工程实现与真实链路验收完成

## 1. 问题背景

`textbook/目录页构建测试.pdf` 包含 3 页教材目录。人工可明确识别 6 个章、19 个节以及 19 条“章包含节”的结构关系。

2026-08-22 的审查底稿同样生成了 25 个 `container` 节点、19 条 `contains` 和 4 条 `progressive`，说明主要目录内容已经抽取。但是 25 个节点的 `candidate_parent_node_id` 全为空。现有可视化只依据 `parent_node_id` 建立容器嵌套，同时隐藏 `contains` 连线，因此最终载荷成为 25 个顶层章节容器、0 个普通节点和 4 条可见关系。

该问题属于“关系数据与层级视图之间缺少统一投影”，不是目录 OCR 或首轮模型完全漏抽。

## 2. 已确认原则

1. 节点候选与局部关系线索继续独立抽取，不要求首轮节点提前知道最终父级。
2. 归一化和关系整合完成后，`contains` 是层级事实的权威来源。
3. `candidate_parent_node_id` / `FormalNodeDTO.parent_node_id` 是兼容现有导出和视图的层级投影，必须由无歧义 `contains` 同步得到，不能成为第二套互相冲突的事实来源。
4. 候选 `contains` 即使仍为 `pending`，也必须在候选图中通过空间嵌套正确显示。
5. 教师确认前，正确显示不等于正式通过；目录结构保留待审状态和证据。
6. 教师可以“一键通过当前章节结构”或“一键通过全部无歧义目录结构”。
7. 批量通过是原子结构操作：同时通过结构节点及其 `contains`，不顺带通过 `progressive`、`prerequisite` 等语义关系。
8. 一个子节点存在多个候选父级、端点缺失、循环或 OCR/编号冲突时，不纳入自动批量通过，继续人工处理。
9. `container` 只表示结构容器，不再直接等同于“章”。结构角色至少区分 `chapter`、`section`、`subsection`。
10. 目录先后顺序只用于 `order_index` / 布局顺序，不能单独证明 `progressive` 等知识语义关系。
11. “阅读与思考”“观察与猜想”“综合与实践”等栏目可作为附属内容保留，但不默认成为核心知识点，也不进入知识主干关系。

## 3. 目标数据流

```text
页面证据 / OCR
-> 独立节点候选 + 局部关系线索
-> 规范节点与候选关系
-> contains 层级解析与冲突检查
-> 候选层级投影
   -> parent_node_id
   -> structural_role
   -> order_index
-> 候选图正确嵌套（pending 样式）
-> 教师按章或全局批量确认结构
-> 质量门禁
-> 正式图谱与 layer_mapping
```

## 4. 层级解析规则

### 4.1 权威来源

层级解析同时读取：

- 节点已有 `candidate_parent_node_id`；
- 候选关系中的 `contains`；
- 关系审核状态和端点有效性。

若两者一致，保留一个父级。若只有一条无歧义 `contains`，由它生成父级投影。若同一子节点出现不同父级，则记录冲突，不静默选择。

### 4.2 结构角色

- 无父级且存在结构子节点：`chapter`（当前 P2 范围内的顶层结构容器）。
- 有父级且自身仍包含结构子节点：`section` 或 `subsection`，按深度区分。
- 有父级、类型为 `container` 且没有结构子节点：`section` / `subsection` 叶子结构。
- 非 `container`：保持知识节点类型，并挂入最近结构父级。

结构角色是候选视图和分层映射属性，不改变 P4 当前节点类型枚举。

### 4.3 顺序

目录编号、页面阅读顺序和关系出现顺序只形成结构排序。章或节之间不能仅因相邻而自动生成 `progressive`。

## 5. 审查行为

候选视图必须同时表达：

- 父子空间嵌套；
- 节点待审/通过/退回状态；
- `contains` 的待审/通过状态；
- 冲突节点与未挂载节点。

批量操作：

1. **通过当前章节结构**：通过当前章、其无歧义结构后代以及对应 `contains`。
2. **通过全部目录结构**：通过当前底稿全部无歧义结构节点及对应 `contains`。

批量操作不接受非结构关系，不处理有多个父级、循环或缺失端点的结构。

## 6. 正式导出和质量门禁

正式导出仍只包含 `accepted` 节点和关系，但必须增加以下门禁：

- 已通过结构子节点的父级未通过或不存在：错误，阻止正式导出。
- 已通过结构节点缺少已通过的 `contains`，且其候选层级表明它不是顶层：错误。
- 同一已通过子节点存在多个已通过父级：错误。
- `contains` 形成循环：错误。
- 候选 `contains` 待审：保留明确警告，不再静默跳过。
- 孤立 `container` 不再一律跳过；只有确认的真正顶层结构可以无父级。

`layer_mapping.json` 必须使用同一层级解析结果，不能因为父级投影缺失把“18.5 分式方程”之类节节点重新解释为章。

## 7. 目录页验收基线

冻结输入：`textbook/目录页构建测试.pdf`。

最小验收：

1. 识别 6 个章和 19 个节。
2. 候选层存在 19 条无歧义 `contains`。
3. 候选图显示 6 个顶层章容器和 19 个嵌套节结构，而不是 25 个顶层容器。
4. 候选 `contains` 保持待审，但不影响正确嵌套。
5. “通过全部目录结构”后，25 个结构节点和 19 条 `contains` 同时进入 `accepted`。
6. 非结构语义关系不会被批量接受。
7. 正式图谱包含 25 个节点和 19 条层级边。
8. 分层映射包含 6 个章节点、19 个节/知识结构节点和 19 条层级边。
9. 任意单独接受一个节而不接受父章时，质量门禁阻止正式导出并给出明确错误。
10. PDF 来源路径、页码、OCR 块和关系证据可追溯。

## 8. 实施顺序

1. 增加统一层级解析/投影工具和冲突对象。
2. 在分阶段底稿转换、工作簿构建、布局、G6 payload 和分层映射中复用同一解析结果。
3. 增加结构角色和候选嵌套显示。
4. 在无界面审查会话中增加当前章/全部目录结构批量通过。
5. 桌面工作台接入对应操作和结果提示。
6. 增加正式导出依赖检查和质量错误。
7. 增加目录页离线回归、第三方 API 真链路和可视化截图验收。
8. 将最终测试数字、API 调用和产物事实回填到本文件及 `07_实施结果与验证记录.md`。

## 9. 实施与验收结果

以上 8 个实施步骤均已完成：

- 新增统一层级投影，候选 `contains` 可同步兼容父级字段；正式导出按已通过关系重新投影，不会把待审结构提前写入正式图谱。
- 章节布局、桌面回退视图、G6 payload、正式工作簿、质量检查和 P4 分层映射共享同一层级事实。
- G6 根 combo 不再输出空 `parentId`，首次加载使用 `graph.data()`/`graph.render()`，真实浏览器中成功注册 6 个 combo。
- 叶级 `container` 作为节卡片进入章 combo；`contains` 继续通过空间嵌套表达。2026-08-23 后续确认：结构节点之间真实存在的 `progressive`、`prerequisite` 等非层级关系必须进入图谱画布，不得因端点属于结构节点而隐藏，具体见 `10_双视图关系一致性与日期导出实施方案.md`。
- `WorkbenchReviewSession` 已支持“通过当前章节结构”和“通过全部目录结构”，多父级、循环和缺失端点不进入批量通过。
- 已通过节缺少已通过父章或 `contains` 时，质量检查返回错误并阻止正式导出。
- `staged-check --remote` 现在同时生成待审底稿、质量报告、可直接打开的 G6 HTML 及本地 vendor 资源。

自动化测试为 38 项通过。真实三页目录测试得到 25 个结构节点、19 条 `contains`、6 个章 combo、19 个节节点、0 个层级冲突和 0 个未解析关系线索；运行清单为 7 次文本调用、0 次图片调用、约 49425 个输入字符。

隔离的一键通过模拟得到 25 个已通过节点和 19 条已通过 `contains`，质量检查 0 错误；正式图谱为 25 节点/19 层级边，分层映射为 6 个章、19 个知识结构节点和 19 条层级边。6 条非结构模型推断保留 `needs_expert_review`，未被批量通过。
