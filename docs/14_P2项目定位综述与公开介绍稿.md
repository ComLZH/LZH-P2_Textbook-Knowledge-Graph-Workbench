实现演进：桌面版当前默认以知识点关系探索为入口，采用左向右布局、教材证据步骤顺序、单层关系分区和完整端点/箭头保护；教材章节嵌套保留在“教材定位”模式。该表现层演进不改变本文的产品定位，实际能力与限制见[文档 21](21_关系分区与左向右自动布局可读性优化实施完成报告_20260913.md)。

## 1. 项目名称与核心定位

项目名称：**LZH-P2 教材知识图谱本地工作台**

一句话定位：

> P2 不是普通的 PDF 脑图生成器，而是一个以教材结构为底图、以规范知识点为核心、以类型化语义关系为价值、以证据追溯和教师审查为保障的知识图谱建设工具。

P2 面向教材知识结构的建设阶段。它负责把 PDF、图片及结构化教材材料转化为可审查、可追溯、可质量校验，并可继续交给 P4 使用的知识节点与关系图谱。

## 2. 为什么还需要 P2

以思维导图工具和大模型自动脑图服务为代表的现有产品，已经能够把一份教材或课程资料整理成层次清晰的内容结构。它们往往擅长完整保留材料中的章节、标题、段落和出现顺序，适合阅读导航、内容概览与复习。

但“完整整理了一份教材”并不等于“建立了可以参与计算的知识图谱”。

教材目录通常只能说明内容如何编排，不能直接回答以下问题：

- 哪些内容是稳定、可复用的知识单元？
- 两个知识点之间是包含、前置、递进，还是推导关系？
- 一个公式、表征、题型或应用分别依赖哪些概念和方法？
- 教材先讲 A 后讲 B，是否真的意味着 A 是 B 的前置知识？
- 哪些关系来自教材明确表达，哪些只是模型推断，哪些仍需要教师确认？

这些问题正是 P2 存在的必要性。

## 3. 教材脑图与 P2 知识图谱的差异

| 维度 | 教材脑图或内容图 | P2 知识图谱 |
| --- | --- | --- |
| 核心目标 | 内容整理和阅读导航 | 知识结构建模和关系审查 |
| 主要结构 | 教材→章→节→标题→内容 | 规范知识节点＋类型化关系 |
| 排序依据 | 教材出现顺序 | 教材层级＋知识语义与依赖 |
| 内容粒度 | 可以事无巨细地保留 | 控制为可教学、可诊断、可复用的知识单元 |
| 主要关系 | 以父子层级为主 | 包含、前置、递进、推导、解释、应用、表征、等价、并列、对比 |
| 事实保障 | 内容与原文相邻 | 原文证据、模型理由、审查状态和质量检查 |
| 后续用途 | 浏览、复习和内容概览 | 知识诊断、学习路径、题目挂载和个性化学习的结构基础 |

两者不是相互排斥的替代关系。P2 应当吸收脑图工具在内容完整性和教材顺序表达方面的优势，同时避免把所有标题、例题编号和活动名称都无差别地升级为正式知识点。

## 4. P2 的双层结构

P2 的理想结构由“教材内容结构”和“规范知识关系”两层组成。

### 4.1 教材内容结构层

```text
教材
  └─ 章节
      └─ 小节
          ├─ 标题
          ├─ 定义或性质原文
          ├─ 例题与练习
          ├─ 阅读、活动与应用材料
          └─ 页码、图片和 OCR 文本块
```

这一层强调：

- 尽可能覆盖原教材内容；
- 保留书、章、节和页面顺序；
- 记录 PDF 页码、图片及文本块位置；
- 方便教师检查遗漏和返回原文复核。

### 4.2 规范知识关系层

```text
三角形的概念
  ├─ 前置 → 三角形的有关线段
  ├─ 递进 → 三角形的内角与外角
  └─ 应用于 → 综合与实践
```

这一层强调：

- 将教材表述归一化为稳定知识节点；
- 区分概念、性质、规则、方法、表征、题型和应用；
- 使用具有明确含义的关系连接节点；
- 保留方向、置信度、证据和审查状态；
- 为下游图计算和个性化学习提供结构化输入。

### 4.3 证据桥梁

两层之间通过证据锚点连接：

```text
教材第 12 页的某段文字
          ↓ 证据支持
“三角形的内角和”知识节点
          ↓ prerequisite / applies_to
其他规范知识节点
```

知识节点因此不只是一个模型生成的名称，而是能够返回教材原页、原文和判断依据的待审查对象。

## 5. 顺序与关系不能混为一谈

教材顺序和知识依赖属于两个不同维度：

- **教材顺序**反映编写者如何组织内容，适合按章、节和页面从上到下展示。
- **知识关系方向**反映知识点之间的前置、递进、推导、解释或应用关系，适合使用有向边表达。

教材中 A 出现在 B 之前，可以成为判断关系的上下文，但不能单独证明 A 是 B 的前置知识。P2 会保留这种候选关系的来源、置信度和审查状态，由教师决定它是否能够进入正式图谱。

当前图谱布局也遵循这一原则：章节按照教材结构组织；章节内部的无环方向性关系采用左向右阅读流，同源目标上下排列；对称关系同层展示；循环关系以显式回边保留真实语义。

## 6. 当前已经实现的工作链路

当前 P2 建设态 MVP 已覆盖：

1. 导入 PDF、PNG、JPG 和结构化教材材料。
2. 优先读取 PDF 原生文本，扫描页使用本地 OCR 回退。
3. 分阶段抽取节点候选、局部关系线索和章节内关系。
4. 对节点名称、别名、类型和关系端点进行保守归一化。
5. 使用教材页码、文本块和原文建立证据锚点。
6. 在 G6 与 Qt 兼容视图中审查章节嵌套和真实语义关系。
7. 支持节点、关系、证据和质量问题的人工审查。
8. 生成工作底稿、质量报告、正式图谱和 P4 分层映射。
9. 在开发阶段记录脱敏的过程信息，辅助定位模型波动和链路问题。

当前实现强调“候选先完整呈现、教师再审查确认”。待审关系不会因为被绘制出来就自动成为正式知识事实。

## 7. P2 与 P4 的衔接价值

普通脑图主要帮助人理解材料，而 P2 产生的类型化、有方向、带证据的关系能够被程序继续使用。

P2 向 P4 提供的不是一张静态图片，而是结构化的节点和边。P4 可以在这些数据基础上继续建设：

- 知识点之间的依赖网络；
- 题目与知识点的挂载；
- 学习路径和先修条件；
- 学生薄弱知识点诊断；
- 个性化推荐和后续学习调度。

因此，P2 的价值不只是“把图画出来”，而是把教材内容整理成可以审查、计算和复用的知识基础设施。

## 8. 当前边界与诚实表述

当前项目已经完成可运行、可人工审查、可质量校验、可导入 P4 的建设态 MVP，但仍不应宣称：

- 已经完成任意整册教材的全自动生产级抽取；
- 大模型生成的每一条知识关系都一定正确；
- 可以替代教师完成最终知识结构判断；
- 已经完成多人在线协作和公网生产部署；
- 已经建立跨教材统一的人工金标准和长期质量基线。

真实模型输出仍可能存在节点遗漏和关系波动。P2 通过过程记录、证据锚点、置信度、审查状态和质量门禁来管理这种不确定性，而不是隐藏它。

## 9. 公开宣传正文

### 从教材脑图到可计算的知识关系：我为什么要做 LZH-P2

最近，我集中体验和调研了一些思维导图工具，以及由大模型生成课程脑图和内容图谱的产品。

这些产品给我留下很深印象的一点，是它们能够把 PDF 或图片中的课程材料完整地组织起来：从教材到章节，从章节到小节，再到标题和具体内容，按照原书顺序逐层展开。对于快速阅读、内容导航和复习来说，这种能力很有价值。

但在继续思考后，我意识到，教材脑图和知识图谱解决的并不是同一个问题。

一份脑图可以告诉我们“教材里依次讲了什么”，却不一定能够告诉我们“这些知识之间为什么相连”。一个知识点是另一个知识点的前置条件，还是递进内容？一个定理是由哪些概念推导出来的？一种方法可以应用到哪些题型？两个不同章节中的内容是否存在等价、对比或表征关系？

这些关系如果不能被明确区分，图谱就仍然主要是一种供人阅读的内容目录，很难直接参与后续的知识诊断、学习路径和个性化推荐。

这正是我开发 **LZH-P2 教材知识图谱本地工作台** 的原因。

P2 并不希望简单复制一份“更复杂的教材脑图”。它尝试在保留教材章节结构、页面顺序和原文证据的基础上，进一步抽取规范化的知识节点，并识别节点之间具有明确含义的关系。

在 P2 中，章节和小节仍然构成教材结构的底图；概念、性质、规则、方法、表征、题型和应用则成为可以继续审查和复用的知识单元。节点之间可以通过包含、前置、递进、推导、解释、应用、表征、等价、并列和对比等关系连接。

每个知识节点和关系还需要尽可能保留教材页码、原文片段、模型判断理由、置信度和审查状态。大模型负责生成候选，但不会因为生成了某条关系，就自动把它升级为正式教材事实。教师仍然是知识结构最终确认的重要参与者。

在可视化上，P2 同时保留教材结构和知识方向。默认“关系探索”让一个知识点只出现一张卡片，以单层浅色分区区分互不相连的关系阅读单元，并按左向右方向排列；有证据的步骤按教材编号自上而下展示。辅助“教材定位”继续用章节嵌套框表达知识出现位置。前置、递进、推导与对称关系使用不同的路径和箭头语义，完整端点保护避免连线穿卡或箭头贴住边框而难以辨认。

P2 当前已经形成了一个建设态 MVP：能够导入 PDF 和图片，读取原生文本或调用本地 OCR，分阶段生成节点与关系候选，在本地工作台中联动教材原文、知识图谱、审查表格、证据和质量问题，并导出可以继续交给 P4 使用的结构化图谱。

它仍然不是一个已经完成生产级验收的整册教材自动建图系统。真实模型可能漏掉节点，也可能在不同运行中给出不同的关系。因此，当前项目尤其重视过程记录、证据追踪、教师审查和质量门禁。

我希望最终形成的不是一张只能观看的图，而是一套能够为知识点诊断、题目挂载、学习路径和个性化学习提供支持的知识结构。

如果你正在研究教材数字化、知识图谱、教育大模型、题库建设或个性化学习，欢迎关注这个项目，也欢迎对节点粒度、关系类型、教师审查方式和实际教学场景提出建议。

## 12. GitHub 公开前检查

将项目上传到公开仓库前，至少完成以下检查：

- 不提交项目本地 `.env` 和任何真实 API Key。
- 不公开包含 Authorization、token、密码或模型请求秘密的日志。
- 检查 `progress_recordings/`、缓存、运行快照和导出测试是否包含敏感内容。
- 未获授权时，不提交完整教材 PDF、扫描页、OCR 全文和可能受版权保护的模型响应。
- 为公开演示准备自制、授权或脱敏的最小样例。
- 保留 G6、本地 OCR 模型及其他第三方组件的许可证和归属说明。
- 明确当前是建设态 MVP，并列出尚未完成的生产级能力。
- 增加开源许可证、安装说明、截图、最小运行示例和反馈渠道。

微信公众号发布也应避免直接展示 API Key、绝对本机路径、教材完整页面和未经授权的学生或教师数据。
