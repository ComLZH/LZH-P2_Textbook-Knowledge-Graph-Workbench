更新时间：2026-09-13  
状态：建设态 MVP 已闭环；关系分区、证据顺序、左向右布局及完整端点保护已达到 G20-B 核心试用

## 1. 已实现

### 输入与来源

- 结构化教材 JSON Reader。
- PDF、PNG、JPG Reader。
- PDF 页码范围、页面数量和可选切分记录。
- 教材页面渲染与证据锚点定位。
- PDF 原生文本优先、扫描页共享 PP-OCRv6 回退。
- 页面图像哈希、模型组合和流水线版本级 OCR 缓存。
- 兼容中文共享模型路径的 ASCII 临时模型缓存。

### 候选生成

- 本地结构化抽取器。
- 大模型候选协议解析器。
- OpenAI-compatible 文本/图片请求客户端。
- 本地模拟与真实模型模式切换。
- 章节内部布局的本地判断和模型建议适配。
- 首轮模型同时生成相互独立的节点候选和局部关系线索。
- 节点保守归一化、别名映射、批次临时 ID 隔离。
- 局部关系端点重映射、自环阻断、重复合并和证据类型/推断范围标记。
- 归一化后按章执行文本关系整合，不重复上传已正常 OCR 的页面图片。
- 整本书章节清单检测及章内最多 80 节点的关系请求保护。
- 可选页面连续性检查与可疑对模型复核；系统不自动重排页面。

### 审查工作台

- PySide6 本地桌面入口。
- 教材原文、节点、关系、证据和质量问题联动。
- 本地 G6 与 Qt 兼容图谱双渲染器；默认 `relations` 为一个业务知识点一张卡片的关系探索，`textbook` 为多引用教材定位，两者共同消费 `ReviewViewProjection` 和 `SceneGeometry`。
- 关系模式使用单层 `VisualRelationGroup` 区分连通阅读单元，并以教材证据绑定生成上下文 `ReadingSequence`；可靠步骤固定为同列自上而下的有序扇出。
- 关系模式优先使用随包 elkjs 0.12.0 分层正交布局；多组件在单个 Node 进程中批量求解并逐项校验，缺失、超时、非法输出或硬可读性失败时显式回退 Python/NetworkX。
- 两端共享节点矩形、分区框、端口法线、避障折线、终端直段、箭头多边形和标签几何；G6 提供点击/悬停、一跳/二跳/显示全部、分区显隐、重新排版、恢复默认视图和缩放标签滞回，Qt 保持基础选择和表格联动。
- 视图操作拆分为隐藏卡片、管理教材归属、逻辑归档、重新排版和恢复视图；布局版本 6 禁用会破坏共享路径的自由拖动与教材框折叠。
- 节点、关系审核状态与人工修改。
- 可重新打开 `review_document_v2.xlsx` 或迁移旧 draft 工作簿；可将离线 Excel 修订按可信基线三方合并，冲突需显式选择后才提交。

- 从 `config/app_info.json` 读取 `LZH-P2`、应用和开发者公开信息，并通过“帮助 → LZH-P2 / 开发者信息”弹窗展示；无效配置不会阻断启动。

### 工作台服务层

- `WorkbenchAnalysisService`：无界面完成来源读取、候选生成、协议解析、审查工作簿和布局建议，并支持注入模型客户端工厂进行离线回归。
- `PageEvidenceService`：无界面完成 PDF 页面渲染、原生文本读取、OCR 回退和缓存。
- `StagedTextbookExtractionService`：无界面完成首轮抽取、节点归一化、关系线索整合、章内关系补全和现有底稿兼容转换。
- `WorkbenchReviewService`：无界面完成 v2 文档创建/保存、共享投影和递归几何、建设态质量、发布预检及原子正式发布；旧审核工作簿接口继续兼容。
- `WorkbenchReviewSession`：无界面保存底稿、关系状态覆盖、兼容视图节点位置和独立 G6 配置，并处理深拷贝撤销、关系增删改、节点引用清理、批量通过和拒绝关系识别。
- `ReviewDocumentSession`：以文档 revision 执行节点/关系/结构/profile 命令，拒绝过期写入，支持逻辑归档、兼容行单事务提交及历史追加式撤销。
- `AnalysisWorker` 只保留 Qt 线程、进度和取消信号适配。
- `TextbookWorkbenchWindow` 支持注入分析服务、审核服务和审查会话，便于后续测试和替换实现。

## 5. 工程风险

- `desktop_app.py` 仍是较大的界面编排文件。v2 业务写入已经通过 Session/兼容事务边界收口，投影与几何已移出；表格控件同步、编辑对话框和两种渲染适配仍可继续拆分。
- 真实模型异常、限流、成本和大响应解析尚无在线回归基线。
- 当前工作台界面默认启用 OCR 和分阶段抽取、默认关闭页序检查；无界面请求对象为兼容旧调用，`staged_pipeline_enabled` 默认仍为 `False`，调用方需显式开启。
- `storage/` 仍同时保存演示、缓存和人工验收产物；桌面正式导出已经按日期隔离，但长期版本命名和跨日审计仍需继续建设。
- 当前冻结目录底稿有 12 条由目录/课程顺序推断的非结构语义候选（8 条递进、4 条前置），其中 11 条为待修。它们进入双视图供教师直观判断，但不会被目录结构批量操作接受，也不会仅因显示而成为正式关系。
- 冻结正文样例的 3 条知识点间旧 `contains` 被保留为 `unresolved`，不会自动改写为归属或语义；教师需先裁决后才能发布。
- 30/100/300/1000 节点已经按“单个高密组件诊断、多个有界小组件完整布局”两类完成分级；100 节点 25 次及双真实文档冷/热基准已记录。Node RSS、跨设备性能、Windows 文件占用/磁盘故障矩阵和完整桌面端到端交互仍属于后续专项验证。
