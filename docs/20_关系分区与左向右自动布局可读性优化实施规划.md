## 0. 交接摘要与阅读说明

### 0.1 本轮目标

用户在上一轮实现后实际使用美术《篆刻》与数学《三角形》图谱，发现步骤排列与教材编号不一致、箭头沿卡片边框接入、标题被审核徽标覆盖、缩放后关系标签留下空背景等问题。节点无法拖动，进一步放大了默认布局不清楚的影响。

随后几轮讨论明确了新的目标：**自动排版为主，明确分离的关系组块使用单层浅色分区框；框内保持卡片和真实箭头，主要按从左到右阅读；修复步骤、端口、箭头和标签的可读性。**

分区框表示“这些节点在当前图谱中构成一个关系阅读单元”，不是新知识点，不是教材章节，不声明内部节点是某个大知识点的组成部分。不得借分框改变任何业务事实。

### 0.2 本期与后续的边界

本期必须完成：

1. 建立本轮样例与失败反例，纠正只检查路径中心线的验收盲点。
2. 从已有教材证据提取可核验的局部步骤编号，建立有来源的阅读顺序约束。
3. 采用稳定的关系分区依据；对明确不相连的关系单元分框，孤立节点不逐个套框。
4. 框内主方向左到右、同级上到下；步骤编号优先，循环及回指例外明确。
5. 路由保护包括起终点卡片，端口方向、末段长度和箭头可见性联合校验。
6. 卡片标题、类型、状态分区；标签文字与背景同步显隐。
7. G6 与 Qt 的基础语义、框、实际路径、箭头和固定密度标签一致。
8. 关系追踪、模式隔离、无界面计算、离线导出、状态兼容及明确降级形成闭环。

后续增强，不是本期完成前提：

- 在一个大型连通网络中自动推断主题分组、自动知识体系命名。
- 多层知识包含嵌套、知识分区折叠、拖框改变语义归属。
- 手动节点/分区拖动、固定位置、自由排版及其撤销系统。
- 专门的横向流程展开模式、人工编辑步骤顺序。

拖拽不作为掩盖默认布局问题的替代手段。后续实施拖拽时，遵守用户已确认的“默认保持左右层级，自由摆放为可选模式”。

### 0.5 R2 专家审阅取舍与用户确认

用户已确认以下取舍，并授权据此更新最终开发规划；这不是项目代码实施授权。R2 保留 72 项最终验收要求，细化实现职责及阶段性放行，不增加主题聚类、多层嵌套或拖拽范围。

| 审阅意见 | 处理结论 | 最终规则与落实位置 |
| --- | --- | --- |
| 普通右向分层与同列步骤递进存在接入冲突 | 采纳 | 有序扇出内的递进边不参与普通横向 rank，但仍保留真实关系身份；第 6.4、8.3 节 |

| ELK 只能处理严格 DAG，所有边必然跨到新 rank | 不采纳绝对判断 | 有破环、自环等能力；本工程的普通链输入确会横向展开，须纠正约束输入；第 2.4、24 节 |
| 单连通图只能得到一个分区，需要预期说明 | 采纳 | 不保证任意学科都有多个框；框不是智能主题分类；第 5.2 节 |

| 编号优先使用证据到对象的绑定 | 采纳强化，原规划已有此原则 | 使用真实字段 target_ids、evidence_anchor_ids 和 occurrences，同时定位编号条目范围；第 6.2 节 |
| 逐组件调用会反复启动 Node | 采纳风险提醒 | 默认单次请求内批量复用运行时，允许少量有预算的批次；不按组件循环启动进程；第 8.5、15.2 节 |
| 全部交由 ELK 自带分组件与打包 | 保留为受检候选，不直接替代共享打包 | 最终边界必须覆盖标题、标签和箭头；基础分区依据由共享层掌握；第 8.5、10.2 节 |
| 启动 60–100ms 及固定累计时间 | 不作为工程结论采纳 | 记录进程、模块加载、求解和序列化实测成本，不引用示例数作为 SLA；第 15.1 节 |
| 72 项按优先级分批交付 | 采纳阶段放行，不缩减最终范围 | G20-A/B/C 分批，子场景结果与完整 V20 结果分开；第 17.3–17.5 节 |
| 端口法线、关键反例、模式/状态安全推迟到视觉修复之后 | 不采纳 | 它们是当批正确性门禁；核心几何与数据保护不能因阶段性试用而延期；第 17.4 节 |

| F20-15 | 分区只在 Python 局部布局中作为计算单元存在，`SceneGeometry` 没有独立关系分区框契约 | 不应复用 `StructuralScopeDTO`/教材 combo ID 写入视觉分组 |

| F20-17 | “恢复布局”主要清理坐标并重绘固定 payload，不等于后端重新计算 | 新 UI 必须区分适配相机、恢复默认视图和重新计算布局 |

**关系页面连通性：**按页面实际节点与真实关系线的无向邻接计算，不补入教材结构/归属边，不把页面快照当作最新底稿完整基础图。

| 页面 | 节点实例/边 | 连通分量规模 | 本期预期解释 |
| --- | --- | --- | --- |
| 数学 000001，revision 0 | 25 / 21 | 8、6、5、2、2、2 | 当前页面可形成 6 个关系分区，不是一个全连通组 |

分区数不是按学科固定的参数。以上计数不能直接套到数学 revision 4 或新版美术底稿；尤其不能将全部业务对象及 structure/membership/semantic 混算后，断言关系视图只能显示一个框。

**有序扇出最小试验：**随包 Node v22.16.0＋elkjs 0.12.0，1 个父节点和按 step1–step5 输入的 5 个子节点，各 250×86，方向 RIGHT、正交路由。结果如下：

| 输入 | 结果 | 证明的范围 |
| --- | --- | --- |
| 5 条父子边＋4 条步骤递进边，普通 layered | 子步骤横向展开成 5 列 | 当前普通链式分层确实与同列 fanout 要求冲突 |
| 仅 5 条父子边，无顺序约束 | 子步骤同列，上下为 3、4、5、1、2 | 只移除递进分层约束仍不能保证教材顺序 |
| 仅 5 条父子边，同时设置模型顺序相关选项 | 子步骤同列，上下为 1、2、3、4、5 | 简单 fanout 可由 ELK 顺序配置实现，并非必需 Python 强制坐标 |

第三组使用 `elk.layered.considerModelOrder.strategy=NODES_AND_EDGES` 与 `elk.layered.crossingMinimization.forceNodeModelOrder=true`。这只是小样配置，不是完整适配方案：该小样没有将四条递进边重新路由回最终场景，也没有验证多父、跨组、复杂约束、双端箭头或标签，因此不能当作生产默认算法已选定的证据。

当前 `layout_flat_graph` 每调用一次就执行一次 `subprocess.run`，而 runner 每次读取一个 graph 并构造 ELK 实例。当前代码并未因此证明已经存在“逐组件启动风暴”；风险出现在后续把该函数直接放进组件循环时。本期需要预防，不能把预测成本描述成已发生的实测故障。

## 3. 概念、数据边界和必须保持的不变量

### 3.1 三种结构不能混为一谈

| 结构 | 来源 | 可否影响业务关系 | 示例 |
| --- | --- | --- | --- |
| 教材结构/归属 | scope、structure、membership | 只能经现有明确业务命令修改 | 13.2.1 所属节及其教材知识引用 |
| 知识语义网络 | semantic、unresolved 关系及证据 | 只能经审查流程修改 | 解释、递进、未决包含、对比 |
| 阅读分区/顺序约束 | 当前业务快照的确定性派生 | 不可反向写入知识实体、关系、审核或 P4 | 某连通单元的背景框、教材步骤编号 |

同一知识点可有多个教材出现位置，但关系模式仍保持一业务知识对象一卡。视觉框不能占用业务 node ID，也不能让虚拟 scope endpoint 被导出成新增知识实体。

### 3.2 不变量

1. 排版前后业务指纹、节点/关系 ID、source/target、类型、审核状态和发布 profile 不变。
2. 每条关系要么有可追踪的线表示，要么账本明确记录非线表示、筛选或缺端点原因。
3. 空间父子位置不是教材归属，更不自动声明 prerequisite。
4. 未决关系仍未决；已通过审核与含义已解析是两个维度。
5. 布局破环只产生路由例外，不删除边、不反转业务箭头。
6. 无来源的序号不得作为“教材第几步”展示。
7. 框不作为语义连线终点；框标题不自动成为知识对象。
8. 不用节点、边或标签消失来取得“零重叠”。任何降级均有计数和恢复入口。
9. 显示、选择、缩放和恢复默认视图不增加业务 revision。
10. 同一输入、参数、引擎版本及视口档位给出确定性场景；状态变化不凭数组次序抖动。

## 4. 用户体验与界面范围

### 4.1 默认关系视图

首屏显示单层关系分区背景、卡片、真实关系线及简明图例。分区框默认开启；工具栏可切换“显示分区”，该开关只影响背景/标题，不改变节点坐标、关系可见性或分区计算。

分区标题建议为“关系组 1 · 篆刻印章步骤相关”，其中“相关”必须保留。无法选择可信代表节点时仅显示“关系组 1”。代表标题算法不调用模型，不声称完成学科主题识别。

标题附近或详情注明：“按当前已记录关系分组；不表示知识之间绝对独立。”节点/关系总数与当前可见数分别显示，不要求常驻长篇解释。

### 4.2 核心阅读任务

- 从父节点辨认右侧的直接子节点。
- 从 ①–⑤ 编号辨认篆刻步骤，打开来源证据核验编号。
- 点击某条线，确认起点、关系含义和终点。
- 在分区之间辨认不同关系单元；知道组名是阅读提示。
- 选择一个节点查看一跳/二跳，返回时恢复原相机和选择。
- 对大图明确进入局部布局，不要求先手动拖动。

### 4.3 工具栏操作约定

| 操作 | 行为 | 不应发生 |
| --- | --- | --- |
| 适配 | 调整相机到当前显示范围 | 重排节点 |
| 显示分区 | 显隐背景框及标题 | 改变连通分组、创建包含边 |
| 一跳/二跳 | 默认稳定位置聚焦，显示范围计数 | 因隐藏节点而自动拆框 |
| 局部重新布局 | 对明确选中范围产生新布局，保留返回快照 | 冒充“显示全部”或丢弃外部关系信息 |
| 显示全部 | 恢复本阅读范围及原相机快照 | 重新生成业务关系 |
| 重新自动排版 | 明确请求新场景，可响应视口档位和新拓扑 | 点击前静默变化或套用旧坐标 |
| 恢复默认视图 | 清理本模式的筛选/相机偏好并请求默认场景 | 清理审核、归属或发布选择 |

本期不显示可用的拖动按钮，不用 `cursor:move` 暗示节点可拖；画布平移继续可用。独立“局部重新布局”可复用已有范围控件，但必须有清楚文案与返回行为。

## 5. 关系分区生成与稳定性

### 5.1 基础关系图与可见图分离

先构造 `base_relation_graph`，再计算分区，最后应用视图筛选。不能直接对隐藏后的 `projection.edge_instances` 求连通分量。

本期基础图口径：

- 节点：当前文档中关系模式的活动知识对象，以及真实语义边引用的结构端点视图。
- 边：活动的 semantic 和 unresolved 关系；默认排除 rejected，保留 pending、accepted、needs_revision、needs_expert_review。
- 不纳入：structure/membership、布局辅助边、已归档关系及非法端点。
- 用无向邻接仅判断连通性；原关系方向另存且不修改。
- 自环不连接两个组；多条平行边只贡献一次连通性，仍分别保留绘制身份。

`include_rejected` 是基础口径的一部分，只有用户明确切换该口径并重新布局时才重算分区。审核从 pending 改 accepted 不改变连通性；改为 rejected 或归档可能改变，进入待重排流程。

### 5.2 分区规则

1. 对基础图求连通分量。
2. 至少 2 个节点的分量形成 `relation_component` 背景框。
3. 单个节点不逐个画大框；存在自环仍在节点周围保留合法路径空间。
4. 孤立节点集中在有标题的紧凑区域，标题为“当前未连接知识点”；该区域不是一个连通分量，不声明主题一致。
5. 如果整个图只有一个连通分量，也只画一个框，不为了展示多个方块强切主题。
6. 不按卡片颜色、node_type、章节标题、ID 前缀或“看起来有关”强行合并/拆分。

构造标准分区的新快照中，不应有跨分量业务边；出现时说明基础图和绘制图不一致，需要诊断。历史分区暂存、口径显式变化或未来主题分组可以产生跨框边，见第 10 节。

一个全连通关系图只获得一个背景框是本期允许的结果，不等于分组功能失效；可关闭背景继续阅读内部关系。不得承诺数学会按“概念、性质、分类”自动分框，也不得承诺美术固定生成三四个框。相反，第 2.4 节当前数学页面恰有多个关系组件，不能以专家的学科概括代替样例计数。

### 5.3 身份、标题与成员

`group_id` 建议使用 `visual-group:` 命名空间，散列内容为文档 ID、模式、基础图策略版本、排序后的成员业务/端点身份；不要把显示标题、审核颜色、序号位置或节点坐标放入 ID。

分区成员列表与边列表使用稳定排序。显示“关系组 1/2”是当前排列下的易读编号，不是永久业务 ID。

代表节点选择优先级：有明确局部流程证据的共同父节点 → 稳定主干入口 → 连接度高的知识节点 → 稳定 ID 平局。标题显示完整名称的可访问替代，不能只靠被截断的标题辨认。

孤立节点区域使用 `visual-region:unconnected` 身份，不能填充成一个假的 `relation_component`。

### 5.4 交互与拓扑变化

| 事件 | 分区成员/边界策略 |
| --- | --- |
| 悬停、选中、缩放、隐藏关系标签 | 均不改变 |
| 临时隐藏节点/边、邻域过滤 | 保留基础分区身份；空分区可暂不绘制，其他分区不移动 |
| 关闭背景框 | 只隐藏装饰，不移除分区信息 |
| 审核颜色变化 | 不重算分区；刷新样式并复核绘制安全 |
| 新增/删除/归档关系，拒绝状态改变 | 标记结构已变化；明确重排时生成新分区快照 |
| 切换阅读模式 | 读取该模式独立快照，不能复用另一模式的成员与坐标 |

在用户尚未重排时，新增跨组关系应以原始节点为端点，在旧分区之间合法路由，并提示“分区待更新”。如果有界局部路由无法合法完成，明确保留旧几何/待更新提示及关系列表，不能画一条穿框穿卡的线并标记成功。

本期不要求跨拓扑编辑永远保持 group ID；可以保存新旧成员映射用于回到邻近区域，但不得把旧分区缓存误认为新拓扑的正确分区。

## 6. 教材步骤编号与有来源的阅读约束

### 6.1 当前缺口与本期取舍

没有顺序数据时，布局引擎不能从五条父子边推断五个子节点的时间先后。单纯恢复 ID 排序、OCR 出现顺序或添加几个临时绘图箭头都不合格。

本期采用**从已有证据派生的局部阅读约束**，不新增全局节点 `order`，不改业务 schema 2，不扩展 P4，不自动写入 progressive 关系。派生约束在共享场景中有完整来源，可由底稿证据重新计算。

### 6.2 编号识别与绑定链路

1. 在同一文档、教材出现上下文中定位可能的流程父节点及其相关子节点。
2. 首选 EvidenceAnchor 的原文编号；支持 `1.`、`1、`、`①`、`第一步`、`步骤（一）`、`【第一步】` 等明确形式，保留原始 token 及文本范围。`其一/其二` 等必须结合流程标题与内容，不能把普通性质列举自动当成操作流程。
3. 复用对象引用建立候选绑定：`EvidenceAnchorDTO.target_type/target_ids`、`ReviewNodeDTO.evidence_anchor_ids`、`KnowledgeOccurrenceDTO.node_id/evidence_anchor_ids/block_ids` 及上下文。字段名以当前契约为准，不另造 `evidence.target_node_ids` 或平行的 evidence_item 身份体系。
4. 对每个编号条目定位独立 source_span，结合可用的文本范围、block/bbox 和出现上下文，把条目与候选节点唯一关联。对象引用先于名称匹配；节点重命名不应破坏已经有条目级来源支持的稳定 ID 绑定。
5. 若证据整段同时指向父节点或多个子节点，只说明段落有关，不能按 target_ids 数组次序分配编号。须用条目范围和上下文继续消歧；强引用矛盾时不得忽略引用、再用字符串强行匹配。
6. 没有可用的条目级对象绑定时，才使用已存在的确定别名，再使用严格规范化名称唯一匹配；仍需遵守已有引用限定的候选范围。规范化只处理可解释的格式差异，不使用无阈值的模糊相似度或模型猜配。
7. 同名节点不唯一、同号多项、同项多号、不同流程混合或证据冲突时，分别给出 `ambiguous/conflicted/unavailable` 等诊断，不为提高命中率制造确定序号。
8. 父节点摘要或关系 `reasoning_summary` 可用于提示候选；仅有模型推理文字、无原文锚点时不能显示“教材第 N 步”确认标记。
9. 已存在的 progressive/prerequisite 保留原状态，只提供辅助核对；不会因为图中缺链而新建业务边。
10. 明确原文编号与候选递进矛盾时，保留编号展示及业务箭头，标记冲突，不能悄悄反向或删除任何一方。

绑定证据的最小记录是“编号 token＋条目范围＋证据 ID＋目标节点 ID＋流程上下文＋匹配方法”。已有 bbox 或 text_span 缺失时不伪造坐标；如可从 anchor_text 唯一切出条目，只保存明确声明为 anchor_text 相对偏移的新 source_span。

本期不重新 OCR、调用 LLM 或打开外部服务补顺序。已有原文不充分时显示“顺序待确认”，使用确定性普通布局，而不是编造完整流程。

### 6.3 派生约束建议结构

拟 `ReadingSequence` 字段：

| 字段 | 用途 |
| --- | --- |
| sequence_id | 文档、上下文、父对象及策略版本形成的稳定派生 ID |
| parent_node_id / context_key | 序列所属流程及来源上下文，不是全局知识排序 |
| items | node_id、ordinal、original_token、anchor_ids、source_span、match_method |
| verification_state | `evidence_backed`、`partial`、`ambiguous`、`conflicted`、`unavailable` |
| presentation | 本期默认 `ordered_fanout`；不是新增 view_mode |
| evidence_fingerprint / extractor_version | 证据变化后使缓存失效 |
| diagnostics | 冲突对象、缺号、重复号及未绑定条目，不包含猜测结论 |

`evidence_backed` 仅表示编号有证据，不表示节点或关系已通过业务审核。数字不连续时保留原始数字，不重编号补空缺；缺项有明确提示。

同一节点出现在两个流程的不同位置时，把编号放在各自流程的关系/详情上下文中；只有当前局部上下文唯一时才在卡片显示单一编号，禁止给同一卡片同时贴矛盾的“第 2 步”和“第 5 步”。此类样例不自动复制知识实体。

### 6.4 默认布局与额外关系

篆刻默认父节点在左，五步在右按 1–5 上到下排列。五个步骤是一组有序兄弟节点，不因单列占比超过旧阈值而打乱。

如果这五步之间同时存在真实递进边，保持可追踪，允许在步骤列旁走纵向通道，并记录 `ordered_fanout_vertical` 阅读例外。本期通过线宽/透明度和选中高亮降低竞争，不默认偷偷删掉递进边或 contains 边。

对已明确采用 `ordered_fanout` 的序列，内部步骤间递进边在本次布局派生层中标为 `routing_only`：不进入普通横向 rank 计算，但仍参与基础图连通性、关系覆盖、审核/选择与最终路由。该标记不是业务 relation_family，也不是 `is_layout_edge=true`；“显示辅助关系”开关不能使这些真实边消失。

仅排除序列内部的已识别递进分层约束，不排除涉及这些步骤的全部外部关系，也不把全部 progressive 全局改成 routing_only。无明确 fanout 上下文、存在条目绑定冲突或共享节点无法同时满足多序列时，按第 6.3、7.2 节保留事实并诊断，不套用固定模板。

步骤列是父节点右侧的局部阅读带，不是整个图固定的全局 Rank 1；右侧纵向走廊是候选优先位置，不是唯一合法位置。必须结合端口、其他真实关系和分区边界选择合法通道。

专门横向流程模式及带账本的关系汇总放入 E20；本期不能用“未来会提供流程模式”作为五步顺序未完成的理由。

### 6.5 缓存、再导入与更正边界

阅读约束是可再生派生数据：缓存按文档、证据指纹、上下文、提取版本隔离，输出到场景 JSON/离线页面供追溯。现有 XLSX 不新增必需 sheet，不让旧读取器静默丢弃新的权威业务字段。

仅复制 XLSX 后重新打开，应从其保留的证据生成相同编号；缺失证据时如实降级。本期不提供手工序号覆盖；若后续增加，需独立的带来源、版本、撤销的阅读批注契约，不能塞进 manual_positions。

## 7. 左向右阅读规范与约束优先级

### 7.1 关系角色到布局行为

| 关系/上下文 | 布局约束 | 不能推断的含义 |
| --- | --- | --- |
| 明确教材编号的兄弟步骤 | 父左子右，编号按上到下；绑定当前上下文 | 不自动接受候选流程关系 |
| 无环、已接受的前置/递进主链 | 从左到右的高优先顺读 | 不把所有邻接都当先后 |
| 待审前置/递进 | 方向保真、较弱顺读偏好 | 不作为已确定教学前提 |
| 父子候选 contains | 无冲突时源左目标右的展开偏好，保持未决标识 | 不生成知识包含框或教材归属 |
| explains / applies_to / represented_by | 邻近、少绕行；适合主干时右向偏好 | 不强迫每条边增加一列 |
| derives_to | 方向保真，局部推导链右向优先；冲突可例外 | 不等同所有知识的全局学习顺序 |
| parallel / equivalent / contrast | 邻近、同级或成对布置 | 不凭左右位置添加单向箭头 |
| cycle / 自环 / 回指 | 外侧通道，记录例外，原始方向不变 | 不自动修复业务循环 |

### 7.2 约束裁决

依次保障：

1. 业务身份、方向和来源不变量。
2. 卡片、端口、路径、箭头、标签和分区的合法几何。
3. 无歧义教材编号的局部顺序。
4. 无冲突主链右向，以及父子展开偏好。
5. 减少歧义共线、交叉、绕行和无意义空白。
6. 在上述条件满足后改善整体宽高及增量位置稳定性。

业务约束互相矛盾时不存在“一律满足”的布局。必须输出 constraint exception，区分数据冲突、阅读例外与几何失败。几何失败不能因为存在业务冲突而自动豁免。

对参与有序 fanout 的步骤间递进边，不再重复要求所有相邻步骤 x 递增；按第 6.4 节明确使用纵向例外。不能同时施加矛盾硬约束，再通过修改顺序来取悦布局引擎。

### 7.3 分层、排序及宽高控制

- 先选局部主干、阅读约束，再决定 rank；不是全部有向边统一参与最长路径分层。
- 层内采用邻接优化且保留强阅读约束；ID 只用于最终平局。
- 普通高扇出可以在同一逻辑层中使用多个视觉带，但不制造新的语义层；父子边联合路由验证。
- 合法五步列与真实长链不能被“同 x 超过 40%”机械判错。原阈值改为拓扑感知诊断，不作统一后端否决规则。
- 非有序的 24 叶星状反例仍须验证二维利用和可追踪性，不能借“父子关系”保留无限长柱。
- 真长链优先横向浏览，不强制塞入一屏；适配不能把中文标题缩成无法辨认的小块。
- 同一视口档位内窗口微调只改变相机；显式重排或跨档确认后再改变组外打包。

## 8. 共享计算链路与布局引擎接入

### 8.1 目标链路

```text
审查文档快照 + 阅读范围 + 配置
  → 基础关系图（未受临时显隐影响）
  → 关系分区 + 有来源的局部阅读约束
  → 显示投影与关系覆盖账本
  → 文字/状态/端口容量测量
  → 每分区约束布局
  → 有方向端口 + 起终点保护 + 避障路径 + 箭头
  → 有界标签放置及各密度档位
  → 分区完整边界（包含内部路径、箭头、标签）
  → 分区二维打包及必要的跨区路由
  → 全场景验证与报告
  → G6 / Qt / 离线 HTML 共用结果
```

### 8.2 算法边界

保留现有 ELK 和 Python，不引入第三个生产引擎。本期最小技术验证集中在约束传递、固定几何消费和末端方向，禁止把时间耗在泛化引擎排行榜。

ELK 官方描述支持分层、端口约束及复合图，但当前适配并未自动获得这些行为。本期分区优先采用“分区内平面布局，再外部打包”，不需要为浅色背景框启用完整 compound graph。官方资料见第 24 节。

每个后端都必须消费相同的阅读约束、卡片尺寸和端口要求。不能 ELK 尊重编号、Python 回退后恢复 ID 排序；不能 Python 有箭头门禁、ELK 输出直接跳过。

### 8.3 ELK 验证要求

**共同职责先固定，实现路径由 S1 有界验证后固定。** 普通右向分层输入与包含全部真实关系的最终场景必须分开建模，不能试图仅靠一个 `RIGHT` 参数同时表达层级、步骤编号和路由需求。

| 路径 | 实现职责 | 使用条件和门禁 |
| --- | --- | --- |
| A：ELK 局部顺序约束 | 在明确的有序扇出单元内按编号提交节点、端口/模型顺序约束；内部递进边只在最终路由阶段恢复 | 优先验证现有引擎能力；必须测多父、外部边及多个序列，不能由第 2.4 节简单小样推定全部正确 |
| B：Python 确定性局部布局 | Python 按实际卡片尺寸固定有序单元的局部相对位置；外部布局将该单元视为已知尺寸与接口的布局单元，之后统一路由 | 作为路径 A 无法可靠满足局部要求时的受检替代；局部单元只是算法对象，不新增可见嵌套框、业务节点或教材 scope |

每种受支持拓扑固定一条已验证规则，记录在 ADR20-03；可以采用“普通图由 ELK、有序特殊单元由确定性局部策略”的组合，但不能无限尝试多个后端，或失败后悄悄接受乱序结果。

必须验证：

- `layout_constraint_graph` 只含明确参与节点位置求解的关系/约束；最终 `render_relation_set` 仍保留全部真实关系。引擎输出边集合先按其实际输入子集核验，完整覆盖在后续统一路由完成后核验，不能因为 routing_only 未交给 ELK 就误报丢边或静默删除。
- 节点序号来自 ReadingSequence，而不是临时 node ID 的字母顺序。输入模型顺序不等于固定层内顺序，必须验证随包版本的实际配置效果。
- 端口 side/order 与第 9 节规则一致。路径 A 的简单配置不能被升级为全图不顾局部上下文的强制排序。
- 路径 B 的内部坐标是相对布局单元定义，外部只做合法定位/平移；不能把多个序列都锁在全局 Rank 1，或强制共享节点同时出现在两个位置。
- routing_only 的真实递进边参与最终路由和覆盖账本，不能绘制成布局辅助边，不能被辅助关系开关隐藏。
- 如果后处理移动或缩放任何节点/单元，重算或精确同步所有受影响的父子边、步骤边、外部关系、箭头、标签和分区边界，不能只补画四条递进线。
- 外侧纵向通道按真实障碍分配，右侧可优先但不是唯一合法位置。所有路径继续经过终端法线、末段长度和箭头轮廓门禁。
- 最终结果同时满足身份、有限数值、编号、业务方向、端口、路径、箭头及标签检查。Python 回退也遵守同一完整标准。

如果路径 A/B 都不能满足一个真实业务冲突样例，保留事实并按既定规则诊断，不改变用户阅读规范来让候选“通过”。

### 8.4 Python 回退与失败边界

Python 回退须按节点包围盒、端口逃逸点建立稀疏正交路由，预算按组件和整体双重控制。路由成功状态应在新增硬门禁全部通过后赋值。

单个组件失败时，不把其他合法组件全部降成无路径网格；保留通过部分，标记失败组件及其边数，提供真实可用的局部阅读入口。全场景只要存在失败组件，就不能显示“完整布局通过”。

后端异常回退必须保留原因分类：运行时缺失、超时、非法输出、顺序违约、端口不合法、路由失败、资源预算，不统称“运行时不可用”。

### 8.5 多组件的批量运行时契约

**按组件求解与按进程执行是两个层次。默认一次布局请求只创建一次短生命周期 Node 批量会话；高密组件隔离、超时恢复等必要情况允许少量有界批次。禁止循环调用当前单图 `layout_flat_graph` 为每个组件各拉起一次 Node。**

建议请求 envelope：protocol_version、request_id、document/mode/fingerprint、总预算、component_jobs。每个 job 携带 component_id、输入图/约束、预期节点和布局边 ID、该组件预算；进程内复用一个已加载的 ELK 实例，顺序或受控小并发处理。组件坐标以局部原点返回，最终全局位置由共享层统一决定。

不预设长期常驻服务、不新增第三种引擎、不要求教师管理后台进程。无须 Node 的确定性局部单元可直接由 Python 完成，但仍须满足同一输出契约和门禁。

结果和失败规则：

1. 返回 request_id、component_id、状态、耗时、节点/边几何或明确错误；完整节点/边集合按组件预期校验，不信任仅有“success”字符串。
2. 已完成组件应产生可独立验证的完成记录。优先采用有界的逐组件结构化结果记录，不能只在所有组件结束后一次性返回、导致最后一个超时丢弃前面全部工作；若用受控临时检查点，记录及清理规则必须进入 ADR20-07。
3. 接收方验证记录版本、请求 ID、成员 ID、记录长度和有限数值，拒绝重复组件结果、未知组件及截断记录；截断记录不算已完成。
4. 单个组件报错可继续处理下一组件；进程整体卡死由父进程的总 deadline 终止。已返回且验证通过的组件可以保留，其余明确未完成。
5. 剩余组件只能在剩余全局预算内进入受控重试/回退。批次数、组件重试次数及最大并发由 ADR20-07 固定，不能失败后递归拆成每组件无限重启。
6. 小图批量样例应验证 Node 启动次数不随组件数线性增长；同时记录模块加载、求解、记录传输和 Python 最终打包时间。

逐组件完成记录只在当前请求内暂存，不逐条覆盖活动画布。共享层须完成最终路由、完整边界打包与场景验证，再按第 12.3 节提交 complete 或明确的 partial/diagnostic 场景；不得把某组件的 ELK 局部成功直接等同于最终可读性通过。过期或已取消请求即使还有合法组件结果，也不得提交给当前文档/模式。

ELK 的 `separateConnectedComponents=true` 可以在单次整图请求中隔离和布局组件，当前代码已开启。但该选项不能替代本期的分组口径、ReadingSequence 约束、组件失败计量和完整框边界计算。

可以比较“单次整图 ELK 求解”与“单次会话内多个组件 job”两种封装；本期优先后者以保留逐组件约束/预算控制。无论选择哪种，最终打包结果必须覆盖标题、标签、箭头和 padding。若直接复用 ELK 的整体打包，必须在 S1 证明这些完整边界已经正确参与；否则继续使用共享层打包，不能只给 ELK 节点 bbox 再事后加大方框。

## 9. 端口、正交路径与箭头接入

### 9.1 端口不只是边框上的一个点

拟共享 `PortGeometry` 至少包含：port_id、node_view_id、side、attachment_point、outward_normal、escape_point、terminal_direction、min_stub_length、lane_index。

attachment_point 表示卡片边界上声明的连接位置；arrow_tip 表示实际箭头尖端绘制位置。二者可因边框描边和安全间隙不同，不能隐含由 G6/Qt 自行猜测。

| 接入边 | 外法线 | 目标末段方向 |
| --- | --- | --- |
| 左边 | (-1, 0) | 水平向右 |
| 右边 | (1, 0) | 水平向左 |
| 上边 | (0, -1) | 垂直向下 |
| 下边 | (0, 1) | 垂直向上 |

右出左入是正常主干的优先规则，不强制自环、循环、步骤纵向链遵守同一端口侧。源端第一段沿外法线离开，目标端最后一段沿外法线的反方向进入。

### 9.2 起终点保护与逃逸通道

1. 所有节点，包括当前边的起终点，都进入障碍集合。
2. 障碍范围考虑卡片主体、边框、必要的阴影安全量及路径 clearance。
3. 为当前边的源/目标端口声明狭窄、定向的终端通道，不整张排除其节点。
4. 搜索在两个 escape_point 之间进行；源端和目标端直线短段单独拼接。
5. 路径简化不能删掉必要终端短段、改变其方向或把线压回边框。
6. 完成后复核非终端部分不得穿过自己的起终点卡片，也不得长距离沿其边框运行。

可采用现有 A* 的有向扩展，但搜索状态需要区分到达方向；不得只在找到任意终点后称为合法接入。

### 9.3 箭头几何

共享场景输出最终箭头尖端、切向、轮廓多边形或等价 path，不再只输出 `end_arrow=true`。

- 箭头尖端应位于目标外侧的指定间隙，不能被卡片边框、状态条或遮罩盖住。
- 初始间隙建议 2–4 逻辑单位，并计入描边半宽；实际值在 S1 的 G6/Qt 和 DPI 测试中确认。
- 末段长度至少覆盖箭头长度、描边及转角安全量；初始箭头长 10–12，终端直段不小于 20–24 逻辑单位。
- 箭头朝向使用最后一个非零长度段，不以源中心到目标中心的方向替代。
- 双向关系同时验证两端；无箭头关系不添加教学方向。
- 不能通过把整个边图层提到卡片上方来掩盖穿卡问题。
- 同一场景采用相同逻辑箭头尺寸。缩放档若调整箭头尺寸，必须同步输出对应几何和重新校验，不能浏览器单独放大。

节点 hitbox、可见边框和路由障碍必须分别定义，不能把点击热区当实体卡片宽度；也不能因阴影 bbox 外扩让锚点被重复偏移。

### 9.4 多边与高连接度

同一对节点的多种关系保留独立 edge ID、可单独选择的路径和标签。默认不做隐式总线汇聚，不将一段共线当成多条可辨认的边。

端口间隔以箭头半宽、描边和点击需要为下限，初始建议至少 12 逻辑单位。节点侧边容量不足时，先尝试换侧、增大卡片高度或周边走廊，并重新布局；不能把 20 条线压进 86 高卡片的同一小段。

高连接度的容量扩展有上限和预算，但基础 24 叶星状样例不能靠默认隐藏大半关系验收。确实超过预算时记录降级，详情列表仍完整，局部范围可以重新求解。

### 9.5 交叉、重线与标签

允许图结构决定的必要交叉，但不允许把不可区分的长共线误判为普通交叉。点交叉不能默认画成有连接语义的实心连接点。

若使用跨线桥或圆角，最终段应进入共享几何，两端渲染一致；本期优先直角折线，不为装饰引入新的路径拟合。标签不放在交叉、箭头末段、端口或分区标题处。

## 10. 单层分区框与组外打包

### 10.1 分区几何

拟 `VisualGroupGeometry` 包含 frame_rect、content_rect、header_rect、member_view_ids、internal_edge_ids、paint_bounds、group_id 和 grouping_basis。

frame_rect 按以下内容联合包围再增加 padding：

- 成员卡片的实际绘制外边界；
- 内部边的所有路径段和箭头轮廓；
- 预留的可见标签布局，以及需要切换的密度档位占用；
- 分区标题、统计与必要安全边距。

分区标题带不允许内部路径穿过。框不是节点障碍：内部路线可以在 content_rect 内走动；外部不相关路线不能穿过其他组的 content_rect 抄近路。

### 10.2 外部打包

对无跨组边的连通分区执行确定性的二维 shelf/skyline 或等价矩形打包，比较有限个候选列数，目标兼顾可读缩放与画布宽高。记录候选数量上限，避免无界搜索。

按明确阅读上下文（若有）与稳定 ID 排序；面积可参与打包，但不能导致同一输入每次随机换序。分区之间的左/右或上/下不作为先后关系写入。

每次平移一个分区时同步平移全部成员节点、端口、路径段、箭头、标签和诊断定位。遗漏任何一类属于整体事务失败。

孤立节点区域一并打包，区域标题不画成知识节点；单一大连通块不能通过切掉弱边伪装成多个无关联框。

### 10.3 跨框线的适用场景

本期正常连通分区不存在跨组业务边。以下场景需要保底支持：旧分区待重排期间新增连接、明确切换基础口径但尚保留旧快照，以及测试注入的合法旧快照。

跨框线从真实源卡片到真实目标卡片，穿出源框/进入目标框时选择边界通道，避开标题和无关卡片；分区间走廊优先。不把框边界改成业务端点，不把视口裁剪处的线头画成目标箭头。

重新计算基础分区后，确有连接的旧分区应按新快照合并；此前跨框显示不声称它们仍是独立连通分量。未来主题分区可保留跨框关系，但不在本期自动启用。

### 10.4 视觉规格与交互

- 背景低饱和、浅填充，边框比知识卡片轻；分区不能抢占标题和箭头的视觉优先级。
- 不使用审核状态色标记整个视觉分区为“已通过”。可显示成员数量和待审数量，但需要准确分母。
- 本期单层，不设置 group 的 parent_group_id，不提供折叠按钮或可拖框把手。
- 框内空白区域仍可平移画布；点标题可选择分区并展示成员/范围详情，但不触发业务编辑。
- 框背景绘制在路径与卡片下方，命中事件不能截获内部边选择。
- 关闭分区背景时保留坐标和箭头，不改变可读性口径。

## 11. 卡片、文字与标签密度

### 11.1 卡片区域拆分

卡片至少区分标题区、知识类型/角色区、审核状态区；流程编号在当前上下文唯一时占用独立位置，不覆盖标题。

优先采用独立状态行或明确预留的状态区域，不能只在原有标题上层增加徽标。标题允许有限行换行，超过后按实际测量宽度省略；悬停、选择详情和无障碍文本保留完整标题。

标题测量必须考虑中文、英文、数字、标点、公式字符、emoji/组合字符和真实字体。截断不得拆坏 Unicode 字符。字体缺失使用明确回退并重新测量，不能假设所有环境字符宽度相同。

本期优先复用 Windows 已有中文字体和现有 PySide6 的离屏字体测量能力，不新增需分发的字体包。共享规格使用逻辑像素字号，Qt 不得把它误作 point size 再随 DPI 放大，G6 使用对应的 CSS 像素字号。测量服务可以创建必要的离屏字体环境，但不能启动主工作台窗口；具体字体族、回退次序和测量实现由 ADR20-04 固定。离线 HTML 使用字体回退时需要检测尺寸风险，不能声称在任意未测设备上文字几何绝对一致。

不要求所有节点永远同高。若采用固定尺寸档位，必须先测量并选择档位，再计算布局，不能渲染后随意撑高卡片。

### 11.2 关系标签必须消费共享位置

共享 `EdgeLabelGeometry` 输出文本、rect、anchor、密度档、可见性、抑制原因和完整说明。G6 与 Qt 按相同场景绘制，不能 G6 再按路径中点自行放置。

缺少合法空间时允许抑制标签，原因必须记录为 node_collision、label_collision、terminal_zone、header_collision、density 或 budget，不能以空字符串冒充“没有标签”。

标签隐藏时同时隐藏文字、背景、阴影及命中组件。删除/重建标签时不得残留 G6 `text-bg-shape`；Qt 对应组合对象同样清理。

本期优先将标签放在线旁。标签背景不能遮住另一条关系线；若未来采用覆盖本边的内联标签，须明示路径截断/连接规则并单独验证，本期不默认启用这类豁免。

### 11.3 密度档位

| 档位 | 默认呈现 |
| --- | --- |
| 总览 | 卡片名称、简要类型/状态、关系路径；部分重复标签抑制，未决身份仍可识别 |
| 阅读 | 显示已通过碰撞校验的常用关系标签与步骤编号 |
| 聚焦 | 强调选中路径及两端，完整关系说明进入固定详情；不强迫所有标签同时出现在画布 |

保留滞回防止缩放阈值附近抖动。当前 0.78/0.92 只是起点，不直接继承为新卡片尺寸下的正式阈值。

切档默认不移动节点或分区；可以切换预先计算的标签几何。不能把总览中隐藏的所有标签一键恢复到未经验证的路径中点。

若聚焦标签没有合法画布位置，使用固定详情区显示，并突出边与端点，不覆盖卡片。标签放置考虑框标题、箭头、边线及其他标签；聚焦不能绕过这些规则。

### 11.4 图例与颜色

语义颜色、线型及箭头来自共享注册表。审核状态是第二维度，不得让“已通过”的绿色完全覆盖关系类型，造成类型不可辨认。

未知/未决含义在图例、选择详情及适当的低密度标记中可辨认。禁用纯颜色编码：同时通过线型、箭头和文字支持理解。背景网格保持轻量，不能比细线关系更显眼。

## 12. 聚焦、稳定性与后续拖拽

### 12.1 本期关系追踪

选中边时，同时突出完整边、源节点、目标节点；详情显示两端名称、原始类型、展示名称、审核状态、语义待确认标记、证据入口和例外原因。

选中节点时高亮直接关联，可进一步一跳/二跳；无关联节点说明“当前范围未记录关联”，不自动补关系。ESC 清除焦点，键盘或详情列表应有等价定位入口。

缩放后隐藏的标签仍能通过边或关系列表选择。命中容差可以比绘制线宽大，但命中热区不能改变几何障碍或标签重叠统计。

### 12.2 过滤与局部重新布局

一跳/二跳默认做稳定位置过滤，不重新计算基础分区。对确实拥挤或降级的大图，用户可明确请求“局部重新布局”：

1. 以选中 ID、跳数、允许关系类型和当前文档快照形成范围。
2. 保留所有该范围内部关系；外部连接显示计数及可打开的列表。
3. 调用共享服务重新计算该子图，不能仅 hide/show 旧诊断网格。
4. 分区仍注明来自哪个基础分区，不宣称筛选后产生新的独立知识体系。
5. 返回显示全部时恢复此前节点坐标、相机和选择快照。

范围超过预算时明确显示部分布局及未展开数量，不能把“二跳”文案暗示为全部两跳数据已完整绘制。

### 12.3 重新布局事务

UI 发起计算时携带 document_revision、mode、scope、request_id 和 fingerprints。计算完成只有与当前请求一致才提交；过期结果丢弃，不能覆盖用户刚切换的教材模式。

提交包含节点、分区、路径、箭头、标签及报告的一整份场景。失败保留旧可读场景并提示；首次无合法场景时显示明确诊断及表格入口。

耗时计算不占用 GUI 主线程。取消后终止或忽略过期子进程结果，不能让取消的结果进入当前视图状态。

### 12.4 E20 拖拽边界

后续拖拽需另行落实：同层默认上下调整、横向保持阅读约束、自由模式显式切换、松手后全体受影响路径重算、固定/取消固定、整操作回退、视图撤销。

“受影响”不限于与移动节点相连的边，还包括被该节点挡住的其他边及分区边界。移动框时全部内部几何共同平移。

普通拖动不能改变步骤序号、知识包含、教材归属或业务 revision。本期不实施此套系统，也不以“拖动被禁用”在 E20 中写通过。

## 13. 共享场景契约、版本与持久化

### 13.1 拟新增/扩展对象

以下是规划接口，实施可整合文件，但字段含义与责任不得省略。

| 对象 | 最小字段与责任 |
| --- | --- |
| LayoutRequest | 文档快照标识、mode、scope、view filters、viewport profile、strategy、budget、request_id |
| BaseRelationGraph | 排序后的基础节点/边、纳入策略、拓扑指纹；独立于临时可见性 |
| VisualGroup | group_id、kind、member_ids、edge_ids、title、basis、snapshot_id、pending_update |
| ReadingSequence | 第 6 节的上下文、序号、证据、验证状态与冲突 |
| LayoutConstraint | 对象 ID、类型、强度、来源、适用上下文、可接受例外；派生 edge_role 区分 rank/ordering/routing_only，不修改业务关系身份 |
| NodeGeometry | body_rect、paint_bounds、title/status/type/ordinal rect、完整文本、尺寸档位 |
| PortGeometry | 第 9 节的 attachment、法线、escape、容量和终端方向 |
| EdgeRouteGeometry | 真实端点 ID、port ID、最终段、status、终端区、例外、使用后端 |
| ArrowGeometry | edge ID、端别、tip、tangent、polygon/path、paint_bounds |
| EdgeLabelGeometry | 各密度档的位置/文本/背景/显隐/抑制原因 |
| VisualGroupGeometry | 第 10 节的框、标题、内容区、整体绘制边界 |
| SceneLayoutResult | 上述完整集合、版本/指纹、组外打包、布局状态、覆盖账本和 ReadabilityReport |

坐标统一为逻辑画布坐标，节点 body_rect 用左上角与宽高；向 G6 中心点转换只在适配边界发生一次。DPR 只影响最终物理像素，不能重复缩放路径。

`visual_groups` 与教材 `scopes`/`scope_rects` 分开。不要把新框加进当前 `all_rects` 后让通用障碍判断把框内所有节点视为穿框；节点障碍、合法容器、分区边界分别查询。

### 13.2 版本建议

建议保留业务 schema 2 和关系投影 schema 2，新增独立 scene schema 1，并把布局版本提升为 6、绘制测量规格提升为 3；最终编号在 S1 ADR 中确认，但不得沿用版本 5 的几何含义。

新增视觉分区是场景扩展，不改变原投影 scope 的业务定义。如果最终必须变更 `ReviewViewProjection` 的序列化含义，则单独升级投影版本并迁移，不能以“只加一个字段”绕过兼容检测。

`scene_status` 至少区分 complete、partial、diagnostic、failed；`business_review_status` 与其完全分开。未来版本不能被 `stored.layout_revision >= current` 判定为可套用。

### 13.3 指纹及缓存

| 指纹 | 包含 | 不包含 |
| --- | --- | --- |
| base_topology | 基础节点身份、关系身份/端点及纳入策略 | 坐标、颜色、临时标签开关 |
| grouping | 基础拓扑、分组策略版本 | 显示组号、相机 |
| reading_constraints | 来源上下文、编号映射、证据摘要、方向约束状态 | 字体颜色 |
| metrics | 字体、卡片/徽标/标签/箭头规格、密度档和视口档位 | 业务置信度 |
| layout | 上述指纹、引擎及配置版本、范围 | 当前鼠标悬停 |
| style | 语义/审核样式、非几何外观 | 业务身份和位置 |

不能直接把现有 `structure_fingerprint` 当纯拓扑指纹。新旧字段并存期间分别验证，不就地篡改旧哈希算法含义。数组先稳定排序；无关审核颜色更新不得让所有分区换 ID。

### 13.4 旧状态与独立保存

- Desktop 文件状态与浏览器 localStorage 明确各自权威来源，不重复覆盖。
- 当前文档/模式/布局版本不匹配的旧坐标不应用；保留原文件或可恢复备份，不直接覆盖用户旧配置。
- 旧隐藏/选择设置只在 ID 仍存在且语义一致时迁移；旧手工坐标不进入新自动布局。
- 未来版本状态只读且不回写；损坏状态隔离并提示，不能自动当作空文件覆盖。
- 本期持久化重点为模式、相机、密度偏好、分区显隐及范围；派生分区和编号可重算，缓存不是权威知识事实。
- 保存采用同目录临时文件、验证及原子替换；失败显示未保存，不能先显示“已保存”。

保持相机、筛选和布局偏好独立于业务审查撤销链。恢复默认视图仅影响当前文档和当前模式，不清理其他教材配置。

### 13.5 导入导出

审查 XLSX 继续原协议，不将视觉 group 写成 scope、不将 ReadingSequence 写成正式关系。导出前后校验节点、关系、证据和发布 profile 不变。

离线 HTML 嵌入场景快照及必要的只读证据摘要、组信息、顺序来源、密度标签位置、范围计数和状态。没有 Qt 桥接时可适配、选择、缩放、过滤及恢复嵌入视图；未提供本地布局执行器时，明确禁用“重新计算”，不能伪装成后端可用。

不得因新增场景 JSON 输出而覆盖用户的底稿目录。导出新增布局快照可以作为伴随诊断/视图文件，但需清楚说明只复制 XLSX 不会携带相机偏好，编号仍可由保留证据重建。

## 14. G6、Qt 与既有入口适配

### 14.1 G6 主视图

分区优先实现为受共享几何控制的背景层，不使用 G6 combo 自动反算成员边界、重新布局或收缩节点。若采用自定义 combo，必须关闭隐式布局并证明不改变共享几何。

对最终路径采用精确消费方案：若内置 polyline 会因锚点 bbox 或默认 offset 改变端点，则使用自定义共享路径边或等价无重算适配；以实际 shape path 验证，不以配置名判断。

标签按共享 rect 放置，箭头消费共享轮廓，背景层不得吞掉边点击。保留现有语义注册表和业务桥接 ID，不将 group click 派发为 node delete/edit。

前端状态显隐要覆盖初次渲染、viewportchange、选中、取消选中、数据更新和重新渲染所有分支。只修一处 `label:''` 不足以证明没有残留。

### 14.2 Qt 兼容视图

用独立背景 item 绘制关系分区，路径/箭头/标签按相同场景创建。QPainterPath 和多边形不重新按中心点推测方向；状态更新不把共享路径替换成旧曲线。

Qt 必需基础能力：分区含义清楚、编号正确、卡片无覆盖、箭头可辨、类型/审核维度正确、节点/边可选、详情/证据可达、显式布局失败提示。

G6 的动画、复杂悬停和自动密度交互不要求原样复制；Qt 可以用明确密度按钮切换，但选中固定档位后必须使用同一标签几何，不允许显示端各算一套。

### 14.3 模式能力矩阵

| 能力 | G6 relations | Qt relations | textbook 模式 |
| --- | --- | --- | --- |
| 视觉关系分区框 | 必需 | 必需 | 本期不叠加，保留教材框 |
| 步骤编号与来源 | 必需 | 必需 | 有匹配出现上下文时展示，不跨引用串用 |
| 新端点/箭头/卡片/标签安全规则 | 必需 | 必需 | 同样必需，防共享改动回归 |
| 分区/对象基础选择和详情 | 必需 | 必需 | 沿用教材作用域与业务详情 |
| 动态密度滞回 | 必需 | 可用明确档位切换替代 | 固定场景档位几何一致 |
| 局部重新布局 | Desktop 必需 | 共享服务入口可复用 | 不把局部框变为知识分区 |
| 手工拖动、固定及自由模式 | E20 | E20 | 不因本期分区改动偷偷开启 |
| 分区折叠/多层嵌套 | E20 | E20 | 不扩展既有教材折叠能力 |

### 14.4 服务、CLI 与旧分支

服务、Desktop、HTML exporter 及当前可运行的 CLI staged-check 复用一个 scene 构造入口。旧 DTO/legacy 布局分支必须标明适用边界，不能让同一文档因入口不同而默认进入不同版本。

不要求本期扩展 Web 原型产品功能；其复用的服务不能被破坏。相关可选依赖未安装时记录未运行，不伪报浏览器产品验收。

## 15. 性能、有界降级、离线与安全

### 15.1 性能口径

按业务节点数、可见实例数、边数、组件数、最大组件规模、最大度、步骤组规模和标题长度记录样例，不能只用 n 比较算法。

计时分为：读取/投影、分组、编号提取、文字测量、节点布局、端口分配、路由、标签、打包、验证、渲染。记录机器、引擎版本、冷/热运行、峰值内存和超时原因。

初始目标：本轮美术/数学完整默认场景在参考 Windows 机器上计算 p95 ≤3 秒、首屏总耗时 p95 ≤5 秒；100 节点稀疏组图完整计算 p95 ≤5 秒。至少 5 次冷、20 次热样本，分别报告；目标待 S1 实测确认，不写成已实现承诺。

另行统计 process_count、batch_count、组件排队时间、Node 启动/模块加载成本、序列化/传输成本和每组件求解耗时。专家举例的 60–100ms 冷启动及累计时长未在本工程实测，不作为基线或承诺；不能仅用 ELK 内部 elapsed_ms 代表用户等待时间。

### 15.2 按组件与全局同时限额

- 节点总量较大但每个组件很小时，应优先逐组件求解再打包，不继续简单按总量 ≥300 直接放弃全部路径。
- 单个高密组件可独立降级；其他通过组件保持正常显示。
- 组件拆分不取消整体时间/内存预算。批次启动、模块加载、传输和打包全部计入，不能每组件都获得无限叠加的 5 秒预算。
- 按第 8.5 节在单次短生命周期会话内批量复用 Node/ELK，默认不做组件与进程的一一对应；内部先串行或受控小并发，不预设长期守护进程。
- 高密组件可以隔离为少量受控批次，但进程数量与重试必须有上限；预算用尽后不再启动新的批次。
- 全局预算用尽后未处理组件列为未完成，而不是空边成功。

### 15.3 降级呈现

场景状态与摘要必须同时显示“已布局/待处理组件、成功/失败/范围外边数”。失败路径可以作为诊断示意，但明确不是真实通过的路由；不能与正常边无差别混绘。

基础真实样例不允许仅靠降级网格完成本期验收。对 300/1000 节点压力样例，允许有界降级但必须证明局部重新布局能真正生成新的合法路径，而非只隐藏旧网格。

### 15.4 离线与安全边界

- 保留随包 Node/ELK，固定受控路径及版本；不能执行底稿内容提供的脚本路径或命令。
- Windows 子进程不弹出控制台，超时/取消后正常回收；不得影响工作台之外的进程。
- 场景输入输出验证 ID、有限数值、点数/数组规模、路径长度和文本长度上限。
- 所有来源文本和组标题按文本处理；JSON 嵌入脚本必须处理 `</script>` 等边界，DOM 详情转义不能代替嵌入层安全。
- 导出不携带密钥、临时个人绝对路径或无关完整教材正文，不向外部布局服务发送数据。
- 本文引用原始证据只用于可读性核验；安全问题的修复范围限定在本次触及的渲染/状态/导出链路，不顺带扩大为服务器重构。

## 18. 可读性指标与通过口径

### 18.1 逻辑几何和实际绘制双层检测

第一层直接验证共享场景，可无 GUI 执行。第二层从 G6 实际 shape/path/label 和 Qt item/path/polygon 提取绘制结果，在同一逻辑坐标系复核。

第二层不能只检测节点和 combo bbox。若真实边/箭头/标签无法提取，记录为 `not_measured`，不能自动输出 0。

### 18.2 指标定义

| 指标 | 计数定义与要求 |
| --- | --- |
| node_overlap | 两张知识卡片可见主体重叠；不同引用实例仍分别检查，教材框/视觉框合法包住成员不算卡片重叠 |
| title_status_overlap | 标题或编号的实际文本区域与状态/类型区域相交 |
| edge_nonterminal_intrusion | 除声明终端短段外，边的绘制轮廓进入任意卡片保护区，包括自己的源/目标 |
| terminal_direction_violation | 源首段不沿外法线或目标末段不沿负外法线；记录 edge、port、向量 |
| terminal_stub_short | 终端直段不足以容纳箭头和转角安全量 |
| arrow_occlusion | 箭头轮廓被目标卡片、边框、其他卡片、标题或遮罩遮挡超出规定接触容差 |
| port_spacing_violation | 同侧端口间距小于当前箭头/线宽规格要求 |
| ambiguous_overlap | 不可单独追踪的线段长共线；不能用普通 crossing 代替 |
| edge_crossing | 可辨认的点交叉，单列统计和记录对象；一般不是全图零交叉硬要求 |
| label_collision | 实际可见标签与卡片、标签、终端区、分区标题或受保护线段冲突 |
| empty_label_background | 无可见文字却残留可见背景/阴影/命中形状的标签组件 |
| sequence_inversion | 对有证据且无歧义的同一序列，有序对违反声明的阅读顺序 |
| sequence_binding_error | 序号绑定错节点/错上下文，或无来源却展示确定教材序号 |
| lr_constraint_violation | 无声明例外的必需右向主干违反 x 顺序；不统计无方向关系和允许的纵向步骤 |
| group_partition_error | 分组成员重复/遗漏、正常组件中出现未解释跨分区基础边、过滤误改成员 |
| group_overflow | 成员卡片、内部边、箭头或当前密度标签越出可用 content_rect |
| group_header_collision | 内部路径或标签穿过分区标题保护区 |
| group_overlap | 两个独立分区的完整绘制边界重叠；不能只比较卡片 |
| renderer_geometry_mismatch | 实际路径/端口/箭头/标签与共享场景不一致，记录最大偏差和对象 |
| failed_edges / unmeasured_edges | 未产生合法路径/未得到实际绘制证据的数量；不可从分母移除 |
| coverage_gap | 业务关系到线/明确非线表示/筛选账本的覆盖缺口 |

初始几何对齐容差为 2 逻辑单位，向量方向比较使用统一数值 epsilon；测试同时检查方向与侵入，不能以 2 单位坐标容差豁免几十单位的沿边末段。容差调整需要 ADR 和 125%/150% DPI 证据。

### 18.3 硬门禁与软目标

真实美术、数学及基础反例中，上表除 edge_crossing 外的适用错误计数必须为 0；实际绘制基础样例不允许 `not_measured`。缺号或真实证据冲突可以有业务/证据诊断，但不得因此出现伪造序号或非法几何。

所有允许例外单独列出具体对象、来源和原因。不能使用“复杂图”这一总括原因让所有右向违约或路由失败豁免。

软目标：减少必要交叉、绕行长度、无效空白和非必要位移，改善可读缩放。不得牺牲证据顺序或端点安全换取紧凑度。对非有序大星状图报告最长视觉列、列占比、画布宽高和识别任务结果，不采用全拓扑统一的 40% 否决线。

### 18.4 报告格式

阶段交付还需输出 `stage_profile`、必需能力/用例 ID、逐用例结果、证据位置及相对完整 V20 的覆盖差额。阶段结果和最终需求结果分别存储；不能把 G20-A/B 的通过自动传播成全部 V20 的通过。对包含已通过与未测子用例的总项，保留子用例明细，总项以 `not_run` 并注明“部分已测”；已有失败或阻塞时明确记录 `failed` 或 `blocked` 及影响范围，不用单一汇总状态掩盖明细。

### 19.1 必须保留的故意失败反例

反例用于证明检测器能发现问题，不能只在“修好后的场景”运行指标：

- 末段沿左侧边框上下行进，但中心线不进入其他卡片。
- 最后直段短于箭头，箭头被目标卡片遮盖一半。
- 绕行中再次穿过自己的源节点，但终点正确。
- 逻辑标签合法，G6 改放中点后与卡片相交。
- 缩放隐藏文字，背景仍可见。
- 正确几何但把 2 和 5 的步骤 ID 对调。
- 整段证据同时指向多个节点，却按 `target_ids` 数组位置强配步骤序号。
- 把 routing_only 的真实递进边标为布局辅助，关闭辅助线后关系消失或组件被拆开。
- 步骤后处理只更新四条递进路径，父子或跨单元路径仍停留在旧端点。
- 隐藏一条桥接关系后错误拆分分区。
- 平移框和节点，漏平移箭头或标签。
- 隐藏失败边并把失败计数写为 0。
- 接受未来状态版本并覆盖保存。
- 批次最后一个组件超时，错误丢弃之前已完整接收并校验的组件结果。
- 多组件输入导致进程计数随组件数量逐个增长，或重试突破总预算；用受控启动计数/故障注入检出，不依赖在用户环境制造进程风暴。

每个坏样例应触发指定指标；正常样例不应被同一规则误报。检测器只查自己生成的数据、不验证实际绘制，不能完成本轮闭环。

### 25.2 最终 ADR 摘要

1. `layout_version=6`、几何测量规格 3；旧 v4/v5 手工坐标不套入新版场景。
2. 步骤顺序优先使用 evidence、occurrence、节点及关系的对象绑定，文本匹配只作回退；冲突时不强制排序。
3. 步骤间递进边仍是业务边，但以 `routing_only` 退出普通 rank 计算，由 Python 后处理固定同列顺序并单独路由。
4. 分区只取关系基础图连通分量，孤立节点合并为一个中性区域；不做主题推断，不产生知识包含事实。
5. Python 生成卡片、实际折线路径、端口法线、箭头多边形、标签矩形和分区框，G6/Qt 共同消费。
6. ELK 通过 `p2_elk_batch_v1` 单 Node 进程处理多组件并逐项校验/检查点；缺失、超时、非法结果或硬门禁失败时采用有界 Python 回退。
7. 单个高密大组件进入明确诊断；总量虽大但每个独立组件不超过 12 节点/24 边时允许逐组件完整计算并二维打包，不循环启动 Node。
