# 11. 开发阶段全过程记录与关系稳定性验证

更新时间：2026-08-23  
状态：已实施并完成真实链路验证

## 1. 目标与边界

本模块用于开发期回答“关系是在模型输出、JSON 解析、节点归一化、关系整合、审查还是可视化阶段丢失”。它是可热插拔的开发观测层，不改变节点、关系、审查状态和正式导出的业务契约。

阶段性可视化目标是：25 个目录结构节点在 6 个章节大框中正确嵌套，`contains` 用空间包含表达，前置/递进等语义候选作为真实有向边显示并等待教师审查。

## 2. 热插拔模式

| 模式 | 行为 |
| --- | --- |
| `off` | 使用 `NullProgressRecorder`，不创建运行目录 |
| `summary` | 保存运行清单、模型调用耗时/用量、阶段数量、解析诊断和错误 |
| `full` | 在摘要基础上保存脱敏提示词、原始模型响应和中间 DTO |

界面位置为“04 模型与识别 → 过程记录”，开发期默认 `full`。命令行读取：

```text
TEXTBOOK_BUILDER_PROGRESS_RECORDING_MODE=full
```

## 3. 目录和数据流

```text
progress_recordings/YYYY-MM-DD/HHMMSS_<analysis_run_id>/
├─ 00_run/                  # 请求、运行清单、结果摘要、最终状态
├─ 01_input/                # 来源记录与书本清单
├─ 02_page_evidence/        # OCR/原生文本、页面摘要与页序结果
├─ 03_first_pass/           # 首轮节点和局部关系线索
├─ 04_node_normalization/   # 规范节点与别名映射
├─ 05_relation_completion/ # 关系候选、分组解析诊断与摘要
├─ 06_layout/                # 布局建议与最终计划
├─ 07_review/                # 初始/导出时审查状态
├─ 08_export/                # 导出清单
├─ model_calls/             # 每次模型请求、原始响应和提供商用量
└─ events.jsonl             # 按时间的事件流
```

每轮分析使用全局唯一模型调用编号，不同 client 包装器不会覆盖对方。`analysis_run_id` 同时写入分析结果、工作台运行信息和导出清单。

## 4. 安全和容错

- 递归脱敏 API Key、Authorization、access/refresh token、secret、password 以及 Bearer 值。
- 不记录 `data:*;base64` 图片正文；只记录本地路径、大小和 SHA-256。
- 写入使用临时文件替换，避免局部 JSON。
- 记录创建、事件写入或后置导出记录失败都不得中断主业务。
- 运行数据默认不进入版本管理；稳定后将模式改为 `off` 即可停止。

## 5. 关系解析诊断

每个章的关系补全自动记录：

- 模型原始关系数和原始类型。
- seed 关系数。
- 非对象条目、无效端点/类型数。
- 被过滤证据引用数。
- 去重后关系数和最终类型。
- 分组失败的章节、异常类型和信息。

模型补全的关系标记为 `relation_source=llm_relation_completion`，不再与首轮局部线索混淆。

## 8. 已知边界与后续

- 单次首轮长 JSON 调用实测约 160 秒，某个关系分组也曾达到约 163 秒；需后续增加可配置的单次超时、重试和串行进度表示。
- 过程记录支持查错，不等于完整审计、交互回放或长期版本系统。
- 语义候选数量可波动；应以冻结输入、录制模型响应和教师金标建立稳定性基线。
- 功能稳定后优先将模式切换为 `off`；是否物理删除记录代码应在生产化前单独决策。
