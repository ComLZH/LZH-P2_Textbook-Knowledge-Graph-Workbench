## 0. 审查摘要与阅读方式

本次优化需要同时修复数据归属、关系投影和多层布局。仅修改节点间距、容器颜色或箭头，不能解决 2026-09-08 正文样例暴露的问题。

建议采用以下方向：

1. 教材结构、知识点的教材归属、知识语义分别建模，以证据关联。
2. 两种视图消费同一个视图投影；教材结构生成框，知识对象生成卡片，语义关系生成线。
3. 使用自底向上的递归尺寸计算及分作用域关系布局，覆盖章、节、子节和正文知识。
4. 保留现有候选、审核、证据与 P4 边界；增加建设态底稿版本和显式导出兼容检查。
5. 先使用已有底稿与录制响应离线验收，再进行真实模型质量验证。

宏观判断：**关系中心的产品定位和 G6 选型可以继续；需要调整的是当前把不同含义压入同一棵包含树的构造方式，以及依赖浅层结构的布局实现。** 本轮不以更换数据库、升级 G6 大版本或重写 Web 平台作为前置条件。

审查时建议先看第 1–4 节确定问题与目标，再看第 5–12 节审查具体契约，最后看第 13–17 节审查实施顺序、验收与风险。

## 3. 目标、非目标与设计约束

### 3.1 必须达成的目标

- 在证据支持的归属下，知识对象位于对应教材章/节范围；未决对象有明确的待确认区域。
- 两种视图的对象身份、业务端点、关系意义、审核状态和结构层级一致。
- 多层框递归包住内容，平级节点和框不重叠；深层节点不能因未定位而进入孤立节点兜底。
- 每条活跃关系都有明确显示方式，或有可查询的过滤/折叠说明。
- 保存、回读、撤销、手工编辑及兼容导出不会重新丢失归属或制造语义关系。
- 已有目录样例继续正确工作；本轮正文样例成为固定回归输入。

### 3.2 本轮不承诺的能力

- 不承诺仅凭模型标题即可准确判定全部知识语义。
- 不要求所有跨框关系、循环边在屏幕上都从左向右。
- 不自动把不同教材、不同版本的同名节点合并为全球唯一知识实体。
- 不开展数据库更换、学生状态、推荐、组卷、多租户或计费开发。
- 不以 G6 大版本升级替代修复数据投影；当前本地 vendor 记录的是 G6 4.8.24 使用方式，不能直接套用新版本字段。

### 3.3 权威关系与展示属性

业务模型决定身份、教材归属和语义；布局决定坐标、线段路由、展开状态与视觉密度。拖拽、对齐、邻近和连通性都不能修改业务关系或审核结论。

### 3.4 同一事实来源，三条独立消费路径

```text
P2ReviewDocumentDTO（唯一建设态事实，由 Session 管理修改）
├─ DraftRowView / 属性读取模型 → 表格、属性面板、搜索
├─ ReviewViewProjection       → 递归布局 → G6 / Qt
└─ PublishPlan + FormalProjection → 正式 Excel / layer_mapping / P4
```

- 三条路径共享结构、归属、语义及审核规则；中间结果均为可重建的派生数据。
- 表格行用于显示，不作为第二份权威存储；修改通过命令返回 Session。
- 审查视图投影包含引用实例、折叠、筛选和虚拟分组，只供显示及关系覆盖检查。
- 正式投影从建设态文档和显式发布选择生成，不读取画布可见节点、combo、缩放、手工坐标或当前聚焦小节。
- 正式 Excel 与分层映射消费同一份正式投影；不能分别重算不同范围。
- 质量预检和所有读取投影不得原地修改建设态文档。旧 `WorkbenchReviewService.check_quality` 会先执行端点归一化及层级同步；新链路必须改为纯读取校验，需修订的数据另列为命令建议。

## 4. 建议采用的三类业务结构

产品仍保留教材内容结构层与规范知识关系层；以下三类是两层之间的具体数据职责。

| 类别 | 典型对象/关系 | 唯一事实来源 | 展示方式 |
| --- | --- | --- | --- |
| 教材结构 | 章→节→子节 | `relation_family=structure` 的结构关系 | 框或折叠结构卡片 |
| 教材归属 | 知识节点在某小节出现 | `relation_family=membership`，关联出现记录与证据 | 节框内知识卡片；归属状态可查 |
| 知识语义 | 前置、应用、表征、分类、组成、属性 | `relation_family=semantic` 的关系记录 | 类型化连线，不自动生成父框 |

不能分类的旧边使用 `relation_family=unresolved`，完整保留原类型和理由，显示“含义待确认”。

### 4.1 本轮正文的推荐目标视图

```text
第十三章 三角形                         教材结构框
└─ 13.1 三角形的概念                    小节框
   ├─ 三角形
   ├─ 三边都不相等的三角形
   ├─ 等腰三角形
   ├─ 等边三角形
   ├─ 内角、边、顶点
   ├─ 按边分类方法
   └─ 符号表示
       上述九个知识对象之间保留各自的语义连线
```

“三角形”保留 `concept` 身份，不因具有属性而变成教材容器。三角形与内角/边/顶点之间可用“原包含·语义待确认”连线过渡，教师确认语义后再采用明确类型。

此目标依赖本轮规范节点及对应教材证据中的 13.1 归属。迁移产生的归属均保留待审状态；仅有旧 Excel、缺少可信恢复信息时，不得声称已经恢复九个节点的小节。

### 4.2 单父级结构与多归属知识

- 教材结构在一个来源版本内采用无环单父级森林；多个章可以是根。
- 同一知识节点可在多个小节出现，多个有效归属不等于教材结构多父级冲突。
- 目标画布默认每个作用域只显示同一知识对象的一张卡片；跨作用域的出现通过引用卡片呈现，聚焦时优先展示当前小节的实例。
- 引用卡片拥有独立 `view_id`，关联同一 `node_id` 和具体 `membership_id`。修改知识内容影响同一业务节点，修改某次归属只影响该归属。
- 知识节点合并、拆分和跨教材统一另设审核流程；不得因为展示了两个引用卡片就新增两个正式知识节点。

## 5. 建设态数据契约与底稿保存

### 5.1 建议增加的聚合对象

新增 `P2ReviewDocumentDTO`（拟定名称），统一持有节点、结构说明、出现记录、关系、证据及版本信息。`FormalGraphWorkbookDTO` 继续服务正式导出，不再作为承载全部建设态信息的唯一对象。

| 集合 | 建议字段 | 规则 |
| --- | --- | --- |
| 文档元数据 | `schema_version`、`document_id`、`source_identity`、`source_sha256`、`analysis_run_id`、`revision` | 来源身份在移动磁盘后不变；校验哈希时区分教材版本与处理范围 |
| 业务节点 | 现有节点 ID、名称、类型、审核状态、`lifecycle_state` 及证据引用 | 本轮保留旧 ID；章/节仍可沿用已有 container 节点 ID；逻辑归档不等于 rejected |
| 结构说明 | `scope_id`、`source_identity`、`structural_role`、编号、阅读顺序、层级证据 | `scope_id` 引用对应 container 节点；名称和审核状态仍以节点记录为准 |
| 出现记录 | `occurrence_id`、`node_id`、`source_identity`、原始 `chapter_hint/section_hint`、页码、块引用、临时 ID | 保留每次出现，不把归属提示直接当已确认父级 |
| 关系记录 | `relation_id`、`relation_family`、`source_node_id/target_node_id`、`relation_type`、证据/出现引用、置信度、审核状态、`lifecycle_state`、来源 | 单一权威关系集合；结构和归属也拥有独立审核状态，归档后保留历史 |
| 迁移与语义信息 | `origin_record_ids`、`original_relation_type`、`original_review_status`、`proposed_relation_type`、迁移版本 | 原始事实与拟议修订并存，可解释差异 |
| 证据集合 | 现有 anchor ID、节点/关系目标、来源页块和原文 | 对象移动、反转关系、删除/合并后统一维护引用 |
| 审核与编辑历史 | `decision_id`、对象 ID、对象 revision、前后状态、操作人、时间、原因 | 当前状态保存在对象中，历史只追加；本地操作人标识不冒充已认证的多人账户 |
| 导出选择 | `profile_id`、目标协议、选定范围、`primary_membership_by_node`、对应文档 revision | 主归属选择必须持久化；归属被删除、拒绝或修订后重新检查，不能沿用失效选择 |
| 可选视图状态 | renderer、投影/布局版本、结构指纹、折叠/聚焦、相对坐标 | 非业务权威；不匹配可安全失效，不影响底稿事实 |
| Excel 导入基线 | `base_export_id`、`base_revision`、对象/字段快照、派生列快照、规范化及投影版本、校验哈希 | 只描述上次导出时的状态，不参与当前事实推导；可随审查包离线携带 |

`section` 可增加为便于阅读的派生字段，但多次出现和多归属必须由集合表达。父级字段、旧 `candidate_relations`、`candidate_prerequisites/prerequisite_nodes` 和视图角色也属于派生兼容字段，不能与新关系集合同时自由写入。修改旧前置列表须转换为独立关系修订并审核，不能直接触发正式补边。

### 5.2 稳定标识与消歧

1. 结构匹配键包含来源版本、章节范围和小节编号；不能在全工程只按“13.1”或显示名匹配。
2. 迁移优先复用旧 `node_id`、原始临时 ID 映射及证据块；不因补充归属重生成节点 ID。
3. 当前节点 ID 含章信息，本轮不改变既有标识体系，也不宣称它已经跨教材全局唯一。
4. 关系 ID 独立于可编辑端点/类型；旧三元组键只用于首次导入映射。端点或类型修改应增加 revision，并使旧审核结论重新待审，而非复用原 accepted 状态。
5. 同端点不同语义类别的边不得按旧三元组误合并；结构、归属与语义的去重规则分开。

### 5.3 合并时保留全部出现位置

`NodeCanonicalizer` 的合并结果必须聚合所有候选的出现记录。即使规范名称、类型和章完全相同，不同小节/页块的来源也必须留下。

结构节点的身份应额外使用结构编号与来源范围，避免同名“复习”“练习”等跨小节容器误合并。已有合并记录若只剩代表性 section，标记为“历史出现信息可能不完整”，不得从单一值反推没有其他出现位置。

### 5.4 Excel 建设态版本 2

建议继续以 `reviewed_draft.xlsx` 作为可携带审查包，新增版本说明及扩展工作表：

- `review_meta`：schema、文档/来源身份、运行编号、数据 revision、兼容说明。
- `draft`：现有节点字段及供浏览的兼容投影；节点字段为权威，旧关系/父级列为派生。
- `scopes`：结构角色、编号、顺序和证据引用。
- `occurrences`：知识对象出现记录。
- `relations`：结构、归属、语义和未决关系的权威记录。
- `evidence`：证据锚点；去重后以 ID 引用，旧列仅作为兼容展示。
- `migration_audit`：迁移来源、规则、前后数量、问题和版本。
- `review_history`：审核及业务编辑历史。
- `export_profiles`：目标协议、主归属选择、发布范围及选择所依据的 revision。
- `view_state`：可选的双视图显示状态，按 renderer 隔离；缺失时重新布局。
- `import_baseline`：只读基线记录，保存导出时的字段与关系快照，供第 5.6 节对账。

R2 在原十张工作表基础上增加一张内部基线表，目标清单为十一张；其中视图状态缺失可重建，基线缺失则降低自动合并能力。工作表数量是保存实现，不是要求教师逐表维护数据。基线表默认隐藏，常用编辑面及内部表的可见性见第 5.8 节。

现有 `XlsxWorkbookExporter` 使用显式列清单、`DraftWorkbookReader` 只读取 `draft` 表，因此新增 DTO 字段本身不能完成保存回读。实现必须增加成对的 `read_document/export_review_document` 接口，并让桌面会话、CLI、撤销和导出共同使用聚合对象。

新版读取旧 v1 底稿时进行只读解析和内存迁移；新版读取 v2 时按扩展表定义解释字段权威性，但所有外部编辑仍需基线对账、校验和导入预览后才能提交。人工在 Excel 修改派生关系列时按第 5.6–5.7 节处理，不能静默覆盖权威表。

旧版程序无法保证回写 v2 扩展表。必须在底稿说明中标明“旧程序仅可查看，回写会丢失扩展数据”，迁移保存为独立文件并保留原本；不能承诺只加一个版本号就能阻止未知旧程序覆盖文件。

未知更高 schema 应拒绝写回；扩展表损坏或 ID 引用缺失时生成可恢复诊断，不悄悄退化为无扩展信息的 v1 保存。

### 5.5 关系端点、类型与归属标识

首期使用下列组合约束，不能只读取 `relation_type` 判断是否为层级：

| relation_family | relation_type | 端点及校验 |
| --- | --- | --- |
| structure | `contains` | 教材结构节点→同来源版本的教材结构节点；校验单父级与无环 |
| membership | `contains` | 教材结构节点→知识节点；引用相符的出现记录或人工指定理由 |
| semantic | 原语义类型，或经审查保留的知识 `contains` | 端点为真实业务节点，不使用 view ID；按类型校验，不能进入结构树 |
| unresolved | 保留旧类型 | 家族含义或端点角色未决；可保存与审查，不参与教材父级推导 |

保留 `contains` 原类型是为了旧记录无损迁移；**family 与 type 的组合才是新模型的完整语义键**。缺少 family 的输入一律走旧格式分类，不按新契约直接使用。这里的建设态 schema 版本与现有 `export_manifest.json` 的版本各自独立，不能因为清单已是 schema 2 就判断底稿已是 v2。

`membership_id` 是 membership 家族记录的 `relation_id`，不是第二套可独立修改的归属表。一个 scope→node 归属可以关联多个 `occurrence_id`；同一小节的多次提及默认合并证据，不反复增加卡片。不同小节产生独立归属。重复边合并时保留全部来源与审核历史；审核结论矛盾则提示冲突，不自动覆盖。

目录中的 `progressive/prerequisite` 等语义边可以以结构节点为端点；“教材框与语义分开”不是禁止框之间存在业务关系。折叠和空框也必须有可连接的视图端点，以保留原目录样例的非包含边。

跨来源操作以文档/来源身份隔离旧 node ID；多文档合并不属于自动归属流程。若未来显式合并遇到旧 ID 碰撞，先给出重映射预览及 lineage，不能覆盖同名 ID 的另一份数据。

### 5.6 Excel 导出基线与三方对账

#### 5.6.1 基线保存内容

每次成功保存 v2 审查包时，基于该次完整文档快照生成新的 `base_export_id`，同时保存：

- 文档/来源身份、业务 `base_revision`、导出器版本、`projection_version`、`normalization_version`。
- 可编辑对象的稳定 ID、对象 revision，以及节点、结构、归属、语义、审核等参与导入的字段值。
- `draft` 派生关系字段的导出值，以及它们对应的关系 ID、归属 ID、当时所选主归属；不能只保存显示名称。
- 规范化后的逐对象/字段校验值及基线整体摘要，便于快速发现变化或意外损坏。

基线分记录保存到 `import_baseline`，大文本/数组按格式限制分段，不把完整审查包塞进单个 Excel 单元格。它是历史参照，不是可编辑的第二份权威文档。隐藏、保护和普通哈希不是防篡改签名，不宣称可识别蓄意修改基线并重算哈希的行为。

换主机只需携带完整审查包即可使用基线，不依赖旧电脑日志或同路径侧文件。真正缺少基线时保留全部可读取内容，标注“无法确认修改历史”，进入保守人工对齐；不得生成一个假基线后声称完成精确合并。

#### 5.6.2 规范化与比较单位

比较按稳定 ID 和具体业务事实进行，不以 Excel 行号或整表哈希作为身份：

- 忽略无意义的行排序、JSON 空白及对象键顺序；有业务含义的阅读顺序保留。
- ID 按文本保存和读取，不将编号中的前导零、版本信息自动数值化。
- 缺少字段、显式清空、删除整行分别记录；不能都当作空值覆盖。
- 名称只作显示及候选解析。改名后对应 ID 未变，不生成新的归属；只改 parent 名称时需唯一解析并检查父级 ID 是否冲突。
- 一个知识对象的派生父级列只表达基线中指定的那一条主归属/结构父级；修改它不意味着删除其他小节归属。
- 前置列表与权威前置关系比较时同时检查边状态及来源；不能重现 F13 的默认 accepted 补边。

#### 5.6.3 三方规则与并行编辑边界

基线为 B，回读的派生列为 D，回读的权威记录为 R。按同一事实比较 D 与基线派生值、R 与基线权威值，再比较双方提出的修订是否相容：

| 变化情况 | 处理方式 |
| --- | --- |
| D、R 均未变 | 保持原事实，无修订 |
| 仅 D 改变 | 形成明确的关系/归属修订建议；列出解析依据，不直接覆盖 R |
| 仅 R 改变 | 校验其修订；通过导入预览后重新生成派生列，不把未改的 D 当作反向覆盖意图 |
| D、R 对同一事实作相同修订 | 合并一次，保留双方来源，不重复建边 |
| D、R 作不同或不兼容修订 | 列出基线、双方值、影响对象，逐项裁决 |
| 基线损坏、版本不可解释、对象 ID 冲突 | 阻止自动合并及有损写回，保留文件与诊断供恢复 |

不同事实的非冲突修改可合并，但不能因整张 relations 表有任一变化就把所有派生列判成冲突。若导入目标是已经继续编辑的打开会话，还需将选定修订与当前会话相对同一 B 的变化比较；同对象同字段冲突仍须裁决，不能拿旧 Excel 覆盖较新的人工工作。导入提交使用第 9.1 节的 revision 检查。

### 5.7 Excel 导入流程与教师裁决

导入流程为“只读解析 → 基线与差异检查 → 预览裁决 → 全量引用/状态校验 → 单次原子提交”。取消或校验失败不改变当前会话、不覆盖源文件。

差异面板至少显示对象 ID/名称、字段、基线值、Excel 值、当前会话值（适用时）、拟执行命令、受影响归属/关系和阻断理由，支持按问题类型筛选。

对派生列修订提供三种明确操作：

1. **将所选 Excel 修改作为修订导入**：转换为明确命令；新建或改变端点/类型的事实进入待审，不继承旧 accepted。
2. **保留权威记录，忽略所选派生列修改**：不删除原文件，可在新保存包中重新生成一致派生值；涉及当前会话更新时仍先做冲突检查。
3. **取消本次导入**：不提交任何修改。

不能提供“以整张派生表覆盖所有关系”的快捷操作。删除 Excel 行首先显示为删除候选，须走实体/归属影响预览；新行须生成或校验 ID，重复 ID 不允许覆盖已有对象。无法解析的名称不通过邻近行猜测。

首期采用全包原子导入：用户须解决冲突，或明确选择忽略相应修订后再提交；不在用户不知情时只导入部分成功行。成功导入记录源文件哈希、基线 ID、采纳/忽略的差异与命令历史，重试同一修订不得重复添加关系。新的基线只在后续成功保存时生成，失败不推进基线。

只有状态字段被明确修改、且对象内容未改变时，才按独立审核命令校验该决策；同时修改内容与 accepted 状态不能绕过“内容修订后重新审核”的规则。

### 5.8 教师编辑面与保存适配落点

- `draft` 默认展示常用节点字段，派生列注明“修改将作为关系修订导入”，不能仅靠表名暗示权威性。
- `relations` 提供可编辑的端点 ID/名称辅助列、家族、类型、状态；名称辅助列与 ID 冲突时提示消歧。
- 出现记录、证据、历史、基线及版本信息默认作为内部/高级查看区；可见性与保护仅防误操作，不承担安全授权。
- 在工作簿元数据和界面帮助中说明：如何修改节点、如何修改归属、修改后如何回到工作台确认。
- 当前轻量 writer 只写显式列和基本工作表 XML；隐藏表、只读提示、校验列表、基线序列化不是现成能力，需要纳入 exporter/reader 的成对实现与 Excel 实际保存回读测试。
- 当前 reader 对列表字段调用 JSON 解析。格式错误应报告工作表、对象、列及可修正原因，不能吞掉为默认空列表；是否提供非 JSON 的教师友好输入格式需定义明确语法并测试，不能擅自按逗号拆分含标点的知识名称。

## 6. 教材归属构建与旧 `contains` 分类

### 6.1 归属处理顺序

1. 读取已有人工确认/拒绝记录。拒绝某个归属后，重算或无关编辑不能使其自动复活；新证据只能产生可审查修订，重新启用须人工确认。
2. 验证现存结构或归属关系的端点、来源和角色；明确冲突不自动选择。
3. 使用候选的章/节提示、已识别标题及其页块证据，在同来源版本内生成归属建议。
4. 多条证据指向同一结构对象时去重；多小节出现生成多个候选 membership，不合并成多父级错误。
5. 只能确定章、无法确定节时，可进入章下“待确认小节”的虚拟分组；不能伪造一个教材小节。
6. 来源或章节也不明确时进入全局“待确认归属”；仍显示相关语义边和证据。

证据冲突、同编号多候选、缺失结构节点、拒绝记录与模型建议冲突，均输出待审问题。模型声明 `section=13.1` 是来源线索，是否可信还需校验来源范围与证据；默认不自动 accepted。

### 6.2 旧关系迁移规则

| 旧关系形态 | 建议迁移结果 | 禁止行为 |
| --- | --- | --- |
| container→container 的 `contains`，结构角色与证据一致 | `family=structure` | 仅凭 `container` 类型就认定任意边是教材层级 |
| 教材 container→知识对象的 `contains`，有内容归属依据 | `family=membership` | 由节点通过状态推导归属通过 |
| concept/property 等知识对象之间的 `contains` | 保留原边，进入 semantic 或 unresolved，附分类理由 | 投影成教材父级、直接隐藏、批量改为已确认 has_part/has_property |
| 只有旧 parent 字段 | 记录 `legacy_parent` 来源，按端点及证据分类 | 当作模型或教师曾明确确认的原始边 |
| 父级字段与显式结构关系冲突 | 保存两种来源并诊断，暂停相关投影 | 用新父级静默覆盖另一种来源 |

`candidate_parent_node_id` 最终只投影教材结构或选定的主归属，不再投影知识组成。需要保留旧投影时存入迁移记录，不能让旧值重新参与新树推导。

### 6.3 不完整教材与多层角色

- 局部正文可只包含小节而没有章节点。结构角色应从已验证标题/编号保存，而非单凭当前深度把根小节升级为章。
- 允许使用“当前教材范围”虚拟框提供上下文；虚拟对象带 `is_virtual=true`，不进入正式知识节点、批量通过和 P4 导出。
- 空结构节点仍在结构导航中可见，可显示为空框或折叠结构卡片；不得因没有子节点而变成知识概念。
- 结构循环、多父级仅在 structure 家族中诊断。冲突对象进入明确问题区，保留原始边，不通过删除事实强行造树。

## 7. 双视图统一投影与关系表达

### 7.1 共享投影对象

建议新增 `ReviewViewProjection`，由建设态文档一次生成：

- `scopes`：教材框、父框、结构角色、排序及审核状态。
- `node_instances`：`view_id`、`node_id`、`membership_id`、显示作用域、是否引用/虚拟。
- `edge_instances`：业务 `relation_id`、实际业务端点、所连视图实例、显示分类和路由作用域。
- `representation_ledger`：每条关系通过嵌套、线段、折叠汇总或明确筛选表达的记录。
- `issues`：未归属、结构冲突、待定关系意义、投影端点缺失等诊断。

G6 与 Qt 都使用该对象；禁止再各自用“是否有孩子”或 `parent_node_id` 猜容器。G6 输出 `comboId/parentId`，Qt 使用递归容器几何，两者只是适配方式不同。

### 7.2 展示契约

| 关系类别 | 默认表达 | 可隐藏线段的前提 |
| --- | --- | --- |
| 教材 structure | 父子框嵌套，结构关系可在面板查看 | 父子实例有效、无冲突且嵌套确实成立 |
| membership | 目标节点位于教材作用域框内，显示归属状态 | 归属映射有效且该实例已表达这条归属 |
| semantic | 有标签的真实连线，包括知识间的旧 `contains` | 仅用户明确筛选或折叠汇总；有计数与恢复入口 |
| unresolved | “关系含义待确认”连线或问题区记录 | 不得仅因原类型为 `contains` 消失 |
| layout 辅助 | 默认隐藏，可单独打开 | 始终不作为业务关系进入审核或正式导出 |

结构关系为待审时可以嵌套；归属关系为待审时可以放入框内并标注待确认。节点审核状态和归属状态分开显示，避免节点已通过就被误认为所有归属已确认。

默认不把 rejected 关系作为自动归属或分层约束。审查模式可显示其线段/问题记录；筛选状态、数量及原因必须可见，两种视图一致。

### 7.3 跨框、引用与折叠

- 每条语义关系默认只选择一对可见端点实例，优先当前聚焦作用域；不为多个出现位置生成笛卡尔积连线。
- 跨小节边连接真实节点或展开/折叠代理，详情永远能返回业务端点及证据。
- 折叠汇总边保存所代表的关系 ID 集合和数量，展开后恢复，不能将汇总边写回底稿。
- 某端点被筛选时列出“因端点不可见而暂未显示的关系”，不得静默缩减关系总数。
- 图谱显示“知识节点数、结构数、归属数、语义关系数”；引用卡片数与业务节点数分别统计。

## 8. 递归布局与几何约束

### 8.1 计算流程

```text
建设态业务文档
  → 教材结构与归属验证
  → 共享视图投影与端点实例选择
  → 关系按展示作用域分组
  → 自底向上测量节点/子框并布局
  → 自顶向下累积坐标
  → 跨框边路由和标签避让
  → G6 / Qt 适配与实际包围盒检查
```

每个父作用域先计算子作用域完整尺寸，再把“直接知识卡片＋完整子框”作为布局单元。父框内容区等于所有子单元包围盒加边距，标题区单独计入，不能在排好一个小卡片后再向其下方追加后代。

虚拟全局根只负责排列顶层章和待确认区。顶层章沿教材顺序纵向排列；深层作用域逐层递归处理，不使用依赖节点列表顺序的一遍追加算法。

### 8.2 几何不变量

1. 每个子单元包围盒完全位于父框内容区，不进入标题或内边距。
2. 同级单元不相交；标题、状态徽标计入实际尺寸。
3. 矩形中心点、左上角和逻辑尺寸的转换集中在适配器，禁止直接复用两种视图的裸像素坐标。
4. G6 实际 combo 边界与 Qt 实际矩形均执行检查；首期按确定尺寸渲染，尺寸不符进入明确诊断，不依赖跨 Python/JS 多轮回算维持布局。处理协议见第 8.7–8.9 节。
5. 布局输入相同、约束相同且无手工覆盖时，层级和顺序确定；同 rank 对象有不同纵向槽位。
6. 缺少坐标视为投影/布局错误，不能统一扔进 orphan 横排。

节点测量采用稳定的角色尺寸和可控换行，两端可使用各自明确的尺寸配置，但共享层级和顺序。首期文字在给定框内排版，不用未经验证的“字数×字号”反向扩大布局单元。真实截图仍需覆盖 Windows 字体与高 DPI，不以纯数值计算替代视觉验收。

### 8.3 关系布局作用域

- 同一小节内的知识对象：按该小节的显示实例分层，不依赖旧语义 parent。
- 跨子节但属于同一章：计算端点最低公共教材祖先，在该层把子框作为单元处理；边仍连接真实业务端点。
- 跨章：保持教材章序，使用外侧通道、折叠汇总或聚焦查看，不为满足某一边方向交换章节。
- 未归属对象：参与待确认区布局，可与已归属节点连线；显式标记尚未参与章内分层的原因。

每条边记录 `layout_scope` 与 `constraint_status`，例如 `rank_enforced`、`semantic_cycle`、`cross_scope`、`order_conflict`、`symmetry_conflict`、`filtered`。验收要检查每条边是否被分类，不能只统计恰好进入算法的边。

### 8.4 方向、对称关系与循环

先明确布局关注的关系：学习依赖视图优先前置/递进/推导，语义全景同时展示应用/表征等，但视觉顺序不宣称是教学顺序。

- 方向性无环边在可满足约束的同作用域内采用左向右。
- 强连通分量先基于真实方向性边计算，组内回边保留端点和方向。
- 对称关系优先同层，但不能把有方向路径的两个节点硬合并成同层，再把人为约束冲突标成知识循环。
- 若 A 与 B 并列但又存在 A→B 的方向约束，采用方向约束优先、对称边保持中性并输出 `symmetry_conflict`；由教师评估语义是否矛盾。
- 将多个子框压缩到父层可能产生“布局单元循环”，即使业务图无环；此情况标记为跨作用域约束冲突，不冒充真实知识循环。
- 学习前置循环与应用/表征构成的语义循环应分别诊断；有循环不等于所有类型都应阻止正式导出。

### 8.5 收敛旧布局建议与新布局

当前 `ChapterLayoutPlan`、模型布局建议及 `relation_layout` 同时影响角色或坐标。新方案以共享投影和确定性递归布局为默认依据。

旧建议可作为可查看的历史解释，不再自动决定“主路径”角色，也不得隐式新增业务边或触发额外布局模型调用。未来模型布局建议若保留，只能提出分组/顺序软建议，并经过同一约束检查。

无关系的一组属性应显示为“并列内容/未建立依赖”，不能仅因排成一行标为“单主线”。

### 8.6 手工拖拽与旧坐标

- 新布局版本拟为 4，同时增加 `projection_schema_version` 和业务结构指纹。
- 版本 1–3 的坐标先备份，再在新投影中失效；结构、归属改变也需要重新验证手工坐标。
- 手工位置使用 `view_id + scope_id` 的作用域内相对坐标，并各自保留 G6/Qt 的显示偏好。
- 首期拖拽保持教材归属，限制在当前父框内容区；释放时若无法在框内无重叠落位，则恢复拖拽前位置并提示原因。拖动教材子框时整体移动其后代，不能只移动边框。两种视图行为一致。
- 自动扩框并重排祖先可作为后续增强，不与首期限制边界行为同时模糊启用。改变归属使用独立审查命令。
- 同框自由拖拽可打破默认左向右方向，但需标识手工覆盖，恢复布局可复原。
- 恢复布局只重置显示覆盖，不修改节点、关系、归属或审核状态。

### 8.7 首期确定性尺寸规格与纯函数几何

新增 `RenderMetricsProfile` 和纯函数几何模块（例如 `geometry/recursive_layout.py`，均为拟定名称），明确以下输入输出：

| 输入/输出 | 内容 | 职责边界 |
| --- | --- | --- |
| 输入投影 | scope 树、节点实例、共同的 rank/order 与边作用域 | 不根据字体宽度重新改变业务归属或教学顺序 |
| 输入尺寸规格 | renderer、规格版本、卡片宽高、标题/徽标区域、边距、同级间隔、折叠尺寸 | Python 与对应渲染器使用同一规格；不在 JS 的 enrich 函数中再次写另一套尺寸 |
| 输入显示覆盖 | 经验证的相对手工位置、展开状态、布局版本 | 不能包含业务父级修订 |
| 输出几何 | 每个实例的外框、内容区、标题区、子单元位置、边路由约束及问题列表 | 逻辑画布坐标，渲染器适配中心点/左上角及相机变换 |

`layout_scene(projection, metrics, overrides)` 应是可离线测试的纯函数，不导入 PySide6、QtWebEngine、浏览器驱动，不写磁盘、不访问模型。文字排版由适配器限制在预留区域内；节点正文的完整文本在详情面板查看。

首期规定固定宽高/有限尺寸档位、最多显示行数、行高和省略方式；长标题不继续横向撑框。空框、节点状态改变、徽标变化也需纳入规格，不能只有无状态卡片尺寸。阴影等纯装饰不作为知识内容边界，但描边、标题和可操作徽标须计入可见范围检查。

目前 `g6_html.py::enrichNode` 使用 250×86 或 220×72，`enrichCombo` 使用独立 padding。这些是现有实现事实，不是已验证的新规格；实施时集中规格来源并移除适配器对已给定尺寸的静默覆盖。

### 8.8 G6 适配验证与运行时尺寸检查

当前桥接事实：`GraphReviewBridge.saveViewConfig` 经 QWebChannel 接收 JS 配置，`_update_g6_graph_payload` 经 `runJavaScript` 更新页面。缺少的是尺寸反馈与布局纠偏协议，不是完全没有双向通信能力。

在 S0/S4 的小型渲染验证中，使用本地实际 G6 包，并记录版本/文件哈希，确认如下行为后才接入主工作台：

1. 空 combo、三层嵌套 combo、结构叶节点、长中文标题均遵守尺寸合同。
2. 固定尺寸、内部 padding、标题定位和 combo 中心重算之间的相互作用有实测结果；不能假定传一个 `size` 就等于关闭所有自动行为，也不直接套用 G6 新大版本配置。
3. 实际边界转换回同一逻辑画布坐标后，与预期外框、内容区核对；页面缩放和系统 DPI 不得重复乘入尺寸。
4. 折叠、展开、拖动子框后重复核对包含与同级间隔。首期折叠保留原布局槽位，不自动压缩整章；展开恢复原几何，紧凑重排另走“恢复/重新布局”。
5. 无 Qt 桥接的外部浏览器静态页同样能显示、检查边界、聚焦和使用约定的显示操作；不能依赖 Python 常驻才能完成基本渲染。

运行时检查输出拟定 `GeometryReport`：文档/视图 revision、投影指纹、renderer/规格版本、测量坐标系、期望/实际边界差异、越界/重叠对象和错误码。数值误差容差需在规格中明确，仅容忍描边/浮点等误差，不掩盖标题溢出或明显几何越界。

检查时机为首次稳定渲染、payload 更新、折叠/展开及拖拽结束；每个显示 revision 合并重复检查。过期页面回调按文档、视图 revision 和指纹丢弃，不覆盖较新状态。Qt 桥接可传回诊断用于汇总，静态页则本地展示；诊断消息不作为业务编辑或自动重排命令。

### 8.9 异常处理及原“有限回算”约定的修订

R2 将原第 8.2 节未明确归属的“有限次回算”替换为以下首期策略：

- 正常显示必须在确定性规格内闭合；Python 不等待浏览器文字测量握手才能生成可用结果。
- 发生越界/覆盖时记录 `geometry_contract_violation`，显示问题对象与聚焦入口；该视图不能被标记为验收通过。
- 拖拽产生的非法位置按第 8.6 节恢复，不能扩大画布后声称问题消失。初次渲染失败保留业务数据，可切换至已经通过检查的另一视图；另一视图未通过时也不得宣称正常。
- 不自动发起 render→回传→重排→render 循环，不因反复测量改写审核结论、归属或正式导出。
- 后续若确需浏览器内局部纠偏，应单独定义触发条件、最大次数、稳定阈值、坐标状态保存和失败回退，优先封装在 JS 表现适配器内。需要跨 Python/JS 协议时另行评估，不作为本轮默认隐藏依赖。

## 9. 审查、状态与编辑命令

新增独立“教材归属”审查入口，显示节点出现位置、目标章/节、证据、建议来源及冲突。节点、结构关系、归属和语义关系分别审核。

| 操作 | 允许影响 | 必须保持 |
| --- | --- | --- |
| 通过当前章/全部目录结构 | 无歧义结构节点及 structure 关系，原子生效 | 不顺带接受正文节点、membership 或 semantic |
| 通过选定归属 | 明确列出的 membership | 不自动接受知识节点或任何语义边 |
| 调整归属 | 目标归属记录、对应视图实例和审计 | 知识身份及知识关系端点不变 |
| 删除结构对象 | 需预览受影响后代/归属；默认转为未归属待处理 | 不级联删除共享知识对象 |
| 隐藏引用卡片 | 只影响 view_state | 不删除出现记录或改变归属审核状态 |
| 拒绝/移除本处归属 | 只影响选定 membership 的状态/活动性 | 保留其他归属、知识对象和原始出现证据 |
| 更正出现记录 | 只影响该条 occurrence 及受影响证据建议，保留历史 | 不等同隐藏卡片或删除知识对象；受影响归属重新检查 |
| 合并/拆分知识节点 | 经预览重映射归属、证据和关系 | 不静默丢弃出现位置；修订后重新审核受影响事实 |
| 修改关系类型/方向 | 创建新 revision，旧决策保留在记录中 | 不继承之前 accepted 的结论 |
| 撤销 | 原子恢复操作前的业务字段、审核及相关视图状态，并追加撤销记录 | 不能漏掉扩展数据；不删除既有历史或把 revision 倒退为旧值 |

五个状态在新建设态模型中完整保留：`pending`、`accepted`、`rejected`、`needs_revision`、`needs_expert_review`。UI 可以提供组合筛选，但存储和对象详情不合并后两项；G6 的旧状态显示归一化也须同步迁移，不能数据层保真而画布仍把专家复核显示成待修。

旧底稿中的 `needs_revision` 若没有原始记录，不反推它一定来自专家复核。原始运行记录有 `needs_expert_review` 时可生成恢复建议；已有人工修改优先，恢复过程有差异记录。

`WorkbenchReviewSession` 应以聚合文档为状态主体，快照深拷贝扩展集合。关系状态覆盖键迁移到稳定 relation ID；同端点不同类别的关系必须可独立审核。

### 9.1 桌面 Facade、命令接口与过渡策略

#### 9.1.1 现有基础与必须迁移的入口

`desktop_app.py` 约 4300 行，具体行数随编辑变化。现有 `drafts` 属性已代理到 `review_session.drafts`，删除节点、部分关系命令和撤销已经进入 Session；但节点对话框、表格内联修改、类型/状态下拉框、复制及新增仍会直接改 DTO 或 append 列表。工作量应按入口清单评估，不将“需重写 60%”作为事实。

实施前至少建立以下迁移清单，每项标注读取模型、命令、快照范围、刷新消费者和测试：

| 现有入口/职责 | 目标路径 |
| --- | --- |
| `_render_tables`、属性详情、搜索/筛选、选中恢复 | 只读 `DraftRowView` / 关系行模型，通过稳定 ID 定位，不依赖行号保存身份 |
| `_edit_selected_node`、`_node_cell_changed`、类型/状态下拉框 | 分别调用修改字段、改变类型、审核节点命令；不直接写 row DTO |
| 新增/复制节点及模型分析结果导入 | 调用创建/复制/载入文档命令，统一分配 ID 与出现记录 |
| 关系编辑、方向修改、关系状态覆盖 | 通过 relation ID 执行修订/审核命令，旧三元组只作为迁移定位 |
| 父级选择、目录批量通过、删除及清理拒绝对象 | 显式结构/归属/实体命令，不调用旧全量 contains 同步来改新文档 |
| `_rebuild_review_workbook`、质量检查、双图刷新 | 纯读取生成相应投影；不因刷新同步回写业务字段 |
| 导入/保存、撤销、导出 | 使用聚合文档及对应服务；不将 v2 压缩成旧 drafts 后继续运行 |

#### 9.1.2 读兼容、写收口

- Session 唯一持有可变建设态文档，Facade 对外提供兼容显示字段，不向 UI 泄露底层可变列表、字典或子对象。
- `DraftRowView` 可为只读对象或脱离权威文档的快照；修改快照不能改变业务，UI 事件必须明确调用命令。不能以“读返回副本、旧写入悄悄无效”冒充兼容，所有写入口须逐项改接并测试。
- 首期保留原表格/属性控件结构，先迁移状态修改通路，再按节点面板、关系面板逐步拆分组件；不把全面窗口重写作为数据升级前提。
- 新旧格式可共存读取，但一份打开文档只能有一个写入模式。v1 旧会话可走隔离的旧路径；切换 v2 须先完成内存迁移与能力检查，不能一边写新关系一边调用旧 parent 同步。
- 无法通过新能力检查时提供只读查看或明确错误，不能回退到会丢数据的旧保存/导出链路。

#### 9.1.3 命令事务与 revision

拟定入口为 `execute(command, expected_revision) -> CommandResult`。命令包含稳定对象 ID、局部归属/视图上下文（适用时）、修改字段、操作来源及理由；命名可调整，职责不可绕过。

命令执行顺序：检查 revision/对象存在 → 计算影响 → 校验业务约束 → 单次修改与历史记录 → 更新 revision → 返回需刷新的对象/投影范围。失败不留下部分修改；刷新和控件赋值期间阻断程序性信号递归，避免一次编辑被提交两次。

业务修改、审核、主归属/发布范围选择均使文档 revision 单调增加；仅缩放、隐藏、聚焦等显示操作使用单独 `view_revision`。保存时更新基线 ID、导出时间等包级元数据不算业务编辑，不推进业务 revision。撤销恢复操作前业务状态，但追加撤销事件并产生新的文档 revision，不删除原审核历史，不让旧发布令牌因 revision 回退而重新有效。既有快照只用于撤销数据恢复，不作为可重写的审计日志。

重做当前不作为已实现事实。若本轮增加重做，同样通过命令历史与新 revision 执行，必须另加测试；不以专家文本中提到“撤销重做”推定现有功能齐全。

### 9.2 多归属选择上下文与防误操作

选择状态拟为 `SelectionContext(document_id, node_id, membership_id?, view_id?, relation_id?, document_revision, view_revision)`。

- 小节卡片/树上引用选中时带具体 membership；节点总表选中时通常只有 node ID，不推断为当前画布焦点对应归属。
- “拒绝本小节归属”只有在明确选定 membership 时可用；否则提示先选择出现位置。
- 多选混合结构、知识实体或不同操作层级时先分组并预览，不能对所有对象套用同一删除逻辑。
- payload 刷新、筛选排序、归属变更后重新验证选中 ID；过期选择不能作用于新行号下的另一对象。

建议菜单及提示如下：

| 菜单文字 | 默认可用位置 | 提交前信息 |
| --- | --- | --- |
| 隐藏此卡片 | 画布引用 | 仅当前显示；隐藏数量及恢复入口可见，无业务审核确认 |
| 拒绝本小节归属 | 有明确 membership 的卡片/出现列表 | “仅取消本对象在 13.1 的有效归属，其他小节及知识关系保留” |
| 查看/编辑知识对象（影响所有引用） | 卡片或节点总表 | 明确共享 node ID，并显示其他出现位置 |
| 从当前图谱删除知识对象（全部引用） | 独立危险操作区 | 全部归属数、相关关系数、证据影响、主归属失效项；明确二次确认 |

局部归属拒绝优先作为常见纠错入口，不能让 Delete 快捷键在不同面板中无提示切换为全图删除。全局节点“拒绝”和“删除”也不同：拒绝是审核状态，不等同物理删除或证据清除。

### 9.3 删除、拒绝与原始出现证据

- 隐藏卡片仅改变 view_state，不改变 membership/occurrence；恢复视图可找回。
- 拒绝 membership 后该归属不再作为默认有效挂载；原 occurrence、证据与拒绝理由仍保留，防止自动匹配又重新挂回。其他小节的卡片与业务语义边保持原事实。
- 若节点失去全部有效归属，默认进入待确认区；其语义边不得因某一引用消失而从建设态文档删除。
- 全局删除采用有历史的逻辑删除/归档：活动图移除知识对象、其归属与相关边，事务内失效主归属选择；原记录和证据历史可追溯，公共证据不能级联擦除。`lifecycle_state` 与五种 review_status 分开，归档对象不参与布局、自动挂载及正式导出。
- 恢复/撤销时恢复本次事务涉及的对象与关系，再校验端点、归属和选中状态。不能把“恢复历史记录”等同自动复活之后另行拒绝或修改的事实。
- 编辑真实出现证据是高级业务修订，与“这个位置不该显示此知识点”分开处理，不通过删除原文证据达到隐藏效果。

## 10. 关系语义优化边界

### 10.1 保留现有关系，增加明确的语义修订建议

本轮不为改善视觉自动更改原始 13 条关系的端点、类型或数量；迁移后通过 lineage 对账，原记录全部可追溯。

以下是拟议语义扩展，不是已确认的教材事实或现行 P4 契约：

| 拟议类型 | 明确方向 | 候选例子 | 需验证的问题 |
| --- | --- | --- | --- |
| `is_a` | 子类→上位类 | 等边三角形→等腰三角形 | 教材定义是否采用包含式分类，不能只按名称批量映射 |
| `has_part` | 整体→组成部分 | 三角形→边、顶点 | 概念组成与教材内容归属是否已区分 |
| `has_property` | 对象→性质/属性 | 概念→相应性质对象 | “内角”具体属于组成、概念还是属性，应依据节点粒度审查 |

旧 `derives_to` 若实际表达分类，保留原边并提供 `proposed_relation_type`；教师确认前不更改其方向或正式类型。未分类的知识 `contains` 使用“语义包含·待确认”标签保留可见性。

新增类型必须成套更新提示词、解析白名单、归一化、编辑器、图例、布局分类、质量规则和导出能力表。仅把新枚举加进提示词会被现有解析规则过滤，不能作为完成方案。

### 10.2 接受结果与导出能力分开

教师可以确认 P2 内部的新语义关系，但“审核通过”不等于“旧 P4 已支持其计算含义”。目标导出能力不支持时，保留审查包并提示不兼容原因，不能将新类型伪装为现有 `derives_to/contains`。

## 11. 旧数据迁移、持久化与回滚

### 11.1 迁移输入优先级

1. 当前底稿中的人工编辑与审核结果作为当前事实。
2. 底稿已保存的原始出现/证据信息。
3. 同一 `analysis_run_id`、来源哈希、节点 ID/别名映射匹配的规范化与首轮记录。
4. 证据页块与教材标题辅助形成待审归属建议。
5. 无法恢复的信息标记为 unknown，交给人工，不凭邻近连线猜测。

不得把 `progress_recordings/` 永久作为业务依赖。它只用于旧样例修复；新格式即使过程记录为 off，或日志被清理，仍必须完整保存归属、证据与审核信息。

### 11.2 本轮样例迁移对账

- 原 11 个业务节点 ID 保持不变。
- 原 13 条关系有逐条来源映射：1 条教材结构、1 条既有归属、3 条知识间旧包含、8 条其他语义。
- 依据本轮已核对的规范记录中的 13.1 出现线索，为其余 8 个知识节点生成待审 membership 建议，连同既有归属共 9 个；这不代替教师对原文归属的确认。新增记录与旧 13 条分开统计。
- 只恢复原五个框外节点不够：内角、边、顶点也需要教材归属，其语义父节点“三角形”不能继续代替小节归属。
- 完整展开且不过滤时，预期 2 个教材结构对象、9 个知识对象、9 个归属记录，11 条知识语义/未决知识关系有可见连线；原 5 条 contains 中只有教材结构及既有归属通过嵌套表达。
- 这是冻结回放的预期投影，不是要求未来真实模型固定生成 11 节点或 13 关系。语义审查后若修改类型、合并或拒绝，按修订记录对账。

### 11.3 原子性与可回退性

- 迁移先内存 dry-run，展示前后对象数、未决数、归属来源和状态变化；确认保存后写入新版本，保留原 v1 文件。
- 重复迁移同一输入不得重复创建 memberships、出现记录或语义边。
- 临时文件完整写入并验证引用后才替换目标；中断不能留下半个审查包。
- 当前导出会先删除当天已知产物。后续需改为先生成新运行目录并校验，再原子更新“当前导出”清单；不能删除前一有效版本后才尝试生成。
- 新目录建议为 `YYYY-MM-DD/<export_run_id>/`，日期层最新指针只指向完整已完成运行；失败的新运行明确标记正式图谱未生成。旧正式文件留在历史运行中，不得混入当前清单。
- 旧日期目录结果只读可回放，不原地批量迁移。回滚应用代码时继续使用备份 v1；v2 不能假装支持旧程序无损回写。

## 12. 质量门禁与 P4 兼容导出

### 12.1 分开的诊断维度

| 诊断类别 | 检查内容 | 行为 |
| --- | --- | --- |
| 审核就绪 | 节点、归属、结构、语义是否确认 | 底稿可保存，正式发布按条件阻断 |
| 数据完整性 | ID、端点、证据引用、来源版本、结构循环/多父级 | 错误对象不能进入正式投影；保留问题记录 |
| 归属质量 | 缺失/歧义归属、冲突提示、外部引用 | 允许候选展示；正式教材发布要求明确主归属或显式受支持的独立对象身份 |
| 语义质量 | 类型/方向疑点、不同类型循环、证据充分性 | 提醒修订或专家复核，不由布局结果代替判断 |
| 显示完整性 | 关系覆盖账本、丢失实例、框越界、重叠 | 界面诊断并阻止宣称可视化验收通过；不因像素问题改业务数据 |
| 导出能力 | 目标协议是否能表达已确认事实 | 不支持时阻断该目标正式导出，审查包仍可保存 |

默认正式范围内的已通过子结构必须有已通过父结构链；已通过知识节点若依赖教材归属发布，必须有已通过 membership 及所属结构链。节点通过不能自动通过归属，候选层推定归属不能漏进正式 parent。

### 12.2 现有 P4 的实际边界

已只读核对相邻 P4 工程：`TextbookGraphBuilder.build_graph` 会根据 `parent_node_id` 补 `contains`，根据 `prerequisite_nodes` 补 `prerequisite`；关系导入器按字符串读取类型，当前 `_validate_edge` 主要校验端点。

因此不能声称“P4 有严格新类型枚举，所以无法读取”；也不能声称“字符串能导入，所以已有正确图计算支持”。当前 P2 `LayerMappingBuilder` 还会把所有 contains 当 hierarchy，这是必须修订的明确事实。

### 12.3 默认兼容目标 `p4_v1_single_membership`（拟定）

保持旧 `formal_graph.xlsx` 的 graph/nodes/edges 字段及 `layer_mapping.json` 外形，新增能力检查和显式映射：

1. 已通过教材 structure 导出为 `contains`，父级投影一致。
2. 每个已通过知识节点选择一个已通过教材主归属，导出为 scope→node 的 `contains` 及相同 parent。
3. 同一节点只有一个有效已通过归属时可确定主归属；有多个时由教师在导出预览中明确选择，不能让当前画布聚焦位置决定正式 parent。
4. 其他归属及全部出现记录完整留在 v2 审查包，清单列出旧协议未携带的记录数与 ID；用户选择此兼容目标时必须看到其单归属限制。
5. 现有已支持的语义类型保留真实端点与类型；新类型及含义未定的知识 contains 不得直接变成教材 hierarchy。
6. 选定发布范围含已通过但目标能力未支持的语义关系时，阻断该目标导出，明确列出对象。允许另行由用户选定发布子集，但不能自动丢弃这些边后宣称完整导出。
7. 发布子集需闭包检查端点和教材祖先，并在预览中列出被排除对象；仍然只输出 accepted 事实。
8. `LayerMappingBuilder` 消费同一个正式投影，不能重新用旧全量候选 contains 推断层级；P4 补出的父级边应与显式结构/主归属边相同，不新增意外关系。
9. `prerequisite_nodes` 仅由选定正式范围内已通过的 prerequisite 关系派生；P2/P4 据此补边必须与显式边幂等一致。待审、待修、专家复核或拒绝的前置边不得由旧列表重新进入正式结果。

正式投影须保留结构角色等上下文供分层映射使用，不能先压缩成旧 DTO 再按深度猜角色。现有映射将非章节点统一计入 `knowledge_point`，包括目录小节；兼容目标保留这一旧统计口径，同时以 `attributes.structural_role` 及清单说明区分教材结构与真正知识卡片，不用旧统计值冒充新视图知识数。局部材料若缺少目标协议所需的祖先，明确阻断或要求补齐可审核结构，不能将根小节冒充章。

目标能力表须按“类型、方向含义、允许端点、映射用途及对应 P4 测试”逐项冻结；不能把当前字符串白名单直接当作下游算法全部支持的证明。

本轮新建设态数据可以保存并审查，旧 P4 兼容导出可能仍因语义能力不足阻断。这是显式边界，不应通过错误映射换取“导出成功”。未来确有全量多归属和新语义下游计算需求时，另行冻结 P4 v2 契约并做跨工程实施。

### 12.4 导出交互

- 区分“保存审查底稿”和“发布到 P4”；发布入口先打开预检面板，不先调用旧导出函数写文件。
- 审查底稿可以保存未审完的业务，但引用损坏等写入完整性错误仍须处理。用户选择且成功保存后才提示“底稿已保存；正式发布待审核”，不能只打开预检就声称已经保存。
- 清单分别记录审核阻断、数据错误、目标不兼容、实际文件集合、导出范围和投影损失说明。
- 格式不支持、无审核通过节点或 IO 失败属于不同结果，不能统称质量错误；历史错误码保留兼容映射。

### 12.5 发布前检查、主归属裁决与正式投影

#### 12.5.1 服务职责

新增无界面发布规划服务（例如 `PublishPlanningService`），拟定接口：

- `preflight(document_snapshot, export_profile) -> PublishPlan`：纯读取，不创建目录、不清理旧文件、不接受任何事实。
- `build_formal_projection(document_snapshot, ready_plan) -> FormalProjection`：只使用已检查的来源快照、目标能力与发布选择，不读取 ReviewViewProjection。
- `publish(ready_plan, expected_revision, output_root) -> PublishResult`：通过第 12.6 节检查后生成新运行产物。

`PublishPlan` 至少包含 plan ID、文档 ID/revision/内容指纹、profile ID/选择指纹、目标协议及能力表版本、业务对象范围、主归属映射、祖先/端点闭包、阻断项、警告、未携带信息清单和结果摘要。指纹的规范化规则必须版本化，覆盖影响发布的来源身份、业务内容、状态、生命周期和选择；时间、坐标、隐藏状态、导入基线副本及包级导出元数据不是业务内容指纹的一部分，避免保存操作引起循环失效。

在目标范围内按 accepted 状态选取事实；其他状态被排除的数量与原因须可见。必要祖先/端点不能排除后继续生成悬空结果，目标不支持的 accepted 语义也不能被默默略过。

#### 12.5.2 面板内容与状态

首期采用一个可筛选列表的发布面板，不把大量对象依次弹成多个模态窗口。提供如下分区：

| 分区 | 显示内容 | 允许动作 |
| --- | --- | --- |
| 发布目标与范围 | 目标协议、选中章/节点、依据 revision | 明确选择范围并重新预检；不会跟随画布筛选 |
| 待指定主归属 | 节点 ID/名称、所有 accepted 且有效的归属、完整教材路径及证据入口 | 选择一个主归属；唯一有效归属可确定性填写，多归属不按第一项默认提交 |
| 数据/审核阻断 | 无已通过节点、必要父级未通过、失效端点或归属 | 定位审查对象，回到工作台修订；面板不替教师批量通过 |
| 协议不兼容 | 不支持关系的 ID、端点、类型、原因、影响范围 | 返回语义审查或明确调整发布子集；没有“强制改型导出” |
| 兼容损失与预览 | 未携带的次归属/出现信息，排除事实，预期节点/边与文件数 | 审查摘要，确认本次兼容目标及损失说明 |

按钮为“返回审查”“保存审查底稿”“重新检查”“确认发布”。仅当阻断项为空且确认信息对应当前计划时启用“确认发布”。主归属选择通过 Session 的显式 profile 命令保存；它不改变 membership 审核状态，不删掉次归属，也不因改选画布焦点而变化。

唯一归属的确定性填写先作为计划建议，不由预检原地写 profile；用户确认选择后提交 profile 命令并重新预检。重复确认完全相同的选择为无修改操作，不推进 revision，避免“预检补默认值→计划失效→再补默认值”的循环。

面板状态为 `needs_decision / blocked / ready / stale / publishing / completed / failed`。取消、blocked 或 stale 状态均不写正式结果；保存审查底稿是单独明确动作。预检失败不伪装成 IO 失败，IO 失败不描述为教材质量不合格。

#### 12.5.3 多归属选择失效与协议边界

主归属被拒绝、归档、改变端点，所属结构链变化，或发布范围移除必要对象时，该选择需重新验证。只有一个剩余有效归属时可以提出确定性选项，但仍展示为何原选择失效，不能沿用旧的 ready 状态。

底稿保留全部建设态事实；FormalProjection 不含引用卡片、虚拟框、折叠汇总边和布局辅助边。相同文档及显式发布 profile 下，切换画布、隐藏卡片或调整缩放后，应生成相同业务正式投影。

CLI、批量验证及静态导出入口复用同一预检服务。CLI 对未决主归属或不兼容关系输出结构化诊断并停止正式发布，不使用“无 UI 因此选第一个”的默认规则；仅当用户显式提供相应 profile/选项后继续。

### 12.6 预检版本一致性与文件事务

1. 预检针对不可变业务快照执行。教师修改数据、审核状态、发布范围或主归属选择后，旧计划变为 stale，必须重新生成。
2. 确认发布时核对 plan ID、文档 revision/内容指纹、profile 指纹、目标能力版本。即使 revision 相同但内容不同，也拒绝复用旧计划。
3. 首期单会话发布期间锁定业务编辑和第二次发布请求；查看、缩放可继续。后台分析新结果排队等待，不在写入中途替换来源文档。锁定失败或来源已变更则停止，不“尽量导出”。
4. 从该快照生成同一 FormalProjection，并写入同一文件系统内的独立暂存运行目录；由清单及审查包元数据将工作底稿、正式表、报告和映射绑定到同一来源 revision/快照指纹，并记录各自 schema 与文件哈希。为追溯而加字段时不得擅自扩展已冻结的 P4 表列；旧正式表可通过清单中的文件哈希关联快照。
5. 验证文件集合、数量、端点/父级一致性与文件哈希，通过后提交完整运行，再原子更新当前结果指针。Windows 文件占用、权限、磁盘不足或替换失败均保留旧有效结果，标明未完成暂存目录，不自动删除历史。
6. 清单只有在全部必要产物完整时标为 completed。中断运行不得成为“当前导出”；仅保存底稿的已完成运行明确 `formal_generated=false`，不得沿用上轮正式路径。
7. 完成或失败后释放业务锁，展示真实产物位置与可重试原因。重试使用同一计划前重新校验；正式发布不反向改变业务审核状态。

这里只要求本地单会话的一致性，不宣称已实现多用户分布式事务。未来 Web 发布应沿用相同快照契约，再另行设计并发控制。
